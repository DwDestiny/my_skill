# 手绘风格化 · hand-drawn

效果：页面像画在一张有颗粒的纸上，图是钢笔勾线、彩铅上色、排线出明暗，字是手写的，悬停时字会“抖一下”、图会换一层。
本质：让读者相信“这是一个人画给我看的”。靠三条：页面上每样东西都出自同一只手、同一套画具、同一张纸；结构准、只让笔触活；藏起程序的规律。技术上，一张纸面高度场驱动全部颗粒，画具全用 Canvas2D 代码画，所以颗粒对得上、能交互、能改。
开工前先看这张图：`${CLAUDE_SKILL_DIR}/showcase/cover.webp`。

## 1. 何时用、何时不用

| 用 | 不用 |
|---|---|
| 讲课页、讲解图：要把一个关系“画给人看” | 需要照片、真实产品图的页（手绘会显得假） |
| 首屏要有温度、像手作，而不是模板页 | 数据要精确读数（排线和抖动会干扰读值） |
| 用户在意“是代码画的，不是生图”，要能悬停、切层、改字 | 只要一张静态图：生图更快，不必搭画具 |

## 2. 先想清楚风格化什么

手法 = **一种模拟的介质**（纸 + 画具 + 字）**套在一个题材上**。先从题材出发，回答三个问题，再选变体：

1. 这个题材在现实里是在什么“纸面”上被画出来的？（课堂 → 笔记本、黑板；工程 → 蓝图；厨房 → 配方卡；旅行 → 手账）
2. 那个场合的人用什么笔？（钢笔、彩铅、马克笔、粉笔、水彩、炭笔、丝网两色）
3. 每屏要说的那一件事是什么？是一种感受（情绪画面，用比喻），还是一个关系（讲解图，直接画）？见 `references/principles.md` 第 1 节。

## 3. 原理与审美

完整内容在 `references/principles.md`。这里是要点，每条都要能迁移到任何题材。

三条底层原理：

1. **材质一致。** 图、字、标题、按钮、提示都像同一只手、同一套画具、画在同一张纸上。版式语法来自题材的纸面（手抄报、笔记本、黑板、蓝图），不来自网页模板。
2. **结构准，笔触活。** 不完美只在笔触层：抖动、复描、断墨、颗粒。透视、比例、对齐和信息的位置必须准。
3. **藏起机器的痕迹。** 笔触随形体、材质、明暗、注意力变化。成片同角度的平行线、处处相同的密度、等距重复，都会让人看出“是算出来的”。

审美原则：

| 原则 | 一句话 |
|---|---|
| 一幅画只说一件事 | 情绪画面用有张力的比喻（并置、断开、融合）；讲解图直接画关系 |
| 视觉重量 | 重量来自明度对比、细节密度、饱和度，最后才是面积；按概念选对峙、对角或中心 |
| 明度结构 | 3 到 4 个明度；最强对比放在焦点；标题落在浅区 |
| 细节分布 | 焦点细，外围点到为止，四边淡回纸里 |
| 空间 | 远、中、近三层；越远越淡、越冷、越细 |
| 笔触语言 | 线分三级；排线顺形；笔触随材质；彩铅给色，排线给明暗 |
| 颜色 | 一墨加 3 到 4 色，每色一个意思，图文同色；强调色只用一两处 |
| 字图一体 | 标题写在画里的空处，画为字让出淡处；标签写在物件上 |
| 动 | 入场讲顺序，常驻让画活着，响应落在概念点；Reduce Motion 全关 |

起步参数在 `references/anchors.md`。它是一次实例的值，换题材按那里的顺序重推。

## 4. SOP

1. **写概念。** 每屏一句话：读者看 3 秒要明白什么。标出它是情绪画面还是讲解图。
2. **推世界。** 按第 2 节三问定纸面、画具、版式语法，再定色板和每种颜色的意思。
3. **和用户确认内容**：每屏讲什么、图里有什么。情绪画面给三个比喻候选并推荐一个。用户要求过“不要随便跳步”。
4. **小稿定构图。** 只画明暗块：平衡方式、焦点、标题放在哪片浅区。
5. **画。** 复制 `${CLAUDE_SKILL_DIR}/templates/starter/`。情绪画面按 `references/scenes.md`，讲解图按 `references/diagrams.md`。参数从 `references/anchors.md` 起步。
6. **字体子集。** 跑第 6 节的字体脚本。改了任何文字都重跑。
7. **首屏试样先给用户看**（首屏加一张图），用可批注的预览链接。用户的话先按 `references/principles.md` 第 10 节翻成原则，再改。
8. **验收。** 按第 5 节逐条过，再做整页。用户评价记进 `CARD.md` 的实践记录。

## 5. 验收标准

每条都看截图或录屏，不凭代码判断。

| 测什么 | 怎么测 | 过线 |
|---|---|---|
| 概念 | 只看首屏 3 秒，用一句话说它在说什么。可以把截图交给另一个模型盲看 | 说出的话与概念句一致 |
| 明暗与平衡 | 把截图模糊到看不清线，或缩到 200 px 宽 | 主体清楚；左右分量相当；最强对比在焦点；标题在浅区 |
| 细节分布 | 在截图上圈出焦点区、过渡区、留白区 | 三个区都有；焦点处至少三种细节来源 |
| 材质一致 | 列出页面上每个看得见的元素，逐个问“是不是同一套画具画的” | 没有系统字体、CSS 图形、照片、网页模板版式 |
| 机器痕迹 | 2× 裁图看大面和重复的物件 | 看不出成片同角度的平行线、等距重复、复制的同一形状 |
| 结构 | 看透视和对齐；讲解图对照数据 | 透视不歪；装饰没有移动任何信息 |
| 字图一体 | 看标题与画、关键词与图的关系 | 标题在画里；关键词与图同色；正文对比度 ≥ 4.5:1 |
| 动效 | 看一遍入场，停 10 秒，再悬停概念点 | 入场不超过 4 秒且顺序讲故事；常驻幅度小；概念点有响应；Reduce Motion 下画面静止且完整 |
| 多页（讲课页、多屏专题） | 冷启动一次；往后翻一页，翻页后 0.3 秒和 1.5 秒各截一张；走一步分步；往回翻一页 | 初版就有四层：加载（第一屏画好前有进度，画好后淡出）、每页入场（标题逐字、块按阅读顺序、画逐层擦出，1.5 秒内到位）、分步淡入上浮、悬停响应。往回翻直接显示，不重播 |
| 载体 | 截 1440×900 与 390 宽（走 iframe 包装） | 无横向溢出；手机是重新构图，不是缩小；控制台无报错 |

| 文件 | 用途 | 怎么用 |
|---|---|---|
| `templates/starter/hand-drawn.js` | 画具包，全局 `HandDrawn`，无依赖 | 阅读 + 引入。`HandDrawn.init(opts)` 生成纸并写 CSS 变量 `--paper-img`、`--ink-mask` |
| `templates/starter/index.html` | 演示页：首屏情绪画面（已验证实例）+ 讲解图 | 运行。复制后改内容；`?p=2`、`?row=0..3`、`?only=2` 用于截图 |
| `templates/starter/fonts/` | 两款字体子集 + OFL 许可证 | 随页面发布，许可证文件一起带上 |
| `scripts/fonts.sh` | 下载字体（缺时）+ 按页面取字子集化 | 运行：`FONT_SRC=<已有原件目录> bash ${CLAUDE_SKILL_DIR}/scripts/fonts.sh <输出目录> <页面.html> [更多 .js]` |

画具 API（全部在逻辑坐标里画，返回点列的函数交给 `pen` 画）：

| 函数 | 作用 |
|---|---|
| `pen(c, pts, {w, jit, alpha, color, seed, closed})` | 钢笔：主线 + 复描，噪声摆动 |
| `pencil(c, clip, box, {color, angle, len, w, density, alpha(x,y), op, tooth, seed})` | 彩铅：同角度短笔触，按纸齿打颗粒，multiply 落下 |
| `hatch(c, clip, box, {angle, sp, thr, w, alpha, tone(x,y,lr), level(x,y,lr)})` | 墨线排线；配合 `HATCH_LAYERS` 四层叠出深浅 |
| `ring` / `rbox` / `tape` / `sparkle` / `paperCard` / `frame` / `tagTape` / `fadeDash` | 手画圈、圆角框、胶带、星、卡纸、手抄报花边、页眉胶带、越走越断的线 |
| `paperize(cv, a)` | 画完一层后按纸的深坑擦掉一些墨 |
| `fitTo` / `place` / `placeIn` | 画布铺满元素 / 放在父元素坐标 / 按图的逻辑坐标放 |
| `handset(el, seed, amp)` / `label(box, W, H, x, y, text, o)` / `fontsReady(specs)` | HTML 逐字手写排；图内标签；字体显式加载 |
| `hatchIn(c, clip, box, {angle, sp, w, alpha, tone, thr, rag, wob, step, color, seed})` | 单层排线：背光坡、岩层线下阴影、云底 |
| `under(c, poly)` / `paperizeN(cv, a)` | 实心物体先垫同纹纸挡住后面的线；自带纸底的画布在纸坑里补纸色（不擦成透明） |
| `edgeMask(W, H)` + `fade(cv, mask, W, H)` | 画面四边按噪声淡回纸里，顶上淡得更慢 |
| `ridgeFn({y, amp, seed})` / `mist(c, y0, y1, X0, X1, yb, a)` | 山脊起伏 `x → y`；把一段高度往下擦淡成雾 |
| `cloud` / `pine` / `bush` / `tuft` / `rock` / `strip` | 云、松树、灌木、草簇、水中石、把线段加宽成杆 |

## 7. 载体与降级

| 载体 | 表现 |
|---|---|
| 桌面 / 投屏 | 两屏整屏吸附，方向键翻页并逐层切换 |
| 手机 | 场景和教学图改竖排（`geo(true)`），花边边距 6；触屏点按切层，提示改“往下滑” |
| Reduce Motion | 关闭入场、常驻、抖动和擦出；三帧轮换只留第一帧；画面直接显示画完的样子 |
| 无 JS | 只剩纸色底和楷体回退的文字，图不出现。要保底就在 `<figure>` 里放一句文字说明 |
| 缺手写字体 | 回退楷体；质感降一档，但版式不坏 |

## 8. 踩坑（按原理归类）

每条写：用户原话、违反了哪条原理、通用改法、那一次怎么改的。新反馈先归到某条原理下再写。

**材质一致**

1. 讲解图改成直接画关系后，用户：“这个确实直观了，但很丑，也没啥质感”，又说：“字体以及其他组件，整体搞成手绘风格……包括底层的纸质感、颗粒感”。原因：图是手绘的，字和小部件还是网页的，整页不像同一只手。改法：字、圆点、下划线、框全部换成同一套画具；纸、彩铅、墨缺口、大字遮罩取自同一张高度场。那一次：手写字体逐字抖动，CSS 圆点改成手画圈加彩铅。
2. 首屏，用户：“既然是手绘手抄报风格，那首屏完全可以按照手抄报或者手绘画那种完全一体化的方式搞，不必要套用刻意生硬的landing模板，左侧字右侧图”。原因：版式语法来自网页，字和图被分成两块，画成了配图。改法：版式语法从题材的纸面推；标题写在画里的空处。那一次：一整幅山谷画，标题写在天空正中。

**结构准，笔触活**

3. 用户：“小房子有些过于潦草了”。原因：把“手绘”理解成结构松散：线两头出头、抖动大、三帧每帧都大变。改法：结构线干净，抖动降档；“未完成”用浅色、不上墨表达；三帧只换线的随机种子。

**藏起机器的痕迹**

4. 自检 2× 裁图时发现：天空和崖壁用同一角度、同一颜色的彩铅铺满，像在下雨。原因：一个参数铺满大面，露出了程序的规律。改法：笔触随材质变，大面按材质分块、分层上色，明暗另叠一层（`references/pens.md` 第 2 节）。

**一幅画只说一件事**

5. 讲解图，用户：“用柜子表达这个逻辑不太易懂，比喻也不是很恰当”。原因：讲解图用了比喻，读者要先翻译一次。改法：先判断关系类型，直接画关系（`references/diagrams.md`）。那一次：六步是时间轴，四条线是横穿全程的色带。
6. 首屏，用户：“首屏感觉设计感缺乏，过于简单，手绘的部分可以搞得精细精美一些，这个比喻可以改换一下”。原因：概念弱（越走越断的路只有一个元素，没有张力），整体细节也不够。改法：用并置、断开、融合想三个有张力的比喻；画成一整幅有远近、有焦点细节的画。那一次：用户在三个候选里选了“两岸各修半座桥，在河心错开”。

8. 滚动讲解图，用户：“滚动的放大缩小幅度有点不够，焦点不清晰，导致用户没有聚焦的感觉，增强一下”。原因：为了不在框中间裁开，把放大压到 1.3 倍上下，每段画面都差不多是整张图，一段没有只说一件事。改法：每段只亮一块，其余淡下去，放大到约 2 倍；装不下就拆段（`references/diagrams.md` 第 4 节）。那一次：链路图 5 段拆成 6 段，放大 1.85 到 2.1 倍，没讲到的组降到 20%。

**动：让画活着**

9. 77 页讲课页初版只有分步淡入，用户：“添加丝滑的交互动效和加载动效，这些东西不应该在你的初版标准里吗？”原因：把动效当成画完再补的润色；多页时只盯每页的画，没把“翻到这一页”当成一次入场。改法：多页页面的初版就带加载、入场、分步、悬停四层（第 5 节“多页”一行，参数见 `references/anchors.md`）。那一次：加载是一条线画过六个点；翻页时标题逐字落笔，卡片按阅读顺序一拍一拍落下，彩铅底和表格线从左往右擦出。

**视觉重量**

7. 用户：“整体的布局很奇怪，右侧太空，左侧太重”。原因：把面积当成重量，刻意画淡的东西压不住另一边的深色。改法：按明度对比和细节密度配平；按概念选对峙、对角或中心。那一次：两座分量相当的半桥对峙。

工程上的坑（截图错位、字体加载、混合模式、热区、类名冲突）见 `references/layout-pitfalls.md` 与 `references/type.md` 第 4 节。
