# 叠图晕染 · layered-reveal

**效果**：暗处是一层画面，光照到的地方像水墨一样晕开另一层同构图的画面，并浮出暗处看不到的信息。
**本质**：N 层对齐的同一构图 + 一条有机的边（墨迹场）+ 一个驱动（指针 / 吊灯 / 时间 / 滚动），驱动决定边在哪里揭开下一层。
**开工前先看这张图**：`${CLAUDE_SKILL_DIR}/showcase/cover.webp`，再看 `showcase/frame-*.webp` 与 `mobile.webp`。

已验证实例只有一次（一次行业宣讲网页，2026-10-23）：底层是稀疏的大理石浅浮雕，光下是同构图的真实照片。浮雕只是一种层关系。本手法教的是机制，换装、昼夜、新旧、外壳与内部都能用它做。

## 1. 何时用、何时不用

| 用 | 不用 |
|---|---|
| 页面有一幅主画面，且画面有"暗处看不到、光下才看到"的东西 | 页面信息主要是文字、表格、表单，画面只是装饰 |
| 讲者投屏讲解，或读者愿意花 10 秒探索首屏 | 读者只想 3 秒找到按钮（下单页、后台） |
| 需要一个签名时刻（例如滚动逐盏点灯）承载一个论点 | 只能拿到一张图，做不出对齐的第二层 |
| 桌面为主，手机可以退化为点按或下半屏取景 | 必须在低端手机上全程 60 帧，且不能降级 |

## 2. 先想清楚：光要揭示什么

先回答一个问题：**光必须揭示什么暗处给不了的东西？** 答案是信息，不是同一张图的亮版。

这个手法能打动人，靠四条原理。换任何题材都先对照它们：

1. **动作就是意思。** 读者“照亮”的动作，对应内容里的“看到表面之下”。内容里没有“藏着、表面看不出”的东西，就不要用这个手法。
2. **两层的差就是内容。** 两层同构图、像素对齐，唯一的差别正是要讲的东西。差别以外的一切都不变，眼睛才会落在差别上。
3. **稀缺让揭示有分量。** 亮区小（不超过屏幕 20%），彩色只有光一种，说明牌一次只亮一张。到处都亮，就没有“被照见”的感觉。
4. **光和边都有物理。** 光有重量（略慢于指针），痕迹会慢慢合上，边的材质来自题材（墨、霜、火、水）。机械的圆形硬边会让人觉得是一个遮罩，不是光。

然后在下面三个维度上各选一项。

### 2.1 变体空间

✔ = 已验证（2026-10-23 那一次做过并被用户认可）；衍生 = 机制相同、未做过，做之前先出首屏试样。

| 维度 | 选项 | 状态 |
|---|---|---|
| 层的关系 | 抽象 → 真实（浮雕、白模、线稿 → 照片） | ✔ |
|  | 换装 / 换材质（白坯布 → 成衣，素模 → 上色，木 → 金属） | 衍生 |
|  | 时间（夜 → 昼，旧 → 新，施工前 → 建成后，过去 → 未来） | 衍生 |
|  | 里外（外壳 → 内部，皮肤 → X 光，整体 → 剖面） | 衍生 |
|  | 状态（混乱 → 有序，问题 → 已解决，空 → 满） | 衍生 |
|  | 三层以上（光越强揭得越深：外观 → 结构 → 数据） | 衍生 |
| 驱动 | 指针探照灯（跟手缓动） | ✔ |
|  | 固定吊灯（滚动逐盏点亮，签名时刻） | ✔ |
|  | 空闲巡游（停 4 秒后自动照热点） | ✔ |
|  | 滚动进度（光圈随滚动扩大或横移） | 衍生 |
|  | 点按落墨（每次点按滴一滴墨，慢慢洇开） | 衍生 |
|  | 设备倾斜（手机陀螺仪移动光） | 衍生 |
| 边缘质感 | 水墨晕染（卷曲噪声平流 + 扩散 + 衰减） | ✔ |
|  | 渐褪的痕迹（走过处慢慢合上） | ✔ |
|  | 永久刮开（刮刮卡，不衰减） | 衍生 |
|  | 烟、水波纹、纸边燃烧、油画笔触、擦开的霜、枯笔飞白 | 衍生 |

边缘质感怎么换，见 `references/ink-shader.md` 第 4 节。

### 2.2 从题材出发想下一层

1. 写下页面要读者记住的一个判断。
2. 问：这个判断里，什么东西"表面看不出来"？那个东西就是下一层。
3. 选层关系，让两层的差就是那个东西。
4. 选驱动：讲者主导选指针 + 巡游；论证"越来越多"选吊灯或滚动；手机为主选点按或倾斜。
5. 选边缘：边缘的材质要来自题材本身（手艺选墨，消防选燃烧，冬季产品选霜）。
6. 在下一层上钉 3 到 5 个热点，每个热点带一句光下才出现的信息。

### 2.3 衍生画面示例

每条都写明"揭示了什么信息"。

| 题材 | 画面 | 光揭示的信息 |
|---|---|---|
| 服装品牌 | 人台上的白坯布样衣 → 同一姿势的成衣 | 面料、版型改动处的说明牌："这条省道收了 1.5 cm" |
| 城市更新 | 1980 年代的街口黑白照 → 今天同机位的街口 | 每栋楼的改造年份与原用途 |
| 硬件产品 | 铝合金外壳 → 同角度的爆炸内部 | 每个部件的名称与一个参数 |
| 餐厅 | 案板上的生食材 → 同构图的成品菜 | 每样食材的产地与处理工序 |
| 医院 | 胸部 X 光片 → 康复后微笑的病人（同姿势） | 治疗节点与时长 |
| 太阳能产品 | 夜里的屋顶 → 白天同一屋顶 | 每块板当天的发电量计数 |
| 软件团队 | 白板上的手绘线框 → 上线后的界面 | 每块线框对应的上线日期 |
| 博物馆 | 残缺的陶器 → 复原后的完整器形 | 缺失部分的复原依据 |

平庸版与好版对照：

| 平庸 | 好 |
|---|---|
| 光圈跟着鼠标走，照到的是同一张图的亮版 | 光下是另一种状态，并浮出一张说明牌和一个计数 |
| 两层题材无关（暗处城市，光下海滩） | 两层同构图、像素对齐，差别正是要讲的内容 |

## 3. 风格规范（已验证版本的数值）

这些数值是锚点，不是配方。换题材时按 3.2 推出自己的数值。

### 3.1 已验证数值

| 项 | 值 | 作用 |
|---|---|---|
| 底色 | `#070B14`（着色器 `.024,.031,.055`） | 有色深蓝黑，不用纯黑 |
| 底层压暗 | 亮度取 `pow(lum,1.35)`，按 `0.42` 混向冷灰蓝 `(.80,.84,.92)` | 保留浮雕自身明暗 |
| 揭示层增益 | `×1.3` | 光下比暗处亮一档 |
| 暖光色 | `#F2B45C`；光边 `(.95,.60,.25)` | 全页唯一彩色，语义是"被照见" |
| 墨迹场 | 512×320；保留 `0.993` / 帧，减 `0.0012` / 帧 | 痕迹约 2 秒褪去 |
| 平流 | 卷曲噪声 `0.0016`，指针推墨 `0.6` | 墨被光推着走 |
| 显影阈值 | `smoothstep(.22,.62)`，fbm 扰动 `0.38` | 边缘不规则 |
| 光圈大小 `lr` | 首屏 12，难题章 20，吊灯章 16，无图章 10 | 数字越大光越小 |
| 跟手缓动 | `0.91`（每 60fps 帧） | 光略慢于指针，有重量 |
| 空闲巡游 | 4 秒后开始，每个热点停 3.2 秒 | 讲者停手时画面不死 |
| 换章 | 场景图 0.6 秒化回底纹，0.9 秒化入下一幅，四边羽化 | 不黑场、不清墨 |
| 吊灯 | 最多 4 盏，亮度 0.9，半径 230 原图像素 | 竖向椭圆 |
| 说明牌 | 1 px 引线，衬线编号，不透明度 0.9，无模糊，一次只亮一张 | 像展厅说明牌 |
| 亮区 | 任何时刻不超过屏幕 20% | 克制 |

### 3.2 换题材时推数值

1. 底色取题材暗部的主色，降到亮度 3% 到 6%。
2. 暖光色取题材里"被照见"的颜色。例如霜题材用冷白，燃烧题材用橙红。
3. 底层压暗系数从 0.42 起调。如果光下与暗处差别看不出，降到 0.2 到 0.3。
4. `lr` 按画面主体大小定。光圈直径约等于一个热点物件的 1.5 倍。
5. 衰减按想要的痕迹时长定：时长 2 秒用 0.993，时长 5 秒用 0.997，永久刮开用 1.0 且减量 0。

## 4. SOP

1. 写下判断与"光要揭示什么"（第 2 节），选层关系、驱动、边缘。
2. 选 3 到 5 个热点，每个写一句光下的信息。说明牌写法见 `references/staging.md` 第 5 节。
3. 生产成对图：先出细节最多的一层，再以它为参考出简化层，差值叠图挑最齐的一张。步骤见 `references/asset-pairs.md`。
4. 复制起手页（第 5 节），换图、换热点坐标、换文字。
5. 做首屏试样：只做一幕，光停在一个热点上截图。
6. 把试样给用户看，按反馈改。两次成功的项目都先过了这一步，才做整页。
7. 整页：加章节、换章、签名时刻（吊灯或其他），按 `references/staging.md` 编排。
8. 截图：1440×900 封面光停在热点上；390 宽手机图；各幕一张。逐张看图，看到问题就改。
9. 检查载体：Reduce Motion、无 WebGL、无 JS、投屏亮度（第 6 节）。

### 验收标准

每条都看截图或录屏。

| 测什么 | 怎么测 | 过线 |
|---|---|---|
| 揭示有信息 | 遮住说明牌，只看光下那一层 | 光下仍能看出暗处看不到的东西，不只是变亮 |
| 两层对齐 | 两层差值叠图，或快速来回切换 | 除了要讲的差别，轮廓不跳 |
| 稀缺 | 光停在热点上截图，估亮区面积 | 亮区不超过屏幕 20%；同时只亮一张说明牌 |
| 边 | 2× 裁图看光边 | 边不规则、有题材的材质，看不出圆形遮罩 |
| 光的重量 | 快速甩动指针，再停手 4 秒以上 | 光略慢于指针；痕迹慢慢合上；停手后自动巡游 |
| 说明牌 | 看文字 | 对比度 ≥ 4.5:1；一句话说清一个事实 |
| 载体 | 1440×900、390 宽、Reduce Motion、无 WebGL | 无横向溢出；降级后仍能看到两层和说明；控制台无报错 |

## 5. 起手代码

| 文件 | 用途 | 运行 / 阅读 |
|---|---|---|
| `${CLAUDE_SKILL_DIR}/templates/starter/index.html` | 演示页：首屏五个热点 + 换章 + 吊灯逐盏点亮 | 运行（需本地 HTTP 服务） |
| `${CLAUDE_SKILL_DIR}/templates/starter/layered-reveal.js` | 引擎，无依赖：墨迹场、显示、换章、吊灯、巡游、Reduce Motion、无 WebGL 降级 | 运行；改质感时阅读 |
| `${CLAUDE_SKILL_DIR}/templates/starter/img/*.webp` | 两对生成图（书桌、四区大厅），各 base / top | 素材 |

运行：`cd templates/starter && python3 -m http.server 8000`，打开 `http://127.0.0.1:8000/`。用 `file://` 打开时浏览器会拒绝把图片传给 WebGL。

API：

```js
const r = LayeredReveal.mount(canvas, SCENES, options);
// SCENES = { 场景id: { base, top, align:'left|center|right', vy, fx, lr, pins:[{x,y,el}], lamps:[{x,y}] } }
// 无 base/top 的场景只显示底纹与光。页面元素用 data-scene="场景id" 绑定场景。
r.setLit(n);   // 吊灯亮几盏（0–4），页面按滚动进度调用
r.geo(scene);  // 原图坐标 → 屏幕坐标的 {k, ox, oy}，用于摆放说明卡
// options 覆盖默认值（LayeredReveal.defaults），onFrame({scene, pin, seen, lit}) 每帧回调
```

替换素材与文字：

1. 两层图放进 `img/`，尺寸相同（默认 1536×1024，改尺寸时传 `imageSize`）。
2. 在图上量热点的原图像素坐标，写进 `pins`。`l:1` 说明牌朝左，`d:1` 引线朝下，`len` 引线长度。
3. 改 `index.html` 里的标题、说明牌与吊灯卡片文字。
4. 保留页脚"场景图为生成示意"。

## 6. 载体与降级

| 情况 | 表现 |
|---|---|
| 桌面 | 指针控制光，停 4 秒自动巡游热点 |
| 投屏 | 暗部容易发糊：把 `baseMix` 从 0.42 提到 0.65，正文最小字号提到 20 px（已规划，未实测） |
| 手机（≤760 px） | 图放在下半屏，按焦点横向取景；点按或拖动移动光；当前说明牌固定在屏幕底部 |
| Reduce Motion | 不跟手、不巡游；热点处预先照亮，说明牌全显，吊灯全亮；滚动时重画单帧 |
| 无 WebGL2 | 舞台直接铺揭示层（压暗 50%），说明牌全显 |
| 无 JS | `<noscript>` 样式给舞台铺揭示层，文字照常可读 |

细节见 `references/staging.md`。

## 7. 踩坑

每条来自 2026-10-23 那次的真实反馈。

1. **光下没有内容**
   - 场景：首屏第一版，白模层与现场层都是同一间办公室。
   - 用户原话："光下边啥也没有"。
   - 原因：两层只差颜色，读者做了动作却没得到新信息。
   - 改法：每处热点在光下浮出一张说明牌，右上角计数"已看见 n / 5"；暗处压到只剩轮廓。

2. **点名参考作品，特征丢了**
   - 场景：用户要"下方是浮雕，光束边界像水墨一样晕染"。前两版做成白模沙盘与 CSS 硬光圈。
   - 原因：换题材时没先写下参考作品让人记住的特征。
   - 改法：先写 2 到 3 个特征（浮雕底、水墨光边、走过留痕），逐个落进试样，再换题材。

3. **底图太满，质感不够**
   - 场景：浮雕刻了整间办公室。
   - 用户原话："内容太多太杂，图片本身的质感不够"。
   - 原因：质感来自元素少、尺度大、留白多。
   - 改法：只留一人、一桌、一屏、一摞纸、一根网线、三只箱子，单侧掠射光。每样东西是一个热点。

4. **两层对不齐，出现重影**
   - 场景：先刻浮雕，再按浮雕重绘照片。
   - 用户原话："图片和浮雕不一样"。
   - 原因：照片会自己补细节（台灯、笔筒、衣领）。
   - 改法：先生成照片，再以照片为参考生成浮雕，一次 2 到 3 张，差值叠图挑最齐的一张（`references/asset-pairs.md`）。

5. **底层压成平灰**
   - 现象：整体去饱和后，大理石失去明暗。
   - 改法：亮度取幂 `pow(lum,1.35)` 后线性混向冷灰蓝，保留浮雕自己的高光与阴影。

6. **换章突兀**
   - 场景：首屏到下一章，背景硬切。
   - 原因：场景图与底纹一起换，中间出现黑场，墨迹也清空。
   - 改法：大理石底纹常驻；场景图四边羽化，先化回底纹再化入下一幅；墨迹保留，光不断。

7. **说明牌在造场景**
   - 场景：标注写成"屏幕上仍是待机的登录页"这类具体情节。
   - 用户原话："不要造场景，你学习一下牛逼的落地页"。
   - 改法：编号 + 概念名词 + 一句判断。画面已经画出的隐喻，文字不再复述。
