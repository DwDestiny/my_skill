# 整套 UI 图像与实现的一致性交接

本页只用于整套页面交付、公共区域复用或图到代码验收；单阶段小改按实际范围引用。它补充 [交接契约](handoff-contract.md)，不另建字段协议。阶段 JSON 使用当前契约定义的文件和字段；内容审查由人或获授权代理承担，结构校验不能代替。

## 三种图和一条基线

1. **视觉方向生图**：真实生成的概念图，用来选氛围、构图和风格；不能把图中看似精确的色值、间距或控件行为当成已测规格。
2. **逐屏设计图**：可以是参考固定母版生成的整页图，也可以是代码/Figma 组件渲染的设计预览。前者每张都要核对公共区和必需元素，生成模型不保证跨页一致；后者须明示渲染来源，不能冒充用户要求的生图。未经用户授权，不把 HTML 截图替换成用户指定的逐屏生图。
3. **运行截图**：从目标 revision 的真实应用获取，只用于运行验收。设计预览、概念图和 mock 不算运行证据。

获选方向图经设计系统阶段转为完整规格：颜色、字体/字阶、间距、网格/宽度、尺寸、响应规则、状态样式、资产和公共组件。图片推断值先标提案，借代表页与内容页整组审查后确认并冻结版本；已授权代理可完成细化并留依据，不逐值追问用户。实现截图不能回写旧设计基线；变更基线需新版本和影响范围。

## 公共区与页面覆盖

- 优先复用项目现有代码组件、Figma 组件和 tokens。没有可复用母版时，建立一份公共导航/页头/页脚等母版，登记版本、位置、允许变化项、使用页和更新规则；不要为交付样板建立与项目并行的第二套系统。
- 交互导航的文字、当前页、焦点、折叠和跳转应由代码或可操作的设计组件承担；整条 raster 图可作视觉参考或装饰，不能成为唯一控件。
- 开工先从页面、旅程、状态、视口注册表算出预计交付总数。逐屏列出内容模块、必需元素、CTA、公共组件和资产；每张默认屏图要实际生成/渲染、打开审查并记录结果。其他状态可用图或相对默认屏的明确差异规格。先看 contact sheet 检查整套节奏，再检查每张原图的细节。
- 按批交付时让已完成、pending、blocked 和剩余清单可见；已授权任务继续做完，不以 Hero、代表屏或首批图代替全套。

## 实现与复验

实现阶段把逐屏必需元素和公共组件映射到 route、文件和运行页面；关键旅程即使没有可点设计原型，也必须在浏览器中从入口走到结果。视觉 QA 固定设计基线版本、代码 revision、route、state、viewport、浏览器与字体环境，把同条件设计图和运行图并排或叠加，逐项核元素、文案、主要尺寸与间距。提前记录可接受容差和判断方式；像素分数只用于提示差异。

缺失或偏差要有问题记录、修复、同条件重拍和独立复核；公共组件改变后复验所有使用页。无法访问运行页面、基线或状态时标 unable_to_verify，不以截图存在、结构测试通过或实现者自述代替最终判断。

## 路线选择依据

- 共享代码组件与 CSS 自定义属性适合以运行产品为交付真源、需要低成本统一导航的项目；浏览器截图最接近用户将看到的结果，但渲染环境须固定。参见 [MDN：CSS 自定义属性](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Cascading_variables/Using_custom_properties) 和 [Playwright：视觉比较](https://playwright.dev/docs/test-snapshots)。
- Figma 主组件、实例、变量及 Auto Layout 适合多人设计协作、跨文件设计系统和长期设计稿维护。它约束设计文件，不自动保证代码或页面覆盖；跨文件库更新有发布与接收步骤，且部分团队库能力受方案限制。参见 Figma 官方的[主组件更新](https://help.figma.com/hc/en-us/articles/360038665934-Edit-main-components)、[变量与模式](https://help.figma.com/hc/en-us/articles/14506821864087-Overview-of-variables-collections-and-modes)、[Auto Layout](https://help.figma.com/hc/en-us/articles/360040451373-Guide-to-auto-layout)。
- 公共 raster 图片只能固定有限尺寸的外观；它不能承担响应式、文字变化、交互状态或可访问导航。仅在静态装饰或极少量固定尺寸画面中考虑。
