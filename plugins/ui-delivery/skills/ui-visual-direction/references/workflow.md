# UI 视觉方向工作流

## 目的与边界

把已知产品与交互转成能在实际图片中比较的视觉方向。用户可以授权复用现有风格；多方向是默认建议，不是固定关卡。可单独处理用户给定页面或风格 brief。

## 最小输入

至少需要页面类型与目标用户/任务，或用户明确指定的设计方向/参考图。若没有 UX 图，先写清哪些结构是输入事实，不得把视觉稿反向包装成已确认交互。

## 工作步骤

1. 检查可用的图片生成和查看能力；按用户偏好尝试可用工具，不硬编码模型或服务。用户指定的工具不可用时明确标 blocked；用户特别要求 Kimi 而当前没有 Kimi 能力时，也如实阻塞/报告，不用别的模型冒充。
2. 为公平比较候选，保持同一任务、内容、信息架构、比较视口和状态。若布局本身就是探索变量，可明确记录候选间布局差别及改变理由；用户要求同布局比较时必须遵守。通常做 2–3 个有意义差别的方向供参考；这是建议数量，不是硬要求。用户只要一个，或已有授权样式，则可减少到一个。
3. 至少用 Hero/入口屏和一个实际内容屏对比，避免只把首屏做漂亮。候选使用同一套标题、正文长度、列表数量与 CTA，区分视觉差异而非内容差异。
4. 每个方向交付可查看的实际图稿，并标注为 concept；注明方向 ID、尺寸、状态、使用的真实内容或示例内容、已知限制。
5. 记录候选的适配点、代价与风险，例如“高密度数据显示更紧凑，但长表格需要滚动”；同时注明明确禁用的方向和原因，如用户否决的强渐变/高饱和霓虹。
6. 等用户选择，或取得对代理代选的明确授权后写 style-decision.json：selection.by 只能为 user 或 authorized_agent；后者必须附授权内容。字段遵照工具 schema。
7. 完整串联时 stage 03 按契约审查后创建快照；独立调用无需快照。

## 产物

direction-options.md 逐个比较概念图和代价。style-decision.json 引用阶段内图片文件，每项标 source_kind。候选是 concept，不是实际运行 UI 截图，也不说明用户已批准。禁止采纳未经许可的商标、受限字体或付费素材。

## 失败与回退

用户要求多版本图片探索但无法生成/查看图稿时标 blocked，附具体缺少能力和解除条件；保留可确定的文字约束但不能称其为候选图。未选择时不伪造 selected choice。偏好特定视觉模型时检查可用性，不可用就报告；不要换用其他工具后谎称满足偏好。

## 验收

- 候选有真实可打开图片；内容、布局、尺寸和状态相同，可公平比较。
- 至少比较 Hero/入口屏与内容屏（用户仅要求单屏时记录此范围）。
- 方向说明包含取舍/代价/禁用风格；概念图明确标 concept。
- 决策来源、证据和授权字段通过 style-decision.json 当前 schema；validator 成功不等于用户审美批准。
