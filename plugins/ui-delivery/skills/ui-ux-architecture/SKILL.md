# UI/UX 架构

本阶段可由用户直接调用，也可由 [$ui-delivery](../ui-delivery/SKILL.md) 串联。使用本阶段实际输入即可；缺少上游文件时写明假设与限制，不伪造上游已完成。

- **目标**：在视觉方向前明确用户旅程、页面结构、行为、状态和关键元素。
- **最小输入**：要支持的用户任务和相关页面、涉及角色/权限、现存导航或业务规则；上游 brief 可用时一起提供。
- **输出**：导航、角色权限、动作、成功结果、失败反馈、去向与适用状态矩阵；每条旅程逐步指向 page、screen 和 state，每个适用状态列出需要保留和验收的关键元素；低保真结构稿按 screen ID 编排。

## 工作要求

在视觉方向前明确页面结构、旅程路径和每个状态的必要元素。按 [阶段工作流](references/workflow.md) 执行。只有完整套件工作区才登记 stage.json 与 snapshot.json；独立调用直接交付结构与状态产物。具体字段以共享交接契约为准。

## 失败回退

关键业务规则或权限不明时阻塞受影响路径；不以视觉稿掩盖交互空白。

## 验收标准

所有范围内页面都由用户旅程覆盖；每一步可定位到 page/screen/state；关键元素能追溯到用户任务，并能作为后续设计与 QA 的检查清单。核心路径能回答谁做什么、结果是什么、失败看到什么、下一步去哪。
