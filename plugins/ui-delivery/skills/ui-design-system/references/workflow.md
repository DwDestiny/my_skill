# UI 设计系统工作流

## 目的与边界

将已授权的视觉选择或现有项目样式转为可执行的完整视觉规格和组件 API。可独立盘点现有系统；完整串联时遵循共享阶段契约。本包的 tokens.json 是供本流程使用的简化语义结构，不宣称完整兼容 DTCG 交换格式。

## 最小输入

获授权的视觉方向/参考图，或现有 CSS variables、theme、组件源码；另需至少一个实际页面或组件使用范围。只有截图时可以提出概念映射，但应标注无法验证源码真源。

## 工作步骤

1. 盘点获选方向图、现有令牌、字号、断点、颜色、状态样式、组件/API 及其调用者；区分用户确认值、代码真源、提案值和图像推断。保存所选图的来源与版本；图片上的像素不能直接当作准确 CSS 尺寸。
2. 先定语义别名，再定具体值，例如 color.surface.canvas 和 color.text.muted；避免把 token 命名为某个当前页面位置或一次性设计值。
3. 为颜色建立文本/背景配对，核对用户指定的 WCAG 等级或项目已有无障碍基线；记录普通文本、较大文本、控件边界、焦点和禁用态。自动对比度值不替代实际组件检查。
4. 确定字体家族与授权来源、字阶/字重/行高、间距尺度、内容最大宽度、栅格、组件尺寸、圆角、边框及响应断点。对获选方向图只能先提出估值，再用可查看的设计预览逐项校正和确认；说明窄屏长标题、放大文字或局部模块折行，不按比例缩小整页。
5. 建立状态 token 和组件 API：组件用途、必需/可选属性、状态（default/loading/error/disabled 等）、事件、键盘行为和不应承担的业务职责。公共导航、页头、页脚、按钮等定义单一母版、版本、使用页、允许变化项和变更传播方式；已有项目组件优先复用，不为样板另造第二套系统。
6. 具体示例：按钮可用 action.primary 等语义色，区分 primary/secondary/danger 三种操作层级；disabled 不得只靠变灰，还需说明不可操作语义和辅助技术表现。
7. 将令牌和组件登记至 tokens.json、component-inventory.json，并在 design-system.md 写使用规则、来源、待定值、资产复用方式和变更约束。品牌插画、照片和纹理可复用为图片；公共导航的文字、选中态与交互控件不可仅靠一张整条 raster 图承担。
8. 在逐屏生产前，用包含入口与实际内容的代表页整组审查颜色、字体、间距、布局和公共组件基准，冻结获选方向与设计系统版本。用户已明确授权代理细化时，可由代理完成规格取舍并记录授权与样板审查依据；仅当改变已确认视觉方向、核心交互或存在必须由用户决定的取舍时再询问。缺少授权的值保留待确认，不因一张生成图看似精细就标成已测量。若后续变更基线，记录新版本和受影响页面，不能用实现截图倒写原基线。
9. 完整串联时 stage 04 经 review 后 snapshot；独立整理现有系统无需规范快照。

## 产物

design-system.md 讲语义规则和确认来源；tokens.json 放颜色、字阶、间距、布局等可消费的 token value；component-inventory.json 记录公共组件 ID、母版位置、版本、呈现方式和适用 screen ID。保持可消费而不过度抽象，不为尚不存在的场景发明 token 体系。

## 失败与回退

视觉授权不足时保留中性语义名称并将值标为 proposed；不得擅自定品牌色。图像无法验证 token 数值时把它标推测。若导入/导出要求完整 DTCG，先说明本包 schema 不兼容完整格式，再按用户授权单独做格式转换和映射表。

## 验收

- 关键颜色、字阶、间距与布局值均有语义名、用途、来源和状态规则；关键前景/背景配对有对比度记录。
- 断点处理覆盖长文本和大字号；状态设计覆盖 disabled/focus/error/loading 等适用状态。
- 组件 API 能映射到真实页面和 screen ID；公共组件有可查母版与版本，没有假定已有但仓库中不存在的组件。
- 获选图的视觉推断已逐项确认或显式待定；设计基线在实现前冻结，可追溯变更影响。
- 简化 JSON 可读且可解析；不把它标为 DTCG 完整实现或标准认证。
