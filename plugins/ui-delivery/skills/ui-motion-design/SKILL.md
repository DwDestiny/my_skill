# UI 动效设计

本阶段可由用户直接调用，也可由 [$ui-delivery](../ui-delivery/SKILL.md) 串联。使用本阶段实际输入即可；缺少上游文件时写明假设与限制，不伪造上游已完成。

- **目标**：在界面结构与主要视觉之后补充服务于理解和反馈的动效，不重定义交互。
- **最小输入**：真实界面状态和触发动作、目标平台/设备，以及 reduced-motion 偏好或要求。
- **输出**：motion-spec.md 与 motion-map.json，含触发、目标状态、时序、打断和 reduced-motion 替代。

## 工作要求

在界面结构与主要视觉之后补充服务于理解和反馈的动效，不重定义交互。按 [阶段工作流](references/workflow.md) 执行。完整套件才登记 stage/snapshot；独立审查可直接输出动效映射或 skipped 原因。

## 失败回退

交互状态未定时不猜动效；无必要动效可记录 skipped 和静态反馈方式。

## 验收标准

每个动效目的明确，操作不被阻塞，减弱动效时任务仍能完成。
