# UI 动效设计工作流

## 目的与边界

在真实交互状态之上描述能传达反馈、因果或空间变化的动效。动效排在主要 UI 结构之后，不能靠定时演示编造与实际状态无关的忙碌动画。

## 最小输入

触发动作与真实前后状态、目标平台/运行时，以及用户已声明的 reduced-motion 偏好。独立调用可基于真实运行界面或明确动效问题，不强制调用其他阶段。

## 工作步骤

1. 从已有状态机挑动效候选，逐条问它解释了哪个状态变化/反馈；无答案就不加。
2. 记录触发事件、来源状态、目标状态、开始条件、结束条件、打断条件、重复提交时行为、元素离开视口后的处理。
3. 动画必须跟随真实异步事件或状态变更；禁止用 3 秒循环假装服务器仍在工作。若实际状态未知，显示未确认反馈并保留检查/重试入口。
4. 写 reduced-motion 方案：可关闭、减少距离/闪烁或直接切换；说明内容和操作在减少动效时仍可读、可执行。
5. 记录时长/节奏的设计意图和实现建议，不为跨平台硬定超出能力的毫秒保证。
6. 若考虑引用动效组件或 API，按项目锁定的包版本查可用 API；Libraries.dev 组件集仅为可选免费来源，需核许可证和确切版本，不能作为主要动效设计者，也不得打包 Pro 内容。
7. 写 motion-spec.md 和 motion-map.json。没有值得加入的动效时，可以按契约只跳过 motion-design 并说明静态反馈理由。
8. 完整串联时 stage 06 经 review 后 snapshot；独立审查可直接给规则和状态映射。

## 产物

每项 motion ID 对应 screen/state/action、触发、目标状态、打断与 reduced_motion。motion-spec.md 记录原则、实现边界、平台/API 版本和可核验场景。

## 失败与回退

状态不由 UI 掌控时，不设计会暗示完成的动画；将真正状态以文字/图标/进度反馈显示。外部组件 API 与锁定版本不匹配时删去依赖或改用项目现有方案，不升级依赖以满足效果而不经授权。

## 验收

- 动画在真实状态切换时开始，并于真实结束事件停止；错误、取消、超时和离屏均有行为。
- reduced-motion 下完成同等任务，不遗漏状态或焦点。
- motion map 中没有无触发事件的定时循环，也不出现动效遮住 CTA 的问题。
- 复用的库/API 名称和版本可从项目配置中确认；方案通过不代表目标设备帧性能已实测。
