# UI 高保真页面工作流

## 目的与边界

把确认的交互和设计系统落实成逐 screen、逐状态、逐 viewport 的页面图与差异规格。可点原型是单独的交付选择；静态图不能证明点击路径可用，设计预览也不是运行态截图。

## 最小输入

page/screen IDs、用户旅程、交互行为和状态矩阵、已授权视觉方向、已确认的设计规格与公共组件母版。独立调用允许从用户提供的现有页面与目标路径开始，记录缺失来源。

## 工作步骤

1. 开工前列出全部预期页面 × 默认状态 × 视口及总数，再列出其他关键状态和旅程节点；逐屏列出内容模块、必需元素、CTA、数据/文案来源和公共组件引用。Hero 仅是一个示例屏，不能替代完整旅程或整套图片。按批制作时向用户展示已完成、待做、阻塞的清单；已授权范围内持续完成剩余项，不在每批后重复询问是否继续。
2. 按 screen ID 检查页面层级、密度和相邻页面节奏；全局导航、内容页、设置/表单页应遵循同一已确认母版与版本。公共交互区域推荐由同一代码或 Figma 组件渲染，公共 raster 图片只作为参考/装饰，不当作可用控件。
3. 对内容量进行压力设计：标题/副标题的长短、长段落、极短摘要、空集合（0）、单项（1）、多项、边界数量。覆盖默认、展开、空、失败状态及目标移动视口；其他状态可用整图或相对默认屏的明确差异规格，不强迫每个异常状态重新生成完整图片。
4. 对表单稿补齐逐字段错误、整体失败、保存中、保存完成和权限失败；错误信息应贴近字段并说明修复动作。
5. 区分三类图像来源并逐项记录实际工具、生成或渲染方式：①真实生成的方向概念图；②参考固定母版逐屏生成的整页图，必须逐图审查，生成模型不能保证公共区域确定性；③结构化代码/Figma 组件渲染的高保真设计预览，须注明来源和阶段，不能声称为生成式生图或真实运行截图。用户明确要求逐屏生图时实际生成并查看；未经授权不能改交 HTML 截图。
6. 每个默认 screen × viewport 交付一张可查看并人工审查的图片，至少确认一项关键元素的可测尺寸与容差；其余适用状态交付图片或可复现的差异规格。对照逐屏必需元素和已确认母版，记录缺失、偏差与重做情况。每批用缩略总览/contact sheet 快速检查全套节奏，再打开每张原图复核元素与文字；图片没有生成或没有查看，不得标 ready。
7. 为适用 screen × state × viewport 编制 screen-specs.json；在 high-fidelity.md 保留逐条审查、图片来源、公共组件版本、pending/blocked 和剩余清单。可点原型若实际交付，单独列操作路径并走查；没有原型时记录待在实现阶段浏览器验证的旅程。热点标注或一组截图不算实际可点。
8. 完整串联时在 stage 05 review 后快照，快照纳入引用资产；独立调用按实际范围交付页面图、状态规格及可选原型。

## 产物

- high-fidelity.md：全量清单与批次进度、逐屏信息层级和必需元素、公共组件版本、图片来源、状态差异与审查结论；有原型时另列操作路径。
- screen-specs.json：每条记录关联 screen_id/state_id/viewport_id、所用可查看资产或状态差异规格，遵循当前交接契约的字段。
- 可点击原型（可选）：若交付，提供真实可操作路径、运行环境和限制；不交付时由前端实现与 QA 验证关键旅程。

## 失败与回退

缺少交互决策时不要把视觉稿中的控件当产品承诺。用户要求真实生图但生成/查看能力不可用时标 blocked；代码/Figma 渲染图可以在获授权后作为另一种设计预览交付，但不能冒充生图。只有部分图片时未完成项保留 pending；不能以文字规格冒充默认屏图片。仅有概念图时注明 concept/mock，不声称已能操作。

## 验收

- 预期页面 × 默认状态 × 视口总数与已审查图片逐项对齐；其他适用状态有图片或清楚的差异规格；未完成项明示 pending/blocked。
- 页面、模块、CTA 和用户旅程可追溯；内容压力集含 0/1/多项、长文本和字段错误等适用场景。
- 跨屏导航、正文密度、标题节奏一致；不是只完成 Hero。
- 图像来源真实标注；逐图查看记录与 contact sheet 并用；静态图不计点击验收，原型若存在则单独走查，关键旅程最终在运行浏览器中验证。
