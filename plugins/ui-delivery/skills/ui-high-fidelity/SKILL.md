# UI 高保真页面

本阶段可由用户直接调用，也可由 [$ui-delivery](../ui-delivery/SKILL.md) 串联。使用本阶段实际输入即可；缺少上游文件时写明假设与限制，不伪造上游已完成。

- **目标**：按完整页面/状态/视口清单产出可查看的逐屏设计图和必需元素规格；静态图与可点原型分别验收。
- **最小输入**：目标页面和 screen IDs、交互/状态要求、已授权的视觉方向与令牌，以及需要可点验证的用户路径。
- **输出**：high-fidelity.md、screen-specs.json、实际生成并查看的页面图；可点原型仅在任务需要且能力可用时交付，未做的交互留给实现阶段浏览器验证。

## 工作要求

按 [阶段工作流](references/workflow.md) 逐屏制作并审查，必要时阅读 [视觉一致性交接](../ui-delivery/references/visual-consistency.md)。静态图片只证明可见外观；只有实际操作过的原型或运行页面才能证明路径。只有完整套件工作区才登记 stage.json 与 snapshot.json。

## 失败回退

上游关键规则未定则标记依赖；用户要求生成式图片而工具不可用时 blocked，不用代码/Figma 渲染图冒充生图。未完成的页面或图片显式 pending，不因代表页完成就收尾。

## 验收标准

每个计划内默认屏与视口都有实际可查看、已审查的图片；关键状态有图或相对默认屏的明确差异规格，必需元素和公共组件一致。若交付原型则单独走查；最终交互路径在实现阶段浏览器验证。
