# 从单账号技能升级到 wxops 多账号插件

这个 npx 包安装的 `wechat-ops-performance-review` 是**单账号运营复盘技能**。它的后续演进已经转移到 **wxops 插件**——一个覆盖账号、数据、选题、写作、配图、发布、复盘全环节的多账号编辑部。

本文说明两者的关系、要不要升级、以及怎么把已有的 `~/.wxops` 数据搬过去。

**先说结论：老技能不会被停掉，现有工作流一行都不用改。** 只做数据复盘、只有一个号，留在原地完全没问题。

## 两者的区别

先澄清一个容易混的点：本仓库的 plugin marketplace 里有两个条目。`wechat-ops-performance-review` 指向的就是本 npx 包投放的那份技能——**这两条安装通道至今等价，任选其一**。变化不在这里，而是 2026-08-01 起多了一个**另外的**插件 `wxops`，它取代了老技能的演进位置：

| | 老技能（本包 / 同名 plugin 条目） | wxops 插件 |
|---|---|---|
| 装的是什么 | `wechat-ops-performance-review` 技能 | `wxops` 插件 |
| 账号模型 | 单账号，`~/.wxops/` 直接放数据 | 多账号，`~/.wxops/accounts/<slug>/` |
| 能力范围 | 登录 → 拉数 → 复盘报告 → 看板 | 上述全部，外加选题 / 写作 / 配图 / 发布（草稿箱止步）/ 复盘闭环 |
| 赛道知识 | 硬编码在代码里（AI 工具赛道） | 可替换的赛道数据包，陌生赛道有兜底 |
| 演进状态 | **冻结**，只修阻断性问题 | 活跃开发 |

老技能被刻意冻结为只读，不再跟进插件的改动。两边出现同名函数不同实现是预期状态，别去对齐它们。

## 要不要升级

| 你的情况 | 建议 |
|---|---|
| 只有一个号，只用复盘报告和看板 | 不用动。老技能够用 |
| 有第二个号，或早晚要有 | 升级。多账号是插件唯一支持的模型 |
| 想要选题、写作、配图、发布 | 升级。这些能力只在插件里 |
| 赛道不是 AI 工具，分类总是不准 | 升级。赛道词表在插件里是可替换的数据包 |

## 升级步骤

### ① 装插件

在 Claude Code 里：

```
/plugin marketplace add DwDestiny/my_skill
```

```
/plugin install wxops@maizong-skills
```

装完 `/wxops:desk`、`/wxops:accounts` 等八个工位即可调用。

### ② 搬数据

```bash
<插件根>/scripts/wxops migrate --slug maizong --name "麦总玩AI"
```

`--slug` 是这个号在多账号结构里的标识（小写字母/数字/连字符，默认 `default`），`--name` 是显示名（不给就读老 `config.json` 里的 `account_name`）。

命令会先打印一份只读盘点（每项的文件数与字节数），然后复制、逐文件校验、落一份清单，最后把这个号注册进账号表并设为当前账号。

### ③ 验

```bash
<插件根>/scripts/wxops accounts list    # 应能看到刚迁入的号，带 ● 当前标记
<插件根>/scripts/wxops desk             # 总控台确认登录态与数据新鲜度
```

登录态（`browser-profile/`）是一起搬过来的，正常情况下不需要重新扫码。如果 `desk` 显示掉线，跑 `wxops login --account <slug>` 补一次。

### ④ 处置旧目录

`migrate` **不会删任何东西**，`~/.wxops/` 根下的 `raw/`、`reports/` 等原样留着。确认新结构跑通后再由你自己归档或删除——不确定就先留着，它们不影响插件运行。

## migrate 搬了什么、没搬什么

| 搬 | |
|---|---|
| `config.json` | 账号配置 |
| `raw/` | 抓取的原始数据 |
| `reports/` | 历史报告 |
| `data/` | 中间数据 |
| `output/` | 报告产物 |
| `browser-profile/` | 登录态（搬过去就不用重新扫码） |

| 不搬 | 原因 |
|---|---|
| `dashboard/` | 构建产物，下次 `analyze` 会重新生成 |
| `accounts/`、`accounts.json` | 多账号结构本身 |
| `runs/` | 运行清单目录 |
| `.DS_Store` | 系统垃圾文件 |

## 安全保证

这是一次数据迁移，按最保守的方式做：

- **copy-first，源文件一个字节不动。** 全程只有复制，没有 `mv`，没有删除。
- **逐文件校验。** 先比文件数和总字节数，再逐个比 sha256（超过 10MB 的文件只比大小，避免大文件拖慢）。
- **目标已存在就中止。** 如果 `accounts/<slug>/` 已经有了，命令直接退出，不覆盖——换个 `--slug` 或先处理那个目录。
- **清单落盘。** 每次迁移在 `~/.wxops/runs/migrate-<时间戳>.json` 留一份完整记录：盘点结果、复制清单、逐文件校验结果、排除项及原因。

校验失败时，命令会打印每一条不一致、指出清单位置，**已复制的内容保留原地不回滚**，然后要求你人工检查。这是刻意的：自动回滚会毁掉现场，让你没法判断问题出在哪。

回退很简单——删掉 `~/.wxops/accounts/<slug>/`，老目录本来就没动过，继续用老技能即可。

## 兼容承诺

插件保留了 `--workspace` 参数，指向哪个目录就在哪个目录干活，绕过多账号结构：

```bash
<插件根>/scripts/wxops analyze --workspace ~/.wxops
```

如果你暂时不想迁移，但又想用插件的新能力，这条路是通的。`--workspace` 与 `--account` 互斥，二选一。

## 遇到问题

- 迁移清单在 `~/.wxops/runs/migrate-*.json`，包含判断问题所需的全部信息
- 提 issue：https://github.com/DwDestiny/my_skill/issues
