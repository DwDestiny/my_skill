# UI 产品规划

本阶段可由用户直接调用，也可由 [$ui-delivery](../ui-delivery/SKILL.md) 串联。使用本阶段实际输入即可；缺少上游文件时写明假设与限制，不伪造上游已完成。

- **目标**：把需求转成页面级、可验证的产品边界。
- **最小输入**：产品目标或要完成的用户任务、主要用户、业务约束，以及相关现有页面/流程；资料缺失可形成标注清楚的假设。
- **输出**：目标、用户、任务、成功信号、范围、非目标、约束、假设与未决项；页面清单记录页面 ID、入口、用途、任务、状态与 screen ID。

## 工作要求

把需求转成页面级、可验证的产品边界。按 [阶段工作流](references/workflow.md) 执行。只有完整套件工作区才登记 stage.json 与 snapshot.json；独立调用交付阶段文件并标注假设，不强制创建快照。

## 失败回退

若关键目标或规则歧义会改变方案，列问题并标记 blocked；非关键未知可带明确假设继续。

## 验收标准

目标与页面可追溯；做与不做清楚；关键状态完整；事实、推断和未决项分开。
