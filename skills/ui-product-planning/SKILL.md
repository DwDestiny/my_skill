# UI 产品规划

本阶段可由用户直接调用，也可由 [$ui-delivery](../ui-delivery/SKILL.md) 串联。使用本阶段实际输入即可；缺少上游文件时写明假设与限制，不伪造上游已完成。

- **目标**：把需求转成可执行的用户旅程、页面范围和可核对的关键元素。
- **最小输入**：产品目标或要完成的用户任务、主要用户、业务约束，以及相关现有页面/流程；资料缺失可形成标注清楚的假设。
- **输出**：目标、用户、任务、成功信号、范围、非目标、约束、假设与未决项；有序旅程覆盖所有范围内页面，页面清单记录页面 ID、入口、用途、任务、screen ID、关键状态和必须呈现的内容/控件。

## 工作要求

把需求转成旅程覆盖完整、页面范围明确且元素可追溯的产品边界。按 [阶段工作流](references/workflow.md) 执行。只有完整套件工作区才登记 stage.json 与 snapshot.json；独立调用交付阶段文件并标注假设，不强制创建快照。字段结构以共享交接契约的当前 schema 为准，不另造平行 ID 或 JSON 结构。

## 失败回退

若关键目标或规则歧义会改变方案，列问题并标记 blocked；非关键未知可带明确假设继续。

## 验收标准

目标与页面可追溯；每个范围内页面由至少一条用户旅程覆盖；旅程步骤指向明确页面、screen 和 state；每个 screen/state 标出关键必需元素；做与不做清楚；事实、推断和未决项分开。
