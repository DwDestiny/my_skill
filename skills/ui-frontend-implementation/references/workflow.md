# UI 前端实现工作流

## 目的与边界

把已确认的产品和 UI 契约落到可运行代码。此阶段可独立调用现有项目，但必须读取项目自己的规则、入口和实现；不在编码时重新拍板产品、交互或视觉。

## 最小输入

目标代码仓库/运行环境、相关 AGENTS/README、要改的页面或用户路径、当前 UI 基线或 screen IDs、已知数据与权限行为。整套交付还须接收实现前冻结的设计版本、令牌、公共组件母版、资产清单及逐屏必需元素；独立单点修复按实际输入和授权范围处理。

## 工作步骤

1. 确认仓库和分支、项目文档、未提交改动、相关目录 L2、启动与测试命令；避免覆盖用户已有修改。
2. 建旅程和需求到文件/路由映射表：每条需求指向 route、screen/state、必需元素、CTA、公共组件版本、资产来源、输入/输出数据、权限边界和验收证据；核对全量页面清单而非只实现代表屏。
3. 检查冻结设计基线和交互契约与实现目标一致；有矛盾时暂停受影响项，记录待决策差异。优先复用项目已有组件/tokens，不另建第二套主题；公共导航等交互区域由同一代码组件提供，并追踪所有调用页面。
4. 把所有 mock、fixture、演示文案和真实数据通路明确标记；模拟状态不可伪装成已保存、已提交或来自生产系统。
5. 实现默认、加载、空、成功、错误、权限拒绝状态及可恢复操作。记录刷新后的状态规则；保存成功需以真实数据读回确认，不只看前端 toast。
6. 检查权限失败和网络超时的差异反馈；拒绝请求不能留下“已完成”状态。未获授权不可扩展账户权限、连接生产系统或部署。
7. 在浏览器按已登记旅程实际点击入口、跨页导航、主要 CTA、反馈、返回和结果；验证没有可点原型时留到本阶段的交互义务。检查默认与目标异常状态，逐页比对必需元素、公共组件和主要尺寸；代码渲染的预览图注明 design/render，实际运行截图注明 runtime_capture，不能混用。
8. 给出可运行命令、必要环境变量名称（不含值）、目标 route 和可复现点击路径；说明冷启动/刷新后的行为。公共组件变更后列出并复查所有使用页。
9. 写 implementation-report.md 与 implementation-map.json，记录设计基线版本、页面/元素覆盖、浏览器旅程结果和剩余差异。完整串联时 stage 07 审查后快照；独立调用按目标项目规范交付。

## 产物

implementation-map.json 将需求项映射到 route、文件、screen IDs、revision、数据来源和实现状态。implementation-report.md 记录已做/未做、设计基线版本、必需元素与公共组件覆盖、mock 边界、浏览器旅程、运行命令、权限/刷新/失败行为与遗留缺口。

## 失败与回退

项目无法启动、目标环境权限不足或关键 API 缺失时，保留最小可运行改动并标 blocked；只生成静态图或 mock 时明确这不是完整功能接线。发生规格冲突时列出冲突和复现证据，不擅自改变行为。操作用户数据前先满足项目安全与备份要求。

## 验收

- 需求表中的每一条可映射到真实 route、实现文件和 screen/state。
- 全量旅程的页面、内容模块、CTA 和公共组件与冻结规格对齐；公共组件修改后所有使用页已复查。实现中的差异被显式记录，不能用当前截图改写原设计基线。
- mock、fixtures、占位数据明确可见，不被描述为持久化业务数据。
- 给出能从干净启动复现的命令和路径；关键操作刷新后结果符合契约。
- 真实接口的权限拒绝、超时和失败不会被显示成成功。
- 单测/构建、浏览器实际行为分别报告；前者通过不能替代后者。
- 用户旅程在真实浏览器从入口到反馈与结果可操作；静态图或可点原型不能代替实现验证。
