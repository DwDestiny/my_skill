# 内容与讲解方案

把目标和资料变成一份蓝图：读者是谁、读完能做什么、保留什么、按什么顺序讲、每块用什么形式、每条断言的来源与可信度。蓝图交给视觉侧做页面（装了 `design-techniques` 插件时，由它的 `catalog` 选手法）。本 skill 不决定颜色、字号与动效。

## 1. 触发后先做的三件事

1. 读用户原话。逐字抄进 `audience-outcomes.md` 第 0 节。
2. 收集输入：资料路径、目标、受众线索、交付形态（本地 HTML / Artifact / 其他）、用户对风格的话（只记录，不决定）。
3. 建目录：项目里有 `01-内容规划/` 就用它；没有则在页面目录旁建 `content-plan/`。复制 `assets/templates/` 的模板进去。单页且章数 ≤8 时，证据索引和术语表可写进 `blueprint.md` 的附录，不复制这两个独立模板。

## 2. 术语表

| 术语 | 含义 |
|---|---|
| 结果 | "读完后，读者能 X"的可检验陈述，编号 O1… |
| 体验目标 | 用户原话里的体验词（炫酷、高级、有辨识度、想停留）转成的目标：读者应记住这个身份的什么性格，第一眼和中段各被什么吸引。编号 E1… |
| 演示块 | 资料缺具体对象时，明确标注为演示的具体过程，不当事实 |
| 断言 | 页面上的一条事实、判断或缺口，编号 C001… |
| 证据索引 | 全部断言的登记表。独立文件 `evidence-index.md`，或 `blueprint.md` 附录（单页且章数 ≤8） |
| 三态标记 | 事实 / 判断 / 缺口 |
| 可信度 | 高 / 中 / 低 / 未验证 |
| 信息形状 | 内容的结构类型（单值、多对象多属性、顺序、流向、占比、空间） |
| 形式 | 呈现方式：`text` `table` `compare` `timeline` `metric` `chart` `diagram` `figure3d` `exploded` |
| 蓝图 | `blueprint.md`，交给 A 的契约文件 |
| 速读通道 | 只读顶部摘要与每节首句也能得到主线 |

## 4. 流程

### 步骤 0：再入（已有蓝图时先做）

触发条件（任一条）：

1. 新资料到达（用户给文件、仓库更新带来新材料）。
2. 目标或受众变化（例如从"行业"改为"某一家单位"）。
3. 用户说内容过时、不对、没有按最新资料更新。

做法：

1. 读新资料和项目 README 的"下一步"。如果用户原话或项目文件已经给出方向，直接按它做。不要先问"要不要改"。
2. 重新检验 `audience-outcomes.md` 的假设。写明哪条假设被新资料改变。
3. 重定主线。把新内容放到主线位置，必要时重排章节。不要只在末尾追加。
4. 新断言进证据索引。新术语进术语表。结果 O 随目标变化。
5. 蓝图升版本，`handoff-log.md` 追加一条记录，通知视觉侧重建页面。蓝图改了而页面没重建，不算完成。
6. 做完再报告：改了什么、没改什么、原因。

> **警告**：只在两种读法会改变页面用途时才问用户。问的同时，先按推荐读法做。用户没有回复，不等于暂停。继续主线，并在报告里写明采用了哪种读法。

反例（2026-10-15）：新材料到达后，只汇报并问"要不要改页面"，用户没有回复，我转去做别的事。用户之后追问为什么没有更新。

### 步骤 0.5：产品层（根本目标到页面职责）

先回答"这页为谁解决什么"，再拆内容。职责卡是"我们的建议"，不写成客户已确认。

1. 写根本目标表：客户（发起这页的人）的业务目标与读者的目标分两行写，各附依据。
2. 写工作故事 3 到 7 条："当（情境），我想（动机），以便（结果）"。按失败代价从高到低排序，编号 J1…。
3. 写页面职责卡：每页或每章一张，首屏单独一张。本步只填五个产品字段：对应工作故事、访客到此状态、离开时必须做到、唯一主任务、禁止出现。必需内容、展示形式、视觉重量留空，到步骤 9 回填。
4. 多页面、多角色产品才加故事地图或面包板。单页不做。
5. 写进 `blueprint.md`：顶部摘要之后、第一章之前，节名"产品层"。格式见 `references/blueprint-template.md` 第 1、1.1 节。
6. 资料里没有的目标与代价写"未知"，不编。

### 步骤 1：受众与场景

1. 回答 `references/audience-outcomes.md` 第 1 节的 6 个问题。
2. 写出典型读者的"已知 5 条、不知 5 条"。宁可假设读者知道得少。
3. 写使用方式：速读、翻查、学习、体验，可多选，标主次。
4. 写错误代价：说错一个数字会怎样。

### 步骤 2：结果定义

1. 每条结果写成"读完后，读者能 X"。X 用可测动词：说出、区分、指出、判断、算出。
2. 每条结果配一道自测题，答案在页面里能找到。
3. 标优先级：必须 / 应当 / 可选。
4. 禁用"了解""熟悉""掌握"。
5. 用户原话有体验词（炫酷、高级、惊艳、有辨识度、想停留）时，写体验目标 E1…，优先级为"必须"。写三句：
   - 身份：读者看完应记住这个团队、产品或人的什么性格（例："判断快、做东西利落"）。
   - 第一眼：首屏应让人停下的那个东西是什么（只写对象和感受，不写颜色和动效，那些由 A 定）。
   - 中段：读到中段，什么让人继续往下看（例："看到一个真实问题被拆开的过程"）。
   再写两项：希望观众在画面里直接看到的关系（例："一个问题在三个人手里被改了三次"），和容易偏成的样子（例："只像一个 logo 样机""变成合作说明工具""例子行业接管整页"）。
   原因：体验词只进 `style_quotes` 时，后面每一步都会把它当风格词，页面会变成清楚但平淡的说明页。"能认出页面上有什么"不等于"被吸引"，所以体验目标写感受和性格，不写可辨认的对象清单。E 是待视觉验证的设计假设：写完不等于做到，它由首屏试样和用户看成品来检验。

### 步骤 3：证据索引

1. 通读资料。每条会上页面的数字、名称、引文、评价词登记一行。
2. 填类型：事实（有来源）/ 判断（有依据，写反面证据）/ 缺口（未知）。
3. 填可信度：高 / 中 / 低 / 未验证。规则见 `references/evidence-and-credibility.md`。
4. 资料里没有的内容不登记，也不上页面。

### 步骤 4：术语表

1. 一个概念一个词。登记首选词与禁用同义词。
2. 每个术语：一句话定义、类比、例子、边界、前置概念。
3. 按首次出现顺序排列。

### 步骤 5：取舍

1. 每条断言分到：主线 / 折叠 / 附录 / 删除。规则见 `references/structure-patterns.md` 第 3 节。
2. 每条过 so-what 测试：删掉它，哪条结果受损？答不出就删。
3. 信息缺口不删，单独成节。
4. 资料缺少能展示的具体对象（成员、案例、业绩）时，先向用户要：成员照片、名字与角色、现场照、做过的东西、公开链接。团队页、个人页、机构页的主角是人和他们做的事，真实材料比任何自绘物件都强。原因：团队页第四次实测从头到尾没有问过用户要材料，页面只剩一个抽象雕塑和三行文件名。
5. 用户给不了时，下面几种东西可以正当地填出"可看的内容"。每种都要可核实或明确标注：
   - 可核实的公开事实：这个职业或领域的来历、行话、典型现场、公开的标志性事件，带来源进证据索引。例：FDE 这个角色名在公开的招聘页里有可引的原话（Palantir 招聘页把角色分为 Echos、Deltas、Devs，写到"from the CIO to the nurse"）。
   - 角色而不是具名成员：写"判断、设计、工程"这几种角色各自在现场做什么，不编名字、头像和履历。
   - 场景图：用 `image-gen` 生成工作现场、工具、环境，标"示意"。
   - 演示块（下一条）。
   不编具名成员、客户、logo、数字业绩。
   "示意、虚构、mock"的说明集中写一处（页脚或首屏角落一行小字），不在每张卡、每张图上重复标。原因：团队页第五次几乎每个块都带 mock 标注，画面被切碎。
6. 演示块。演示块是例子，服务于身份：它展示团队提议的工作方法，不证明真实的履历、业绩或能力，也不决定整页的视觉世界。做法：一个具体过程贯穿页面，例如"一份零散记录 → 提炼问题 → 原型 → 发现问题 → 改一次"。块上写 `demo: yes`，页面就近标"演示示例"，内容不进证据索引的事实。原因：描述能力不如展示能力，页面要有可看的东西。
7. 删除的断言列进蓝图的"删除清单"，写原因。

### 步骤 6：结构与讲解逻辑

1. 选总体叙事模式：地图式总分总（默认）、答案先行、SCR、问题—方案、概念递进。可按章节混用。
2. 每章一个论点句标题（≤25 字）。标题、副标题、过渡句、按钮、首屏是展示文案，按 `references/copywriting.md` 写：先找洞察，一个概念贯穿，写判断不写设问。
3. 每章新概念 ≤3 个。陌生概念按"类比 → 定义 → 例子 → 边界"引入。
4. 每章末写一句检查点："读完这节你能……"，对应一条结果。
5. 画一张章节到结果的对照表：每章至少挂一个结果，每个结果至少有一章。
6. 每章 `id` 对应一张职责卡。章标题的论点句要能完成该卡的唯一主任务。

### 步骤 7：形式选择

1. 每个内容块先写信息形状，再按 `references/form-selection.md` 的表选形式。
2. 每张图写一句结论标题，并写预算数值（节点数、行列数、序列数）。
3. 预算超过 `form-selection.md` 第 3 节的上限时，拆成总览加细节，或改用表格。
4. 等轴测 3D 只在"空间或机构本身是要讲的内容"时选。
5. 每章标 `stage: yes|no`。有过程、状态变化或空间关系的章为 `yes`。默认舞台章不少于总章数的 1/4（向上取整）。偏离时在 `notes` 写理由，并说明属于哪类不适用页面（操作型原型、成功/确认状态、需要重复结构做比较的页、短内容阅读页）。
6. 每章写 `image_needs`：只写需求（`purpose`、`subject`、`kind`、`size`），不写做法、风格与提示词。不需要图像时写 `[]`。字段见 `references/blueprint-template.md` 第 1.1 节。
7. 蓝图定内容目标，不定画面解法。"首屏要让人记住团队的哪种性格"是内容目标；"首屏是分层的工作对象""用重复录入故事做主画面"是画面解法，写进蓝图时标"待方向验证"，由选手法与首屏试样决定。原因：团队页第四次的蓝图 v0.1 先定了"工作对象分层"和"重复录入故事"，三个方向只是给同一个故事换容器，全部被退回。

### 步骤 8：信息架构

1. 顶部摘要：3 到 5 条要点，每条带断言 ID。
2. 导航：目录，显示当前位置。
3. 章节长度 1 到 3 屏。超过就拆或折叠。
4. 折叠最多两层。折叠标题写清里面是什么。
5. 速读通道检查：只读摘要与每节首句，能否得到主线。
6. 可信度图例放一次。

### 步骤 9：写蓝图

1. 按 `references/blueprint-template.md` 填 front matter 与每章块。
2. `reader_mode`：只提示读者主要怎么用这页，不是分级。读者主要读文字选 `读`；读和看都有选 `读看`；主要看和体验选 `看`。视觉氛围由 A 在设计阶段定。用户对风格的原话写进 `style_quotes`，由 A 与用户裁决。
3. 填删除清单与信息架构节。
4. 回填职责卡：必需内容（块或断言 ID）、展示形式（`form` 值）、视觉重量（主角 / 配角 / 背景）。把每条工作故事 J 挂到结果 O。

### 步骤 10：自检门禁

1. 每章至少挂一个结果；每个结果至少有一章。有 E 时，首屏章和至少一个中段章挂 E。
2. 页面每条断言有 ID；蓝图里没有无 ID 的数字。
3. 每个概念在引入前已在术语表登记，前置概念先出现。
4. 折叠不超过两层。
5. 章节 1 到 3 屏。
6. 没有话术、提问顺序、销售说法：grep "建议你问""可以说""话术""切入点""打动"。
7. 标题 ≤25 字；描述句 ≤50 字；一段 ≤6 句。
8. 有条件时请一位非行业读者读摘要与第一章，圈出看不懂的词，回改术语表。
9. 有"产品层"节：工作故事 3 到 7 条，每页或每章有职责卡，职责卡九列全非空。
10. 每章有 `stage` 与 `image_needs`。舞台章少于总章数的 1/4 时，报 `stage_short` 提示项（不是失败项）：补舞台章，或在 `notes` 写偏离理由。
11. 每条工作故事 J 至少有一章承担。每张职责卡的 J 至少挂一个 O。
12. 视觉重量为"主角"当且仅当该章 `stage: yes`。有冲突时改其中一处。

### 步骤 11：交接

1. 在 `handoff-log.md` 写一条 `ready`：蓝图版本、章数、断言数、reader_mode。
2. 收到 A 的退回条目时，按 `references/blueprint-template.md` 第 4 节处理，追加回复，不改旧条目。
3. 蓝图改动后升版本号。

## 5. 边界

1. 不决定颜色、字号、间距、动效。蓝图里只写信息形状与预算。
2. 不发明数据。资料没有的写"缺口"。
3. 评价词（"显著""领先""大幅"）视为断言，必须有来源，否则换成数值或删除。
4. 不写沟通话术、提问顺序、销售说法。受众分析只记"对方关心什么"，不写"怎么说"。
5. 不替任何人作承诺。
6. 用户原话优先于本文件的任何规则。冲突时按用户原话做，并在蓝图 `notes` 里写明。

## 6. 交接契约

契约文件：`references/blueprint-template.md`。A 侧是所选手法的子 skill：它读蓝图的章节、断言与 `image_needs`，按自己的 SOP 做页面。

A 可能退回七种问题：`over_budget`、`wont_fit`、`form_mismatch`、`missing_source`、`term_conflict`、`incomplete`。B 对每条回复：调整 / 保留并说明 / 需用户裁决。

## 7. 写法

展示文案（主标题、副标题、过渡句、按钮、首屏）按 `references/copywriting.md` 写。其余产物用 ASD-STE100 风格简明中文：一词一义、短句、主动语态、步骤编号、条件在前、警告在前。细则与中文禁词表见 `references/writing-style.md`。

## 8. 本项目叠加层

见 `references/project-overlay.md`。换项目时删除或改写该文件。

## 9. 验证方法（协调者照做）

样例任务 B1：用 `01-业务调研/工程设计院AI讲解页-20261015/00-资料/` 的两份资料，目标"让一位非行业业务人员在 2 小时内读懂行业、已有成果、关键概念"。

1. 产出目录有 `audience-outcomes.md` 与 `blueprint.md`；证据索引与术语表是独立文件，或是蓝图附录（以交付包清单为准）。`audience-outcomes.md` 第 0 节含用户原话逐字。
2. `audience-outcomes.md` 有 ≥5 条已知、≥5 条不知、≥4 条结果，每条结果有自测题与可测动词。
