## 1.1 产品层与新字段定义

产品层由 `SKILL.md` 步骤 0.5 写出，步骤 9 回填。职责卡八个字段：

| 字段 | 写什么 |
|---|---|
| 工作故事 | J 编号，可多个。步骤 0.5 填 |
| 访客到此状态 | 读者到这里时知道什么、想要什么。步骤 0.5 填 |
| 离开时必须做到 | 一句可检验的结果，最好带数字或名称。必须能对应某个 O 的自测题。步骤 0.5 填 |
| 唯一主任务 | 本页或本章只做的一件事。章标题的论点句要完成它。步骤 0.5 填 |
| 必需内容 | 块 ID 或断言 ID。步骤 9 回填 |
| 展示形式 | 用第 1 节的 `form` 值或其组合描述。步骤 9 回填 |
| 视觉重量 | 主角（舞台）/ 配角（有图示的阅读章）/ 背景（纯阅读章）。步骤 9 回填。主角当且仅当该章 `stage: yes` |
| 禁止出现 | 本章不得出现的内容或做法，一到三项。步骤 0.5 填 |

表头多一列"页面 / 章"，用来对齐章节 `id`。工作故事表多"编号""失败代价""结果"三列，用来排序并挂到结果 O。

`stage`（每章必填）：

1. 值只能是 `yes` 或 `no`。
2. 判定：本章有过程、状态变化或空间关系时为 `yes`。纯概念、纯列表为 `no`。
3. 默认舞台章不少于总章数的 1/4（向上取整）。不足时 B 在步骤 10 报 `stage_short` 提示项（不是失败项）。偏离时在 `notes` 写理由，并说明属于哪类不适用页面。
4. `yes` 只是候选。A 决定哪些章真正成为舞台区。

`image_needs`（每章必填，可为空列表）：

| 键 | 写什么 |
|---|---|
| `id` | 可选。指向资产清单的编号，如 `A01` |
| `purpose` | 这张图在本章的职责，一句 |
| `subject` | 画面主体，只用资料里有的事物与数字 |
| `kind` | 信息形状：`data`（数据）/ `mechanism`（机制、过程、结构）/ `atmosphere`（氛围、场景） |
| `size` | 版面位置与比例，例如"全宽 16:9""侧栏 1:1" |

蓝图只写需求。做法（生成图像或自绘矢量）、风格与提示词由 A 侧在 S3 资产清单定。

## 2. A 开工的门禁（B 自检同一清单）

1. front matter 字段齐全。
2. 每章 `claims` 的每个 ID 在证据索引里存在（独立文件或蓝图附录）。
3. 每个 block 的 `form` 是允许值之一。
4. 每个非 `text` 的 block 有 `budget` 数值。
5. 每章 `screens` 为 1 到 3。
6. `reader_mode` 为三值之一：读、读看、看。
7. 每章有 `stage` 字段，值为 `yes` 或 `no`。

## 3. A 的退回类型

| 类型 | 含义 | B 的典型处理 |
|---|---|---|
| `over_budget` | 图或表超预算 | 拆章、拆图、改表 |
| `wont_fit` | 在 390px 或 1440px 放不下 | 缩标题、拆块、移折叠 |
| `form_mismatch` | 指定形式画不出 | 改 form |
| `missing_source` | 页面需要的内容没有证据 ID | 补登记或改为缺口 |
| `term_conflict` | 术语不一致或缺词 | 改术语表与蓝图 |
| `incomplete` | 门禁未过 | 补字段 |
| `gear_conflict` | A 认为读者使用方式与预算预设不符 | 写理由，交用户裁决 |

## 4. `handoff-log.md` 条目格式

B 发出：

```
### R<三位序号> · ready · <日期> · 发自 B
- 蓝图版本：0.1
- 章数 / 断言数 / reader_mode：…
- 状态：待 A 确认
```

A 退回与 B 回复（追加，不改旧条目）：

```
### F<三位序号> · <类型> · <日期> · 发自 A
- 章节：<id>
- 位置：<元素或截图编号>
- 实际 / 上限：<数值>
- 建议：<一句>
- 状态：待 B 处理
- B 回复（<日期>）：调整 | 保留并说明 | 需用户裁决
- 变更：<蓝图字段与新版本号>
- 状态：已处理 | 待用户
```

A 交付：

```
### D<三位序号> · delivered · <日期> · 发自 A
- 页面：<路径>
- reader_mode：…
- 每章实际屏数：s1=2, s2=1 …
- 每图实际节点数：…
- 未渲染断言：无 | [C0xx]
```

## 5. 版本规则

1. 蓝图每次改动升小版本（0.1 → 0.2）。
2. 结果或章节结构变化升中版本（0.x → 1.0）。
3. 旧版本不删，改名为 `blueprint-v0.1.md` 归档，或靠 git 历史。
