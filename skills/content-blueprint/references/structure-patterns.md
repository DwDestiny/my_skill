# 叙事结构与讲解逻辑

## 1. 先分类：这一页主要是哪一类

借 Diátaxis 的四分法，一页以一类为主，不混写。

| 类 | 读者在做什么 | 结构 |
|---|---|---|
| 解释 | 想弄懂为什么、是什么 | 概念递进 + 答案先行 |
| 参考 | 要查一个事实 | 表格、术语表、按对象分组 |
| 教程 | 跟着学会一件事 | 步骤、每步一个结果 |
| 操作指南 | 要完成一个任务 | 条件在前的步骤 |

行业讲解页通常是"解释"加少量"参考"。

## 2. 叙事模式

| 模式 | 适用 | 用法 |
|---|---|---|
| 地图式总分总 | 内容多、读者会跳读 | 默认。开头一张全貌（摘要或总览图），中间分区，结尾回扣结果 |
| 答案先行（金字塔） | 判断型章节 | 首句写结论，证据在下，分组理由同层同角色 |
| SCR（情境—复杂—问题） | 读者要先接受背景 | 导语 2 到 3 句，不超过一段 |
| 问题—方案 | 说明某项成果解决什么 | 只写"解决什么、证据是什么、边界在哪"，不写推进 |
| 概念递进 | 概念有前置依赖 | 先基础后派生；每章新概念 ≤3 |
| 时间线 | 演进、里程碑 | 按真实时间间距；节点 ≤8 |

一个页面可混用：总体地图式，判断章答案先行，概念区递进。组数按内容定，不强制三条。

## 3. 取舍规则

| 去向 | 判据 | 位置 |
|---|---|---|
| 主线 | 直接支撑某条结果；没有它读者无法理解后文 | 章节正文 |
| 折叠 | 支撑证据、数据明细、方法说明、边界案例、反面证据 | 章节内折叠块 |
| 附录 | 全量来源表、术语表、原始数据、口径差异清单 | 页尾 |
| 删除 | 不挂任何结果；重复已有信息；so-what 测试答不出 | 不进页面，记入删除清单 |

so-what 测试：删掉这句，读者的哪条结果受损？答不出就删。

信息缺口单独成节，放在结论之后、附录之前。

## 4. 讲解逻辑

1. 陌生概念四步：类比（读者已知的事物）→ 定义（一句话）→ 例子（资料里的真实情形）→ 边界（它不是什么）。
2. 每屏一个主题。一章引入新概念 ≤3 个。
3. 术语首次出现即解释，之后全文同一个词。类比词不进术语。
4. 抽象陈述后 1 屏内给例子。
5. 章末检查点："读完这节你能……"，对应一条结果。可附一道自测题，不用弹窗。
6. 速读通道：只读顶部摘要与每节首句，也能得到完整主线。

### 4.1 讲课页（投屏授课）

讲课页是讲者投屏、学员边听边看的页面。屏上只放学员此刻要看的东西，讲者要讲的话放讲者条。

1. 按费曼学习法排每个概念：一件小事（学员自己做过的事，先不提术语）→ 一句白话（卡住的地方补上，这时才给名字）→ 拆开看（图、短代码、跑一遍）→ 换个情况（只改一个条件，看结果怎么变）→ 讲回一遍（用一句话讲给没学过的同事，再答两三个问题、对照常见误会）。衔接课里，“一件小事”换成案例里的一刻。
2. 例子的大小按要讲的东西选。讲概念、讲原理：每个概念用能讲清它的最小例子，三条标准：人人做过，一句话说得完，只改一个条件结果就变。讲方法怎么落到业务上（衔接课、情境练习课）：才用业务案例。不要为了“贯穿”把一个业务大案例套到每一讲上：学员得先学业务，才看得到要讲的东西。
3. 先定课程自己的主线：学员带着哪几个问题来，按什么顺序回答，最后怎么独立做一遍。再看它在整套课里的位置。独立的课（默认）：前置写成能力，例子的背景在本课讲清，不按别的课逐讲对应。第一次见到方法的课：概念在案例里第一次出现时才引入。衔接课（用户说明学员已听过方法，这节要接到实操）：先用一段方法论回顾把整张地图摊开，再让案例沿地图一格一格走，最后回看地图并练习。
4. 一页一个要点。屏上：一句主句（≤20 字）+ 一张图或一组卡片／表，最多 3 个短标签（每个 ≤12 字）。画面要填满：图占一半以上，正文块在屏上垂直居中，投屏字号让最后一排能读。
5. 给长课加串联：每段开头一页说这一段问什么、交出什么、常见偏差；每段结尾在同一张总表上填一行；每页右上角标当前位置。学员任何时候都知道自己在地图哪一格。
6. 图的主体用例子里的具体物件和原话：单据、手机屏、时间线、一句话。
7. 讲者要点、出处、参考答案不上屏，放讲者条或讲者手册。
8. 交给用户看的是画出来的试样页，不是逐页文字表。蓝图是内部底稿，用户不需要读它。

| 平庸 | 好 |
|---|---|
| 技术课第 1 讲讲“什么是 Agent”，例子用一家车队的费用核查：先三页讲车辆调动和费用归属，第 6 页才出现循环 | 例子用“明天去杭州，下雨就改去苏州”：先讲托同事看天气，同事看到下雨才去查苏州；再让模型做，它看不到天气；补上工具和循环，就是 Agent。换成杭州晴，少走一个回合 |
| 一页列出“业务事实 / AI 辅助 / 规则和人”三栏，每栏四五行说明 | 一张费用单据画在中间，三个箭头分别指向“AI 读出数字”“规则算出偏高”“人判断是否违规”，主句：“AI 给线索，人下结论” |
| 衔接课 10 页试样：直接从案例第一刻开始，页与页之间没有“现在在哪一步”，每页下半屏空着 | 约 80 页三部分：方法论回顾（各步、各条线、关键概念、一张空总表）→ 案例沿各步走（每步开头页 + 总表行）→ 回看与练习；右上角标“二 · 第 3 步” |
| 先用两页讲概念定义，三节后才出现客户原话 | 先放客户的一句原话，再给名字：“这就是紧迫性” |

### 4.2 情境练习课（学员扮演角色、闯关做题）

学员在一个案例里扮演一个角色，一关一关做题，把成品做出来。学员要先进入情境，才知道每道题为什么要做。

1. 开场先讲背景，再讲规则和做法。背景回答五件事：客户是谁、这门生意怎么运转（钱从哪来、花在哪、什么时候进出）、客户日常怎么干活、客户想要什么和试过什么、学员扮演谁要做成什么。
2. 背景写成学员能复述的小故事：每件事一张卡，一个短标题加两三句白话，用演示世界里的数字（几家单位、几辆车）。
3. 背景不提前说出关里的答案。关里要判断的事（首期做哪几条、看板缺什么）在背景里只交代处境，不交代结论。
4. 每关开头一句“前情”，接上一关的结果，再说这一关眼下发生了什么。学员连着读各关的前情，能读出一条完整的故事线。
5. 收尾写一句“结局”：故事里的事办成了什么，再接到产物回看和自测。
6. 练习课和成品演示是两件东西：各打一个包、各有一个链接，页面之间不互相链接。练习课入口直接进第一页，开场只交代要做成什么，不先放成品走查。成品演示单独打开，最后一步回到它自己的总览。
7. 练习课一屏一页，方向键或底栏翻页。一页放不下就拆成两页，不做整页长滚动。
8. 成品演示让讲解指向“外框里的真东西”。外层讲解页沿用课程的风格；内嵌的成品按真实产品的风格做（产品配色、系统字体、表格与状态标签），放进手机或浏览器外框。讲解气泡编号，对应成品里的圈，箭头从气泡指到部件。学员在成品里点到别的页面，讲解跟着换到那一步。
9. 成品和练习课用同一份演示数据：学员在关里做出的记录，就是成品里的那几条。成品另需的数据（更多的车、更多的客户）单独放一个文件，标明是自拟的。
10. 翻页不上锁。“下一页”一直能点，题没做也能往后翻；顶部关号能直接去任意一关。进一关时整关的页一次排好，不等答对才生成下一页。翻到这一关的产物页，这一关才算做完。原因：验收的人和回头复习的学员要能很快翻到任意一页。题靠内容吸引人作答，不靠锁。
11. 选择题的选项一样具体、长短相近，差别只放在这一关要练的判断上。错的选项各踩这一关的一个真实的坑（取自案例里出过的错），不写成一眼就能排除的偷懒短句。选对后显示这一关自己的理由，不用一句通用的话。自检：不看题干，只比三个选项的长短和细节多少，猜不出哪条对。
12. 课末只留和结果挂钩的题：每道自测对应一条结果（O），再加一张“你写的 / 真实项目”对照表。挂不上结果的“加练”“拓展题”不做，题多了验收和学员都翻不完。

| 平庸 | 好 |
|---|---|
| 开场一句“你是这个项目的 FDE，客户是一家用车服务公司”，接着就是规则、节奏和第 1 关 | 开场五张卡：这家公司（给政企单位管用车，2 家单位、3 辆车）→ 怎么算账（三种车三套账，钱先出后回）→ 每个月（票据从司机传到财务，车会月中换单位）→ 老板的愿望（想看清哪里赚钱，试过通用 AI 会混）→ 你的任务（六关从弄懂生意到验收）；之后才是规则和第 1 关 |
| 第 4 关开头直接是“车03 月中调了单位，AI 给了一版设计” | 先一句前情：“三层任务分好了，先做最底下那层：每笔费用都要挂到对的车和合同上”，再接这一关的处境 |
| 入口是一段九步的成品走查，学员还不知道要做什么，先看了答案；成品里的手机和窗口连界面都是手绘的 | 练习课入口直接进第一页，一屏一页；成品演示另打一个包、另一个链接：手绘讲解页里嵌一个商务风格的应用，气泡箭头指到应用里的“初检建议”“结算单编号” |
| 收尾 10 页：5 道自测、对照表、2 道加练，最后一页再链到成品演示 | 收尾 7 页：拼齐、5 道自测（每道对应一条结果）、对照表；成品演示单独成包 |
| 每道题答对了才放开“下一页”，验收的人要把六关的题全答一遍才看得到收尾 | “下一页”一直能点，整关的页进关时就排好；顶部关号直达任意一关 |
| “选一条指令发给 AI”：两条是一句话的偷懒指令，一条是带材料的长指令，看长度就能猜中 | 三条都给材料、长短相近：一条只比收入，一条把“靠规模赚钱”当前提，一条按三种业务分开算、利润和现金流分开写 |

## 5. 认知负荷检查

| 项 | 上限 |
|---|---|
| 章节长度 | 1 到 3 屏 |
| 一章新概念 | 3 |
| 一屏主题 | 1 |
| 折叠层数 | 2（主线 + 折叠） |
| 顶部摘要要点 | 3 到 5 |
| 标题 | 25 字 |
| 一段 | 6 句 |
| 同屏可见的图 | 2 |

## 6. 外行测试

有条件时让一位非行业读者读摘要与第一章，圈出看不懂的词。把圈出的词回写术语表，补类比或例子。没有条件时，由另一个不看资料的代理读蓝图并复述三条要点。
