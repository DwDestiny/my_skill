# 项目叠加层：如何为一个项目补充规则

本文是通用说明。项目叠加层是一个可选文件，放项目自己的内容边界。它不改本 skill 的流程，只增加限制。

## 1. 何时建叠加层

1. 项目有自己的内容红线（例如禁止写某类话术、禁止替人承诺）。
2. 项目有自己的可信度口径或来源格式。
3. 项目有固定的产物目录或收尾动作。

没有这些要求时，不建叠加层。

## 2. 怎么建

1. 在项目里新建 `project-overlay.md`，放在本 skill 的 `references/` 下，或放在项目文档目录。
2. 在 `SKILL.md` 第 8 节写明路径。
3. 只写项目独有的规则。本 skill 已有的规则不重复。
4. 用户原话与叠加层冲突时，按用户原话做。

## 3. 建议结构与示例

示例使用中性占位符。换成你的项目内容。

```markdown
# 项目叠加层：<项目名>

适用范围：<项目根目录 <project-root>>。换项目时删除或改写。

## 1. 内容边界
1. 事实、判断、方案分开写，各自带标记。
2. 不写 <禁止的内容类型，例如沟通话术、报价>。
3. 不替 <角色> 承诺价格、范围、工期、合同。
4. 来源写检索日期与链接。可信度：高 = 官方原文；中 = 主流媒体转述；低 = 厂商宣传、自媒体。

## 2. 受众分析的限制
只记读者关心什么，不写怎么说、怎么推进。

## 3. 敏感信息
联系方式、凭据、合同、未脱敏数据不进任何产物。只记受控来源链接和证据编号。

## 4. 目录与收尾
1. 产物放 <project-root>/<子项目>/content-plan/。
2. 每次有效工作结束：更新文档版本与日期，追加工作日志。
```
