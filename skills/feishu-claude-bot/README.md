# feishu-claude-bot

> 版本 3.0.0 · 变更记录见 [`SKILL.md`](SKILL.md) 文末

**把你本机的 Claude Code 接进飞书和企业微信。同事在群里 @ 它、你在私聊里给它派活，它就用你机器上的代码仓、知识库和 IM 权限去办，再把结论回到原消息下面。**

## 解决什么问题

| 以前 | 用这个 skill |
|---|---|
| 同事问进度、问接口、报 bug，都得你本人回 | 机器人替你回：查代码、查提交、查文档，给结论 |
| 飞书和终端里的 Claude 是两个世界 | 飞书消息直接进本机 Claude Code，能读写本机文件、跑命令、用 lark-cli |
| 接机器人怕它乱说话 | 人设和边界先问清楚；身份、私密路径由钩子硬拦，不只靠提示词 |
| 无头会话每条消息都重写缓存，一句“在吗”要 $0.18 | 固定开场白 + 续接会话，新会话降到约 $0.02，并附一键验证 |

## 工作方式

1. 常驻进程 `bridge.py` 每个渠道一个接收线程：飞书用 `lark-cli event consume im.message.receive_v1`，企业微信用 `wecom_gateway.mjs`（官方 SDK 长连接，不需要公网地址）。群里只收 @ 机器人的消息，其余不触发。
2. 每个私聊、每个群（话题里的消息按话题）对应一个 `claude -p` 会话。新会话自动带上前文（话题全文，或最近 20 条），之后只补新增的。
3. 守则（人设 + 表达风格 + 边界）通过 `--append-system-prompt-file` 加进系统提示。PreToolUse 钩子按“谁发的、是不是主人私聊”限制 lark-cli 身份和可读路径。
4. Claude 的最终输出用机器人身份引用原消息回复，直接发在群里，不开话题（原消息在话题里才回在话题里）。要单独提醒某人时会 @ 出来。
5. 旁听（可选）：主人在群里发 `@机器人 /旁听`，这个群没 @ 的消息也会定时拉取、攒批交给 Claude，它觉得该接话（接梗、吐槽、提到主人或它自己）才接，默认不出声。不需要开“读取群内所有消息”权限，没开旁听的群收不到任何没 @ 的消息。
6. 长任务：大活儿不在聊天里干。Claude 先给计划，再派成后台任务，在独立工作树和 `bot/` 分支上跑（systemd 用户单元，bridge 重启不受影响）。同事派的先找主人批：群里就在群里 @ 主人，私聊就私聊主人。开工、进展、提问、结果都发回原会话，做完推分支、建草稿合并请求。`/任务` 看进度，`#N 内容` 补充要求。派活时可以写一条验证命令，服务自己复跑，不过就退回返工；主控按角色（产品、需求、开发、排查、评审、杂活）派活，同一项目同一角色接着上次的会话干；任务花到预估值会停下让主控决定加不加，订阅额度用得快会提醒主人但不拦活；卡住的任务会被停掉交回；主人自己的 GitHub 仓库可以放到 Claude 官方云端跑，不占服务器。

## 可选项

| 选项 | 取值 |
|---|---|
| 运行位置 | 服务器（systemd 用户服务）/ 本机 macOS（launchd） |
| 渠道 | 飞书 / 企业微信 / 两个都接（共用一套守则和缓存） |
| 飞书应用 | 复用已有 lark-cli 应用 / 新建 |
| 跨 IM 读取 | 两个都接时，会话能不能读另一个 IM 的聊天记录；默认关，打开要主人确认 |
| 人设 | `work` 工作分身：汇报进度、答疑、对接、记 bug；人物资料和私下评价不外露<br>`personal` 私人助理：只为主人服务，私事只对主人说 |
| 表达风格 | `veteran` 干练老同事 / `tsundere` 傲娇毒舌 / `warm` 温和专业 / `minimal` 极简冷静 |
| 旁听 | 默认没有群开启；主人在群里用 `/旁听` 逐个开关 |
| 长任务 | 默认开；同时跑几个、审批多久作废、心跳间隔、检查点估算、额度提醒、兄弟智能体续接、卡死判定、云端环境可调；角色模板在实例 `roles/` |
| 身份策略 | 主人能不能用自己的用户身份办事；同事触发时能不能用主人身份读聊天记录 |
| 私密资料 | 完全私密的目录；知识库里要自动排除的分区 |

## 前置条件

| 依赖 | 要求 |
|---|---|
| 系统 | Linux（推荐服务器）或 macOS |
| Claude Code | 已登录，`claude` 在 PATH 里 |
| lark-cli | 已安装（`npm i -g @larksuite/cli`），能 `config init` 和 `auth login` |
| Python | 3.8 或更高，只用标准库 |
| 飞书（接飞书时） | 企业自建应用，能开机器人能力并发布版本 |
| 企业微信（接企微时） | `wecom-cli`（`npm i -g @wecom/cli`）扫码授权；Node 18+ |

> **注意**：机器人长期使用这台机器的 Claude 登录态和额度。复杂任务一次约 $0.3–0.5。

## 安装

```bash
npx skills add DwDestiny/my_skill --skill feishu-claude-bot
```

然后对智能体说“把 Claude 接飞书”。它会先问运行位置、飞书应用、人设、表达风格和边界，再生成实例。

手动用法：

```bash
mkdir -p ~/work/my-bot
cp assets/templates/config.example.json ~/work/my-bot/config.json
bash scripts/ids.sh                       # 查 bot_open_id 和 owner_open_id，填进 config.json
python3 scripts/scaffold.py ~/work/my-bot # 生成实例并打印服务安装命令
cd ~/work/my-bot && python3 bridge.py --cache-check 3   # 验证缓存
```

## 已知限制

- 同事触发时允许用主人身份读聊天记录（机器人身份读不了群历史）。这意味着机器人能读到主人的其他私聊，不转述靠守则；在意的话把 `identity.others` 设为 `bot`。
- 本机运行时，电脑睡眠期间的消息收不到；醒来后超过 10 分钟的消息直接跳过。
- 同一个飞书应用的消息只推给一个接收方，不能和别的机器人服务共用应用。
- 同一个企微机器人同时只能有一条长连接；企微群里只收 @ 机器人的消息，没有旁听。
- 改守则后第一个新会话要重写一次缓存（约 $0.2）。
- 长任务只支持 git 仓库；机器重启后正在跑的任务标成“中断”，不自动重跑，回 `#N 继续` 接着干。
