# 长任务

> 版本 1.4.0 · 2026-11-21 · 维护：feishu-claude-bot

活儿比较大时（预计十几分钟以上、要改不少代码），聊天里的 Claude 不在当前会话里直接干，而是派成后台任务：在独立的工作树和分支上跑，开工、进展、提问、结果都发回派活的那个会话。体验参考了 OpenClaw、Devin、Cursor 后台代理和 Claude Code in Slack：派活前先给一句计划，过程中只在关键节点说话，有问题就在原会话里问，做完给分支和草稿合并请求。

## 1. 流程

1. 聊天里先把事聊清楚：目标、范围、仓库、验收标准。
2. Claude 在回复末尾写 `[派活]` 块（守则“长任务”一节规定格式）。bridge 拆出这个块，检查仓库，建任务。
3. 审批：
   - 主人派的：直接排队。
   - 同事在群里派的：bridge 在**同一个群**里 @ 主人，附任务书快照。主人在群里 @机器人 回 `批 N` 或 `不批 N`。
   - 同事私聊派的：bridge **私聊主人**（优先同一渠道）。主人私聊回 `批 N`，bridge 回原会话告诉同事。
   - 只认主人的发送人 ID。24 小时没人批自动作废（`tasks.approval_hours`）。
4. 开工：bridge 每 5 秒检查一次，有空位（`tasks.max_running`，与聊天并发分开）就用 `systemd-run --user` 起一个独立单元（macOS 用独立进程组）。bridge 重启不影响任务。
5. 运行中：Claude 用待办工具列计划；重要节点单独写一行 `[进展] …`，bridge 转发。飞书 30 分钟没动静会发一次心跳（`tasks.heartbeat_min`），企微不发。
6. 提问：Claude 写 `[提问] …` 并结束这一轮，任务变“等回复”。派活人或主人回 `@机器人 #N 意见`，同一个会话接着跑。
7. 完成：提交、推送 `bot/<N>-<月日>` 分支、建草稿合并请求，最后的总结发回原会话。主人私聊派的另附 `claude --resume` 接手命令。

## 2. 命令

| 命令 | 谁能用 | 作用 |
|---|---|---|
| `/任务` | 所有人 | 主人看全部，别人看本会话的 |
| `/任务 N` | 能看到的人 | 状态、计划、最近进展（主人另看花费） |
| `/任务 取消 N` | 主人、派活人 | 停掉，分支留着 |
| `/任务 清理 N` | 主人 | 删工作树，分支留着 |
| `批 N` / `不批 N` | 主人 | 审批 |
| `#N 内容` | 主人、派活人 | 运行中：通过 PostToolUse 钩子塞进当前会话；等回复/完成/失败/中断后：接着跑同一个会话 |

群里要 @ 机器人才收得到，bridge 先去掉开头的 @ 再匹配命令。

## 3. 权限

权限在建任务时按**派活人**定下来，之后不随补充指令的人变化。

| 层 | 主人派的 | 同事派的（主人批过） |
|---|---|---|
| 钩子环境 | `FCB_OWNER=1` | `FCB_OWNER=0`，私密路径照拦 |
| `git_guard.py` | 不能绕过 git 钩子；不能强推或删 main/master | 不能强推、删分支、推标签；gh 只能建草稿合并请求、看 PR/issue/CI、提 issue 和评论、只读 api |
| `hooks/git/pre-push` | 不限 | 只放行 `refs/heads/bot/*`（ref 层面拦，不靠命令字符串） |
| 规则（所有任务） | 不合并、不推主干、不发版 | 同左 |

`pre-push` 通过环境变量 `GIT_CONFIG_COUNT/KEY_0/VALUE_0` 把 `core.hooksPath` 指到实例的 `hooks/git/`，不改仓库配置；分发器做完检查后转给仓库原来的钩子。已实测 Claude Code 的 Bash 工具保留这组变量（它只追加 `KEY_1=credential.guiPrompt`）。

## 4. 存储

- `<实例>/state/tasks/<N>/`：`task.json` 状态，`events.jsonl` 要发回聊天的事件，`inbox.jsonl` 补充指令（`inbox.off` 记已交出的条数），`stream.log` Claude 原始输出。
- 工作树：`<tasks.root>/<服务名>/<N>`，默认 `~/work/.bot-tasks/`。从远端默认分支最新代码切出。
- bridge 记已发到第几条事件（`posted`），发完再记，重启后不丢不重。飞书每条用不同的幂等键。
- 单元没了但状态还是“进行中”：标成“中断”并通知，不自动重跑；回 `#N 继续` 接着干。

## 5. 订阅额度

任务用的是机器的 Claude 登录态（`claude -p` 计入订阅额度，见官方 “Use the Claude Agent SDK with your Claude plan”）。不设花费上限；`/任务 N` 给主人看累计花费。`max_running` 控制同时跑几个。
