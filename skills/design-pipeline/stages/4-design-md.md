# 阶段 4：design.md

design.md 是交给实现的唯一文件。它在阶段 2 和阶段 3 已经写了第 1、2 节。本阶段补第 3 节"执行规则"，再整体检查一遍。模板：`templates/design.md`。

## 1. 做法

1. 从第 1 节的配色、边角、透明度、字体决定写 3.1 令牌。每个颜色都有角色名，不出现没有角色的色值。
2. 从第 1 节的动效气质写 3.2 动效规则。入场种类列表，滚动驱动写清"什么属性随什么进度"。
3. 从 `library/carriers.json` 抄本页用到的载体数值到 3.3。
4. 写 3.4 实现建议。起手优先从 `examples/finished/` 复制工艺层（令牌结构、动效引擎与 Reduce Motion 分支、滚动同步、导出口、截图钩子）。形态、版式、配色、文案不复制。形态不同不是跳过复制的理由。开源库写名字与版本。3D 与生成资产写导出口与清单。
5. 把 3.5 看图清单留空，实现后填。

## 2. 检查（写完自查，不是门）

| 检查 | 怎么查 |
|---|---|
| 原话逐字在第 0 节 | 对照用户消息 |
| 第 2 节一屏一行，没有空行 | 数行数等于幕表屏数。阅读屏"Reduce Motion 后剩什么"与"图像"非空 |
| 签名时刻全页 1 处 | 第 1.4 节与第 2 节各出现 1 次 |
| 页面形态不是纯瀑布流 | 1.2 有形态 id 与幕表 |
| 每条选中案例有"本页怎么改" | 第 2 节该列非空，且用了点子里的名词 |
| 令牌齐全 | 3.1 每个变量有值。正文对比 ≥4.5:1 |
| 实现者不读其他文件也能做 | 把 design.md 单独给一个新会话，问它缺什么 |

## 3. 实现与看图

实现按 design.md 做。用开源组件库或自研都可以，皮肤全部走 3.1 的变量。做完后：

1. 每屏 1 张停靠点截图，首屏加 390 一张，Reduce Motion 一张。
2. 对照 3.5 看图清单逐项填结果。用 Read 看真实截图，不凭门禁结果判断。
   看图发现一屏的密度与填充率没到第 2 节写的值，或一屏下半是空白，这是修改项，不是报告项。先改再拍，再填清单。"留白偏大"不能出现在报告里。
3. 把截图与清单给 Fable 做视觉评审（用户 2026-10-12 全局规则）。
4. 收口后补库：库外自拟的做法入 1 条案例，新亲核的参照入 1 条。规则见 `stages/3-components.md`。
5. 可选工具：`toolbox/shots.py` 出截图清单，`toolbox/defaults-check.py` 查默认值 X1 到 X17。工艺细节见 `references/craft.md`。
