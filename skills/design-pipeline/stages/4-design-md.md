# 阶段 4：design.md

design.md 是交给实现的入口文件，第 0 节“交付包清单”列出它依赖的其他文件。它在阶段 2 和阶段 3 已经写了第 1、2 节。本阶段补第 3 节"执行规则"，再整体检查一遍。模板：`templates/design.md`。

## 1. 做法

1. 从第 1 节的配色、边角、透明度、字体决定写 3.1 令牌。每个颜色都有角色名，不出现没有角色的色值。
2. 从第 1 节的动效气质写 3.2 动效规则。入场种类列表，滚动驱动写清"什么属性随什么进度"。
3. 用 `node toolbox/lib.mjs carriers <id>` 抄本页用到的载体数值到 3.3。
4. 写 3.4 实现建议。起手优先从 `examples/finished/` 复制工艺层（令牌结构、动效引擎与 Reduce Motion 分支、滚动同步、导出口、截图钩子）。形态、版式、配色、文案不复制。形态不同不是跳过复制的理由。开源库写名字与版本。3D 与生成资产写导出口与清单。
5. 把 3.5 看图清单留空，实现后填。

## 2. 检查（写完自查，不是门）

| 检查 | 怎么查 |
|---|---|
| 原话逐字在第 0 节 | 对照用户消息 |
| 第 2 节一屏一行，没有空行 | 数行数等于幕表屏数。阅读屏"Reduce Motion 后剩什么"与"图像"非空 |
| 签名时刻全页 1 处 | 第 1.4 节与第 2 节各出现 1 次 |
| 页面形态不是纯瀑布流 | 1.2 有形态 id 与幕表 |
| 每条选中案例有"本页怎么改" | 第 2 节该列非空，且用了点子里的名词 |
| 令牌齐全 | 3.1 每个变量有值。正文对比 ≥4.5:1 |
| 交付包完整 | 清单里每个必需文件存在且非空 |
| 交付包自足 | 把 design.md 加清单里的文件交给空上下文会话，它不需要追问就能实现 |
| 拿走清单 | design.md 写出拿走的维度与接手者 |
| 重做一次 | 记录首版删掉的一个元素，附前后截图各一张 |
| 试样已做 | 第 1.4 节"试样"行有两张截图路径和一句对照 |
| 方向选过 | 第 1.1 节有研究、2 到 3 个方向、选择理由、落选代价与推翻条件 |

## 3. 实现与看图

实现按 design.md 做。用开源组件库或自研都可以，皮肤全部走 3.1 的变量。做完后：

1. 每屏 1 张停靠点截图，390 宽也每屏 1 张（手机端的缩放、断行、标签字号只有逐屏看才看得到），Reduce Motion 一张。边角截图：页脚、导航展开态、404、加载各 1 张。
2. 对照 3.5 看图清单逐项填结果。用 Read 看真实截图，不凭门禁结果判断。
   看图发现一屏的密度与填充率没到第 2 节写的值，或一屏下半是空白，这是修改项，不是报告项。先改再拍，再填清单。默认值与适用条件见 `references/restraint.md` 第 7 节，不适用的页在 design.md 写原因。"留白偏大"不能出现在报告里。
3. 看图找最差三处：按 `references/critique-method.md` 的七种看法看全套截图，对照第 0 节原话和蓝图的体验目标，写出最影响用户目标的三处（位置、现象、原因、改法）。方向问题（太素、盖住主物就没有氛围、中后段像说明页、和锚点差一档、颜色与字形组合不对、主物靠说明成立）先处理：回阶段 2 或 3 改 design.md 再实现。原因：方向不对时修细节，只会把弱方向做得更完整。报告按方向、贯穿、局部实现、用户评价四种状态分开写（`critique-method.md` 第 2.1 节），技术修复可以单独关闭，方向状态只由看图和用户评价改变。
4. 把截图与清单交给评审者。首选第二个独立 agent 看截图。评审先现场看 2 到 3 个获奖锚点，再和成品、和冠军盲比，五个维度各给档位（`references/judging.md`）。之后进整页循环：每轮只改最差的一处，挑战者赢了才替换冠军，按跳出条件停（`references/iteration-loop.md`）。技术检查只跑一遍，不进循环。宿主有 Fable 且用户要求时才用 Fable。在 design.md 记录实际评审者与未覆盖项。
5. 收口后补库：库外自拟的做法入 1 条案例，新亲核的参照入 1 条。规则见 `stages/3-components.md`。
6. 可选工具：`toolbox/shots.py` 出截图清单，`toolbox/defaults-check.py` 查能 grep 的默认值（X18 到 X20 靠看截图）。`floor-check.py` 的范围见 `references/craft.md` 第 8 节表格。工艺细节见 `references/craft.md`。
