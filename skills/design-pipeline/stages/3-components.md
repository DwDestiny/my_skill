# 阶段 3 组件创意

> 何时读：阶段 2 的氛围已写进 `design.md` 第 1 节之后。
> 读完做什么：为每一屏选一条最好的组件表达，写进 `design.md` 第 2 节。
> 选案例前读 `references/why-good.md` 第 4、5 节。想看有哪些手法可选，查 `references/technique-catalog.md`（手法目录与技术栈地图）。
> 产物：`design.md` 第 2 节"每屏做法"。
> 来自：旧 `references/component-patterns.md`、`prompts/S4-page-plan.md`、`references/page-plan.md`。

本阶段回答"每个组件、每个目的，用哪种最好的视觉或交互表达"。表达来自案例库 `library/cases.json`，也可以库外自拟。整体氛围由阶段 2 定，本阶段的选择要放得进那个氛围。

## 1. 每屏的做法

1. 读 `design.md` 第 1 节的幕表。按幕列屏。屏指一个视口高度内的主要区块，或幕表里的一个相机位。
2. 每屏先写目的：一个动词短语，例如"让人知道可以横滑""把八步压成一眼"。
3. 触感预算：全页指定唯一有材质和形变的元素种类（例：只有按钮）。其余元素只做状态变化。原因：每种元素都有材质时，页面没有重点。
4. 运行发牌命令：

```
node toolbox/deal.mjs --slot <槽> --purpose "<目的>" --carrier <id>
```

5. 发牌先按槽与目的筛，再从命中的案例里发 3 张。命中少于 3 张就全给。 输出约 45 行，读全，不用 `head -n 30` 截断。卡上若有 `depends_on`，先核对本页是否满足该内容条件。
6. 动效气质不过滤。卡上显示 `atmosphere_fit`，只供对照氛围。
7. 选 1 条，或写"库外自拟"加一句做法。
8. 写"本页怎么改"：回答案例的 `adapt` 提问。用本页点子里的名词替换案例里的通用词。
9. 写"Reduce Motion 后剩什么"：去掉动效后这一屏还有什么。
10. 全部屏写完后补写使用史：

```
node toolbox/deal.mjs --set-components --project <项目名> --components <槽:id,…>
```

不运行第 10 项，下一个项目的发牌不会避开这些案例。

槽取值：nav、hero、cards、rows、steps、panel、overlay、footer、gallery、pricing、testimonial、form、cursor、loader、transition、page。

## 2. design.md 第 2 节的表

一屏一行。没有一屏没写。没有空行。

| 列 | 写什么 |
|---|---|
| 屏 | 屏名与对应幕 / 章 |
| 舞台 / 阅读 | 二选一 |
| 目的 | 动词短语 |
| 案例 | 案例 id，或"库外自拟：一句做法" |
| 本页怎么改 | 一句。有案例 id 而此列空，等于直接套模板，重做 |
| Reduce Motion 后剩什么 | 一句 |
| 图像 | `ASSETS.md` 行号，或"无" |
| 内容块 ID | 蓝图里的内容块编号 |
| 密度与填充率 | 本屏字数上限与标记数上限。阅读屏加填充率（第 3 节） |

> **注意**：表里不写色值、字体名、字重。皮肤一律取 `design.md` 第 1 节的变量。

## 3. 阅读屏要有内容

舞台屏靠舞台撑满。阅读屏靠图形或排版撑满。下面两条是计算，写在表的"密度"列旁。两条都是默认值，偏离时在 `design.md` 写理由。适用：展示型。不适用：操作型原型、成功/确认状态、需要重复结构做比较的页、短内容阅读页。

1. 填充率：内容高度除以停靠视口高度。默认不低于 60%。低于 60% 的屏，指定主角图形并编入资产清单，或改停靠方式。不要把空白留给实现。
2. 连续空白：停靠视口内任一段无内容的连续高度默认 ≤120 px，或 ≤15% 视口高。材质（横格线、板底、纸面）要承载文字或图形才算内容。

教训：登记页有 7 条空横格线，成功态小票下有 250 px 空灰底。填充率分别是 100% 和 71%，但评审都判"半页空纸"。

3 到 5 条短事实的形式见 why-good 5.1。

## 4. 相邻与重复

下表前三行和最后一行是默认值。偏离时在 `design.md` 写理由。适用：展示型。不适用：操作型原型、成功/确认状态、需要重复结构做比较的页、短内容阅读页。

| 规则 | 默认值 |
|---|---|
| 相邻两屏的版式家族 | 默认不同 |
| 同一版式家族全页 | 默认 ≤3 次 |
| 同一案例全页 | 默认 ≤2 次 |
| 舞台屏里的阅读区 | 不放舞台动效 |
| hero、每章开场、签名时刻、页脚、导航展开态、加载、404、空状态 | 默认各至少 1 项材质或动效表达，写出它引用的氛围原词。不适用的状态写"不适用"加一句原因 |

每个断点画一张 ASCII 线框，宽度 ≤72 字符。标出舞台区、阅读区、签名时刻。载体是小程序或 App 时，用 `01-载体.md` 的壳尺寸。

## 5. 反同质化三条

| 条 | 做法 |
|---|---|
| 发牌不翻库 | 不通读案例库挑案例。按槽与目的发牌 |
| 案例不带皮肤 | 案例只给结构与机制。色、字体、圆角取 `design.md` 变量 |
| 本页怎么改 | 每条案例都写，回答它的 `adapt` 提问 |

另有 X17：同一页面 3 条以上案例来自同一参照站点，即撞车。换案例。X1 到 X20 全文见 `references/anti-sameness.md`。案例里的数值是起点。它与载体最小字号或 `references/restraint.md` 的限制冲突时，以后者为准，并在"本页怎么改"写压到的值。

## 6. 补库规则

案例库要不断扩充。每个项目收口后补库。

1. 库外自拟的做法入库 1 条。新亲核的参照入库 1 条。
2. 入库前查重。同 `slot`、同 `mechanism`、同 `why`，视为重复。
3. 缺 `why` 或 `reduce_motion` 不入库。
4. `how_checked` 为二手摘要的案例，不得作为一屏的唯一参照。
5. 每 10 个项目清一次：`used_in` 为空且二手摘要的案例，移到 `library/cases.md` 的附录表。不删。

> **警告**：打开外部站点用 `agent-browser` 看行为（用户 2026-10-17 批准，不必逐次问）。只记录看到的行为。不截图存档，不下载素材，不存代码。网图取用另外先问。`how_checked` 只在亲眼看到该行为时写"亲核打开"。

首批来源按序：本库已做出的页面和机制示例，再从 `design-taste-frontend` 的 `library/sections.json` 翻译挑选，最后搜索加亲核。载体是字段，不是维度。不按格子凑数。

## 7. 案例字段

缺一个必填项，不入库。

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | `<slot>-<nn>` |
| `slot`、`purpose` | 是 | `purpose` 是动词短语，1 句 |
| `name`、`why` | 是 | `why` 一句，写体验原理或机制，按"触发 → 变化 → 终态"写，不写外观形容词 |
| `seen_at` | 是 | 数组 `{site, url, year, verified, how_checked}`。`how_checked` 取值：亲核打开、本库已做出、二手摘要 |
| `atmosphere_fit` | 是 | 数组。动效气质（静、呼吸、驱动、沉浸）加材质词（纸、钢、玻璃、织物、屏幕、颗粒）。是提示，不是过滤 |
| `carriers` | 是 | desktop-web、mobile-web、wechat-mini、ios、android、print |
| `adapt` | 是 | 2 到 3 个提问，强制改写。例："卡里的'物件'在本页是什么名词？" |
| `reduce_motion` | 是 | 去掉动效后还剩什么，1 句 |
| `risks` | 是 | 1 句：可读性、性能、浮夸哪一类，什么条件下发生 |
| `avoids` | 是 | X 编号数组，可空 |
| `added`、`used_in` | 是 | 入库日期 `YYYY-MM-DD`。`used_in` 是项目数组，可空 |
| `structure` | 否 | 数值起点，全是数字 |
| `mechanism` | 否 | CSS 或 JS 机制名 |
| `impl` | 否 | `examples/mechanisms/<id>` 或 `开源库@版本` |
| `tasteskill_id` | 否 | 指向 `design-taste-frontend` 的 id。不复制其内容 |
| `depends_on` | 否 | 这条手法依赖的内容条件：高质量作品图、作者名气、真实产品界面、无。可选，不进必填校验，发牌时应显示。原因：离开素材或名气，这类手法会失效 |

禁止：色值、字体名、字重数值进入 `why`、`structure`、`adapt`。`why` 出现"高级""精致""优雅"一类形容词，重写。

动效气质的定义见 `references/restraint.md`。
