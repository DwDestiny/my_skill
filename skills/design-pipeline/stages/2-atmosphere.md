# 阶段 2 视觉氛围

本阶段决定这页的整体风格：点子、页面形态、材质、光、空间、配色、边角、透明度、动效气质和签名时刻。产物是 `design.md` 第 1 节"氛围"（模板 `templates/design.md`）。

用户原话（2026-10-17）："整体风格，包括但不限于配色、边角、透明度等等这些，其实这个环节定的是视觉氛围"。

## 2. 做法

### 2.1 主题盘点（先于库）

先写一句身份："这是 ___ 的页面，读者看完应该记住 ___ 的什么性格。"页面里的演示任务、客户场景、设备是例子，单独写一行，不当题材盘点。原因：拿例子当题材，整页会变成例子那个行业的说明页（`references/direction-and-appeal.md` 第 1 节）。

点子先于库：2.1 的盘点和 2.1.1 的研究写完之前，不发组件牌、不翻案例库（`cases.json`、`expressions.json`）。原因：先看库，氛围就来自库的统计平均。主题目录、同页型标杆和获奖锚点是研究材料，不是库，从 2.1.1 起按步查。外部参照和真实素材要在写方向之前看（2.1.1、2.1.2），原因是第一联想不经研究就写成方向，后面每一步都会给它补理由。

列 8 到 12 件只属于这个身份的东西，每件一行具体名词。按下面 8 类提问，每类至少答 1 件。

| 类 | 提问 |
|---|---|
| 名字 | 这个领域有哪些专有名词、器物名、行话？ |
| 地点 | 事情发生在哪里？那里的光、墙、地面是什么样？ |
| 材料 | 从业者每天手里摸的是什么材料？ |
| 数字 | 有哪些只属于这个题材的数字、单位、刻度？ |
| 约束 | 有什么硬约束（法规、生理极限、时间窗）？ |
| 仪式 | 有哪些固定流程、交接、签字、检查动作？ |
| 印刷物 | 有哪些表单、标签、证书、图谱、说明书？ |
| 工具 | 从业者用什么仪器、软件界面、量具？ |

### 2.1.1 题材研究与同页型标杆

写方向之前做两件事。做法与例子见 `references/direction-and-appeal.md` 第 2.1 节。

1. **题材研究**：查清这个身份在真实世界里是什么：它的来历、典型现场、交付的东西、行话、公开的标志性事实（带来源）。主题盘点（2.1）是从记忆里列名词，题材研究是去查。原因：团队页第四次没有人查过 FDE 这个职业本身，蓝图里的定义（"贴近实际问题、同时推进判断与实现的团队角色"）任何咨询团队都能用，身份是空的，视觉只能往"通用好看"上走。
2. **同页型标杆**：找 2 到 3 个和本页同一页型的高水准页面（团队页就看团队页、招聘页、工作室 People 页；发布页就看发布页），从首屏一直翻到页尾。写下它的首屏靠什么让人停住，中段怎么延续首屏的世界。原因：团队页第四次看的参照都只看了首屏静帧，成品也是首屏有东西、中段塌成文档。

### 2.1.2 带问题看参照

再写 2 到 3 个会影响设计的问题（这类身份留下什么真实工作痕迹；什么视觉语汇能传达身份句里的性格；哪些现成联想会误导），带着问题看 3 到 5 个参照或真实素材。每个参照写它在内容与身份、色彩面积与明度、中文字形与排版、主物与动作上看到了什么，再写一句"它让我想做什么"。颜色、中文字形和氛围（光、色场、环境）要有参照覆盖。只写"不复制、不再、避免"的研究是在躲上一轮的批评，不是在找吸引力。

为什么：颜色和显示字是读者最先看到的两件事。团队页第三次的配色和中文字形在看参照之前就写定了，参照只提供了通用手法，最终用户否定的正是"配色和大字"。

记录写进 `design.md` 第 1.1 节"研究"行，写短：每个参照 3 到 5 行。时间留给方向板。参照的站名、年份写进 2.9。

### 2.1.3 主题打分：选出 3 个主题

好页面靠什么吸引人，有很多种答案：一段电影感视频、一个可以转的 3D 物件、跟着鼠标流动的流体、占满屏幕的大字、一个能玩的小装置、一张会动的数据图。`library/themes.json` 收了这些整体主题，每个主题配了获奖案例。先给主题打分，再写方向。

原因：不打分时，模型会落到最顺手的一种。团队页第六次（Grok 实测，2026-10-21）三个方向板全是生成照片，成品是"满屏照片加压字"，氛围到了 4 档，但交互只剩滚动，用户担心"每次做网站都搞这种放个图片背景的设计方式"。满屏摄影只是目录里的一种主题。

0. 先读 `library/case-map.md`：用题材自己的世界（地方、光、谁在干什么）找簇，簇里挑 2 到 3 条案例，每条先 `toolbox/record-motion.py` 录动和跟手，按它的第 2 节写换题六行，过第 3 节不雷同三问。主题库是手法库，在簇定了之后才查。
1. 运行 `node toolbox/lib.mjs themes`，简表给每个主题的 `one_liner`、`feasibility_here`、`content_signals`。入围的 5 到 6 个再 `lib.mjs themes <id>` 看 `not_fit`、`cases`、`signature_interaction`、`mediocre_version`。
2. 每个主题按 5 项各打 1 到 5 分，写一句依据：

| 项 | 问什么 | 依据从哪里来 |
|---|---|---|
| 内容匹配 | 蓝图里有没有这个主题需要的东西？视频主题要有可拍的现场，数据主题要有真数字，交互玩具要有一个能让读者动手的动作 | 蓝图的章节、`image_needs`、2.1 主题盘点 |
| 身份表达 | 2.1 盘点出的东西，能不能成为这个主题的主物？ | 2.1、2.1.1 |
| 第一眼潜力 | 打开这个主题最好的 1 到 2 个案例，这次能做到它的几成？按 `judging.md` 档位估 | `cases` 字段 |
| 本机可做 | 素材和技术在本机做得出吗？做不出时有没有替代做法 | `feasibility_here` |
| 新鲜度 | 最近 5 次用过的主题记 2 分以下 | `history/history.json` |

3. 按总分排序。选前 3 个**不同主题**，每个主题做一个方向（2.2）。前 3 名里有两个同类（例如两个都靠照片）时，换下一名。
4. 用户点名了手法（例如"要 3D 流体"）时，那个主题直接进前 3，其余 2 个照常打分。
5. 写进 `design.md` 第 1.1 节"主题打分"行：全部主题的总分表，加前 3 名的分项和依据。

打分只用来挑出值得做方向板的主题，不代替盲评。最终选哪个方向，仍由方向板和锚点并排比较决定（2.2.1）。

### 2.2 点子与 2 到 3 个方向

2.1.3 选出的 3 个主题各写一个方向：每个方向一句点子、一句世界观（"这页像 ___"），并在光、颜色归谁、文字的声音、图像语法、构图 5 根轴上各写一个值。至少两根轴（光、颜色归谁、图像语法里）不同才算不同方向，并且至少一个方向的图像语法和第一联想完全不同（例：第一联想是抽象 3D 物件，另一个方向就做真人与现场纪实，或高密度的日志与名册）。同一个造型换颜色、换字体是变体，不算新方向；同一个故事换容器也不算。做法与例子见 `references/direction-and-appeal.md` 第 2 节。原因：第一个联想最常见，只写一个点子时，后面每一步都会给它补理由。

每句点子都要具体到这个身份：把身份换成一个相邻的身份（同行的普通公司），这句话应不成立。这是对点子的要求。到了成品层，身份是深化项，不是淘汰理由（`references/judging.md` 第 5 节）：盲评时第一眼成立但身份弱，就在同一个世界里加身份元素，不换方向。

| 成立 | 不成立 |
|---|---|
| "页面像一张足底压力图谱：数据从冷色走到热色，章节按压力区排列" | "简洁现代的科技感页面" |
| "每章开场是一块正在打磨的鞋垫材料，滚动推进打磨工序" | "用 3D 和动效提升高级感" |

来源检查：写出点子借的一个来源（物件、出版物、工具或语气）。再列它在至少 3 类元素上的落点（字体、编号、边线、页脚）。例：Lynn Fisher 的站借"书"，落到罗马数字、点线目录、版本号、纸纹。原因：只有一处借用的点子会散，多处落点才让页面像一个整体。

### 2.2.1 方向板与选方向

先用生图做方向板，再写代码。原因：生图几十秒一张，画面上限比手写 HTML 小样高得多，能在写代码之前看到这个方向的光、色场和主物到底成不成立。r5 全程最好的一版（首批 A），恰好是一张生成的现场图撑起来的。

1. **每个方向生成 1 张首屏方向板**（`image-gen` skill 或宿主的生图工具，1536x1024）。需要看中段时再加 1 张。方向板画的是这个主题的首屏，不只是一张氛围图：3D 主题画渲染出的物件和舞台，大字主题画字本身占满屏的版式，交互玩具画读者正在动手的那一刻，视频主题画视频里最有力的一帧并写一句它怎么动。提示词写：
   - 主题名、世界观一句、光、色场、主物、构图。主物和环境用 2.1 盘点出的具体名词（器物、地点、材料）至少 2 个，不用抽象的行业词。原因：名词越具体，画面越不漂移；抽象词会被画成字面意思或相邻行业的现场；
   - 签名交互一句（`themes.json` 的 `signature_interaction`）：读者做什么，画面怎么变；
   - 标题放在哪个区域、大约多大（"large headline area on the left third"）；
   - 借哪个高分锚点的做法，用文字描述做法，不写站名，不让模型复制别人的画面（`node toolbox/lib.mjs anchors <id>` 的 `transferable`）；
   - 结尾写 "award-winning website hero, real browser screenshot, 16:10"。
   中文标题可以让模型试着画，但不依赖它画对。方向板看的是氛围和构图，不是界面规格。
2. **盲评选出第一个冠军**：按 `references/judging.md` 第 3、4 节，先现场看 2 到 3 个高分锚点（同一任务只开一次，截图留临时目录，后面每轮复用），再让独立评审把方向板和锚点并排比较。回答四个问题：第一眼停在哪里；和锚点差几档、差在哪个维度；遮住说明，画面自己讲了什么；盖住主物还剩什么世界。
3. **进入方向循环**（`references/iteration-loop.md` 第 4.1 节）：每一轮按 `judging.md` 第 5 节决定深化还是换方向，生成挑战者，盲比冠军。最多 3 轮。要问用户而用户不在线时，写 `process/ASK.md` 并停在当前冠军（`iteration-loop.md` 第 3 节）。
4. **拆成可实现的三层**，写进 `design.md` 第 1.1 节"方向板"行：
   - 图像层：按主题写清主画面怎么做出来。3D 主题用 three.js 或 Blender，大字主题用网页字体和 CSS，流体用着色器，数据主题用 `dataviz`。生成图是图像层的一种来源：摄影、插画类主题可以用同一提示词生成**无文字版本**作资产；其他主题只把方向板当画面目标，不把它铺成背景；
   - 界面层：标题、导航、按钮、正文，用 HTML 重建；
   - 效果层：光晕、景深、粒子、扭曲。写清每一项用 CSS、SVG 还是 WebGL 实现。做不出来的现在就删，不留到实现时才发现。
5. **落地对照**：首屏 HTML 做出来以后，和方向板并排盲比。HTML 明显输（低一档以上）时，先补到不输，再铺整页。原因：方向板和 HTML 之间的落差，是"看着方向很好、做出来很平"的主要来源。

看方向板时，颜色和中文字形当成一组看：这组颜色配这种材料和字重产生什么气质，标题和主物是不是在抢同一种重量。3D 主物按渲染截图看颜色，不按令牌值看（`references/direction-and-appeal.md` 第 3.1 节）。

选定后写四件事：理由；其余输在哪、放弃了什么；不同意见和处理；什么观察会推翻这个选择。写下选择之前，不给任何一个方向搭整页脚手架。

后面 2.3 到 2.10 只为选中的方向写。

### 2.3 情绪词

选 3 个能排除选项的词，每个配一个可观察量。可用：可信、克制、有温度、精确、手作感、临床、安静、粗粝、透气、庄重。不可用：现代、高端、大气、简约、时尚、酷炫、专业、有质感、高级感。例："精确：所有数字带单位，刻度线 1 px，对齐到 4 px 网格"。

### 2.4 页面形态与幕表

先选形态，再排章节。纯瀑布流不可选：章节等宽堆叠、每章"标题加文字加图"、滚动只做位移。用户原话（2026-10-16）："我现在非常讨厌平庸的纯瀑布流的形式"。

1. 运行 `node toolbox/pick-form.mjs --task <explainer|launch|prototype|datastory> --chapters <n> --reading <skim|sequential> --carrier <id>`，或 `node toolbox/lib.mjs forms` 看简表、`lib.mjs forms <id>` 看一种（字段 `one_liner unit advance nav fit carriers acts_template vs_pure_waterfall reduce_motion`）。
2. 选 1 种形态，写一句它表达点子的哪一点。
3. 写幕表：幕号、对应章、相机或舞台状态、视觉主体、停留方式（滚动经过、pin、点击、拖拽）。蓝图每个舞台章对应一幕。
4. 写 390 宽下的形态变化与目录方式。章数超过 8 时，目录不用整行换行的锚点列表。
5. 写 Reduce Motion 与无 JS 退路。退路保留章节分区与导航，不退回纯瀑布流。

### 2.5 表现形式与使用史

1. 按幕表每幕选表现形式：`node toolbox/lib.mjs expressions --where layer=<stage|material|type|interaction>` 看简表，候选再 `lib.mjs expressions <id>` 看全文（字段 `layer expresses fits avoid cost reduced_motion libs example`）。默认一页 1 个 `stage`、1 到 2 个 `material`、1 个 `type`、1 到 2 个 `interaction`。偏离时在 `design.md` 写理由。适用：展示型。不适用：操作型原型、成功/确认状态、需要重复结构做比较的页、短内容阅读页。`example` 指向 `examples/mechanisms/<id>/`。
2. 定稿后运行 `node toolbox/deal.mjs --record --project <名> --carrier <id> --theme <2.1.3 选中的主题 id> --form <形态 id> [--palette <id>]`，写入使用史。下一个项目的 2.1.3 新鲜度和 2.8 禁用清单读它。
3. 整页方向卡（`library/directions.json`）不再发：方向由 2.1.3 主题打分和 2.2.1 方向板决定（2026-10-21）。用户已指定方向时，2.1.3 与 2.2.1 写"跳过：用户指定"，仍做 2.3 以后各步。

炫技是默认。3D 场景、GLSL 流体、滚动驱动相机、WebGL、glTF 模型与 Blender 建模是常规选项，不是高风险选项。用户原话："3D流体、滚动视察、webgl建模、blender建模都不成问题"。放在哪里、放多大，看 `references/restraint.md`。

### 2.6 表面决定

先写世界观与氛围三层：一句"这页像 ___"；从氛围 8 层里选 3 层下重手，各写一句具体做法；光、色场、环境各写一句（底是平涂还是有光、有色、有材质）。做法见 `references/atmosphere-and-impact.md` 第 1 到 3 节。原话有"炫酷、惊艳、有冲击力"时，再写这一页在第 4 节 6 种做法里强在哪 2 种。下面的数值表是在这个基础上的取值，不代替它。

材质先从 2.1"材料"行取。下表是起点，不是全集。
材质、光、空间、图像各选 1 项（材质可选 2 项）。同源优先于数量。光：平光、单侧光、辉光、投影、无。空间：平面、2.5D 视差、等轴测（`anatomy` skill）、3D 场景、固定舞台、图片序列。图像：真实照片（用户提供，取网图先问）、插画或生成图（只经 `image-gen`，标"生成示意"）、SVG 图示、CSS 或着色器纹理、数据图形（`dataviz`）。

边角、透明度、模糊、材质用下表的数值起点。默认一页边角最多 2 个值加全圆，偏离时在 `design.md` 写理由。适用：展示型。不适用：操作型原型、需要重复结构做比较的页。外层边角 ≥ 内层，内层 = 外层 − 内边距。

必答问题"颜色归谁？"三选一，写一句理由。读阶段 1 的"素材盘点"再答。

| 选项 | 含义 |
|---|---|
| 内容 | 颜色来自作品、图像或产品界面。框架不另加彩色，但仍有光和色场：用内容的主色做环境色、深浅明暗做节奏，不退成平涂灰 |
| 框架 | 颜色来自页面自己的配色，内容服从它 |
| 逐项借给内容 | 框架留中性，每个内容项借一个自己的颜色 |

原因：内容自带彩色时，框架再加一种彩色会抢内容。但"不加彩色"不等于"没有氛围"。团队页第四次选了"归内容"，框架做成平涂的浅灰绿，盖住主物以后页面就没有氛围了。色场、光与环境的做法见 `references/atmosphere-and-impact.md` 第 2、3 节。

配色写成角色表：底、面、正文、强调、状态。先从 `library/palettes.json`（字段 `fits taboo rule contrast_notes`）选 1 类，用情绪词反查，写一句理由。然后产出灰阶 8 到 10 个值（最深用有色深灰，不用纯黑）、主色 5 个值以上、状态色 4 个（成功、警告、错误、信息）。强调色只表示语义或结构，不作装饰。浅色与深色主题各算一次对比：正文 4.5:1，大字 3:1。具体令牌写进 `design.md` 第 3 节。对比度合格只说明能读，不说明好看。配色的气质按 2.2.1 的方向板和对照判断。

拿走：写出整体拿走的 1 个维度（例：衬线、圆角、装饰线、动效）和它的接手者（哪个元素承担这个维度的表达）。拿走只作用于框架层，不拿走签名时刻与舞台，也不拿走氛围（光、色场、环境）。原因：整体少一个维度，剩下的才显出来；氛围被拿走，剩下的只有文档。

动效气质选 1 种：静、呼吸、驱动、沉浸。定义（什么在动、何时动、占屏多少）和浮夸判定表见 `references/restraint.md` 第 3、4 节。气质是氛围决定，也是案例 `atmosphere_fit` 的提示值，不过滤发牌。四种都有 Reduce Motion 退路，退路等于静。

### 2.7 签名时刻

全页 1 处。写它在哪一幕、什么动作、持续多久、表达点子的哪一点。

| 形态 | 做法 | 适合 |
|---|---|---|
| 变形 | 一个物体随滚动从状态 A 变到状态 B | 工序、前后对比 |
| 揭示 | 遮罩或切面打开，露出内部结构 | 机制、拆解 |
| 驱动 | 一个控件驱动全部图示同步变化 | 参数、模拟 |
| 汇聚 | 散落元素聚成一个图形或数字 | 结论、规模 |
| 穿越 | 镜头穿过一个空间进入下一章 | 叙事、地点 |
| 落定 | 大字或实物以物理感落到最终位置 | 发布、宣言 |
| 签名字 | 全页只出现一次的字体或巨字（例：Pentagram 页脚衬线大字） | 品牌、宣言、静 |

加"签名字"的原因：前 6 个形态都是动作，缺静态签名。

## 3. 先做首屏与最安静的一章

为什么：氛围最先在首屏和最安静的一章露馅。铺完全页再发现氛围不对，返工最贵。2.2.1 的方向板回答"选哪个方向"，这一步回答"选中的方向能不能撑满整页"。

怎么做：

1. 从 `examples/finished/` 复制一套起手，按第 1 节换令牌、材质、字体。工艺清单见 `references/craft.md`。
2. 只做首屏与蓝图里最安静的一章（取它真实的 3 行内容）。接入选定的舞台、材质与动效气质，写 Reduce Motion 分支。
   如果签名手法是揭示（探照灯、擦除、滚动显影、悬停翻面），试样里要带上被揭示的内容。读者做了动作，就要得到动作前看不到的信息：一处标注、一句数据、一个变化的计数。两层图画的是同一样东西，揭示只是换了颜色，读者照完会觉得"光下啥也没有"。做法：在蓝图的断言里取 3 到 5 条，钉到画面的具体物件上，只在光照到时浮出；暗处压到只剩轮廓，让光和暗的差别一眼可见；截图时把光放在一个断点上截。
   例（2026-10-23，FDE 宣讲首屏）：第一版白模层和现场层都是同一间办公室，光照过去只是上色，用户评价"光下边啥也没有"。第二版暗处亮度从 0.42 降到 0.2，光照到工位、打印机、机房、会议室、档案柜时浮出五条说明牌（如"AI 生成的报表，打印出来再人工核对一遍"），右上角计数"已看见 n / 5"。
   用户点名过参考作品时，先写出它让用户记住的两三个特征，逐个落进试样，再换题材。例（同日第三版）：用户要的是 Immersive Garden 那种"下方是浮雕，光束边界像水墨一样晕染的动态"。前两版换成了白模沙盘、用 CSS 径向渐变做硬光圈，两个特征都丢了。第三版底层换成浅浮雕，光边用 WebGL 墨迹平流（`examples/mechanisms/fluid-ink-pointer`）加 fbm 噪声扰动阈值，边缘不规则、缓慢洇开，走过处留下渐褪的痕迹。
   底图的质感来自元素少、尺度大、留白多，不来自内容多。例（同日第四版）：第三版浮雕刻了一整间办公室，用户评价"内容太多太杂，图片本身的质感不够"。第四版只留一人、一桌、一屏、一摞纸、一根悬空网线、三只档案箱，用大理石和单侧掠射光，四样东西各是一处断点。着色器压暗浮雕时保留它自己的明暗（亮度取幂后线性混入底色），只整体去饱和会把大理石压成平灰。
   成对图层的生成顺序：先生成细节最多的一层（真实照片），再以它为参考图生成简化层（浮雕、白模、线稿）。反过来做，照片会自己补细节（台灯、笔筒、衣领、发型），两层对不上，揭示时出现重影。例（同日第五版）：第四版先刻浮雕再重绘照片，用户指出"图片和浮雕不一样"。改为以照片为参考出浮雕，提示词写"像素对齐、描出人物轮廓、不增删移动任何物件"，一次生成 2 到 3 张。用浏览器把两层以 `mix-blend-mode:difference` 叠在一起截图，人物、物件边缘几乎抵消的那张才用。
3. 截 1440 与 390 两张图，与锚点并排看。看法见 `references/critique-method.md` 第 1 节：眯眼看主次，和锚点并排看水准，找最平的一处。
4. 写一句"这里像、这里不像"。首屏与安静章要像同一页，不像一张海报加一份文档。安静章平时，常见原因是只有首屏用了选中方向的光、材料和颜色归属，安静章退回了说明页排版。
5. 不像时改第 1 节，不为好看在页面上偷改决定。
   试样回答"选中的方向能不能撑满整页"，不回答"这个方向值不值得选"。贯穿会让强方向更强，也会让弱方向的弱点铺满全页。试样上发现方向本身的问题（标题和主物抢重量、颜色在大面积上气质不对、画面靠说明成立）时，回 2.2.1 重选，不在安静章上补救。
6. 两张截图的路径和那句"这里像、这里不像"写进 `design.md` 第 1.4 节"试样"行，后面的实现者和评审者靠它知道方向已经在真实画面上验证过。

这是自己看截图，不是打分。看图清单与独立视觉评审在实现后照常做（评审者规则见阶段 4）。

## 4. 检查（自查，不是门）

| 检查 | 怎么看 |
|---|---|
| 研究在方向之前 | 第 1.1 节有题材研究（带来源）、同页型标杆（看到页尾）、参照看到的东西和"它让我想做什么" |

| 方向发散过 | 第 1.1 节有 2 到 3 个方向、各自的方向板、盲评结果和选择理由 |

| 点子属于这个身份 | 换成一个相邻身份读一遍 |

| 禁用 5 条，有历史时 ≥2 条引上一项目 | 对照使用史。使用史为空或只有示例记录时写"首次使用，不适用跨项目比较" |
