# 改版路线：已有产品按一个设计源统一

> 何时读：用户要求"按首页（或某页）风格统一其他页面""全站视觉升级""这几页重新设计，功能不变"。产品已经在运行，有代码、有组件库、有一页被确认过的设计。
> 和四阶段的区别：四阶段从一句委托做一个新页面，要找点子、选方向。改版的方向已经由设计源定了，工作重点是**把设计源的语言准确地延伸到每一页、每个状态**，并把每页的信息组织做好。
> 读：`references/product-ui.md`（工艺做法），`references/critique-method.md`（看图），`references/asset-generation.md` 第 7 节（图标、logo、头像、插图）。

## 1. 先执行原话

用户说"按首页风格统一"，就直接统一底色、字体、按钮、动效，不先留着旧值等用户确认。实测中执行者把冷色底保留了三轮去等确认，用户第四轮才指出"灰黄白色调很明显跟首页温暖活泼的感觉不一致"。

原话和以前的决定冲突时，按最新原话做，在报告里写一句"改掉了以前的 ___"。

## 2. 从设计源抽语言

设计源是用户确认过的那一页。在浏览器里读它的计算样式，不只读 CSS 文件，因为页面实际用的值可能被覆盖。

写成一张"继承表"，放在 `design.md` 第 1 节：

| 项 | 设计源的值 | 其他页怎么用 |
|---|---|---|
| 底色、表面、墨色、强调色 | 色值与角色 | 全站同值 |
| 字体 | 每种字体的角色、字重、字距 | 只用这几种，清掉其他字体 |
| 圆角、细线、阴影 | 取值种类 | 全站只用这几种 |
| 间距刻度 | 取值 | 全站从刻度取 |
| 动效词汇 | 入场、悬停、按下、切换的时长与属性 | 全站复用同一组类名或 hook |
| 图像语言 | 风格、材质、光、视角 | 新图按这套风格画，主体按内容换 |
| 只属于设计源的东西 | 开场幕布、特殊长卷等 | 不搬到其他页 |

再写一句设计源"活在哪里"：它最让人记住的 2 到 3 个特点（例："暖纸底、衬线 900 大标题、整块纯色面配巨号数字"）。其他页每页至少要有一处体现这些特点，否则只是换了颜色。

## 3. 列覆盖清单

改版最常见的问题是漏：漏 tab、漏弹窗、漏空状态、漏遗留组件。先列清单再动手。

1. 列出全部路由。
2. 每个路由列出：tab 与子视图、弹窗与抽屉、下拉与提示、空状态、加载、错误、登录前后的差别。
3. 每个路由列出 390 宽下的变化。
4. 每页列出"奇怪的东西"：看不出原因的按钮、轮播、装饰、占位头像、单字 logo。每个都问它为什么在这里（`product-ui.md` 第 8 节）。

清单写进 `design.md` 第 2 节，一行一项。每轮报告按清单说明改了哪些、还没改哪些。报告"全站完成"之前，对照清单走一遍。

## 4. 每页做什么

逐页按下面顺序看：

1. **结构**：用户主要做的那件事是否占主要位置。不是时重排（`product-ui.md` 第 8 节）。用户说过"太奇怪的页面允许完全打碎重做"时，保留功能清单，结构可以全换。
2. **页头**：用沉浸式做法（`product-ui.md` 第 6 节）。
3. **卡片与列表**：先定每种卡回答的问题，再分主、次、动作（`product-ui.md` 第 5 节）。
4. **控件**：一层底色、5 种状态、组件库对齐（`product-ui.md` 第 1 到 3 节）。
5. **一处亮点**：每页挑一个最值得做的块，用阶段 3 的发牌和案例库做出创意。实测中用户只认可了"按类别逛"的展开折页，其余块"完全没达到"，原因是只有这一块走了案例库。其他块不必都抢戏，但要用同一种语言做到位。
6. **素材**：图标、logo、头像、插图按 `asset-generation.md` 第 7 节做。

## 5. 先改两页，再推全站

先挑最有代表性的两页（通常是用户最常看的列表页）做完，交给用户看。用户确认语言对了，再推到其他页。推全站时，把公共样式抽成一个文件，按清单逐页接入。

## 6. 看图与报告

每轮按 `critique-method.md` 看图：至少用眯眼看、和设计源并排、放大看细节三种，写最差三处并先改。报告里分开写：

- 看图结果：最差三处，改了什么，还剩什么；
- 覆盖：清单里改了哪些，还没改哪些；
- 功能检查：测试、构建结果。
