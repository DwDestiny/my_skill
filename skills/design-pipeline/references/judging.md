# 好坏标准：拿获奖级作品当尺子

> 何时读：选方向、看方向板、迭代循环每一轮、交付前。
> 本文件管"怎么判断好坏"。"怎么迭代、什么时候停"见 `iteration-loop.md`。
> 用户原话（2026-10-20）："这个评判标准，一定要以一些非常牛逼的创意、获奖级别的设计，作为参考、对照，好的参考是我们能做出好设计的基准！"

## 1. 为什么要用锚点

规则清单只能说明一页"没犯错"，说明不了它"好"。前五次团队页都通过了大部分规则，用户仍说"丑""平""越迭代越垃圾"。

模型没有对照物时，判断会漂移：这一轮嫌"通用"，下一轮嫌"不炫"，权重随手换（r5 主控复盘原话："我更换了取舍权重，却没有证明新权重更合适"）。把候选和获奖级作品并排看，问题就从"这页好不好"变成"它和那一页差多少、差在哪"，后者能回答，也不会漂。

锚点库：`library/anchors.json`。`high` 是 30 个 Awwwards 年度（13 个）与月度获奖站，每条写了首屏实际画面、让人停住的原因、氛围、平庸版本是什么样、能学走的做法；`opened` 写明是现场看的（7 个）还是只看了获奖截图。`low` 是我们自己做过的版本和用户的原话。

## 2. 五个维度和五个档位

按权重排序。第一眼停留力最重要：读者没有停住，后面的一切都不会被看到。

| 维度 | 问什么 |
|---|---|
| 1 第一眼停留力 | 在一排获奖站的缩略图里，它会被点开吗？首屏有没有一个让人想多看两秒的画面。点开之后头 3 秒有没有动作（入场、随指针、随滚动）：获奖站的停留力一半来自动，评候选看三组帧（入场前后、滚动相邻两屏、指针三处），不看单张截图 |
| 2 氛围与世界 | 盖住主物，还能说出"这页像什么"吗？光、色场、环境是不是同一个世界 |
| 3 工艺 | 字、图、边角的细节放大后经得起看吗；动作的缓动、时长、先后顺序像不像参考站（`toolbox/record-motion.py` 录成品和参考站各一遍并排看） |
| 4 贯穿 | 中段和页尾还在首屏的世界里吗？最平的一屏有多平 |
| 5 身份 | 遮住标题，换成别的行业还成立吗？成立的候选先淘汰，再进排序（2026-10-21 改：此前写"加分项"，实测四个模型评审因此把一张与题材无关的流体图排第一，用户判"不可用"）。已贴题的候选之间，身份再作为深化方向（第 5 节） |

档位都用锚点定义，不用形容词定义：

| 档 | 含义 | 参照 |
|---|---|---|
| 5 | 和高分锚点并排不输 | `anchors.json` 中 `tier: 5` 的站 |
| 4 | 并排略输，但看得出是同一水准的作品；至少有一处决定性的画面：占首屏一半以上，盖住说明文字仍成立，而且放在一个有光、有色场或有环境的世界里。画面不只是照片：可以是 3D 物件（Igloo 的冰屋）、占满屏、字形本身好看的字（Synchronized 的高对比衬线）、能动手的装置（Don't Board Me 的弹球）、数据或图形 | 高分锚点里较克制的那一类；同一个站的中段 |
| 3 | 完成度正常，像一个好模板。不丑，但不会被记住 | r5 首批 A（用户："勉强还行"） |
| 2 | 平。第一眼没有落点，或像文档、像产品后台；或一个精致物件放在空的平涂底上；或画面很大但审美不在线：配色廉价、主物猎奇 | r4 首屏与成品、r5 整页（用户："这么丑""配色、氛围啥的全都没有""越迭代越垃圾"）；GPT r6 首屏（用户："很垃圾啊，审美不在线，有些猎奇了"） |
| 1 | 有明显错误：配色冲突、裁切、乱字、廉价素材 | r3 成品的配色与大字（用户："也太丑了"） |

四条打档规则：

1. **氛围不到 3 档，第一眼停留力最多 3 档。** 锚点库里每一个高分站的底都不是空的：Lusion 的物堆放在深色画框里，Synchronized 的大字压在塑料膜上，Immersive Garden 在黑里只照亮几朵花。r4 首屏的 3D 色带工艺很好，但放在空的浅灰绿平涂底上，像一张产品渲染图。独立评审第一次校准时给了它 4 档，用户的评价是"配色、氛围啥的全都没有"。
2. **中段截图不评第一眼停留力**，写"不适用"，只评氛围、工艺、贯穿。中段不和锚点的首屏比，和锚点的中段比（条目的 `middle` 字段）。
3. **审美不在线，第一眼停留力最多 2 档。** 怪东西也能让人停住，只有美的那种算数。先看这三件事，再看尺寸和世界：
   - 配色：大面积的颜色是不是一个和谐的关系。两种高饱和色大面积对撞（例：满屏紫配奶黄）读起来廉价。锚点里的强色都有克制：Locomotive 是一种红占满，Synchronized 几乎只有黑白。
   - 主物本身好不好看：字形、材质、比例放大后经得起看。把团队名挤成巨大的塑料立体字、把比喻做成小人模型，是把概念字面化，读起来猎奇，不是惊艳。大字能成立，是因为字形本身美（Synchronized 的高对比衬线），不是因为字大。
   - 克制：一个画面一个焦点。首屏的说明小标签最多一处，辅助线不和主物抢。
   例：GPT r6 首屏是紫色立体"同场"二字加错位重影、三个小人围桌、五个说明标签、紫黄两色。按尺寸、世界和交互，独立评审给了 4 档；用户的评价是"很垃圾啊，审美不在线，有些猎奇了"。
4. **先过遮名检查，再排序；评审默认代替用户选候选，用户主动要求时才给用户选。** 选案例时评的对象是"案例加换题清单"（装置、换掉的名词、从自己现场取的光、三处不同），不是生成图：对画面排品味模型和用户不一致（`history/calibration.json`），对题材判装置成不成立模型做得了。 遮住标题换成别的行业还成立的候选不进排序（`library/case-map.md` 第 3 节）。剩下的先看第一眼停留力，同档再看氛围；身份决定深化时加什么（第 5 节）。氛围必须从题材自己的世界里来：地方、时辰的光、物件、人；借来的世界再好看也只是壁纸（用户 2026-10-21："氛围一定要跟主题结合才行，否则就啥也不是"）。

3 档和 4 档怎么分：问"锚点让人停住的那个做法，我们做出来了没有"。做出来了、只是精度不如，是 4 档。用了同类素材，但做法没做出来，是 3 档。例：r5 首批 A 和 Locomotive 都是满屏人像，Locomotive 用满屏红光和像素带做了一个主动的色彩决定，A 只压了一层深蓝蒙版，所以 A 是 3 档。

中段可对照的锚点较少：`opened: 现场` 的条目才有可靠的 `middle` 记录。中段评审优先选这些条目。

## 3. 每次评审前，先看锚点

1. 用 `node toolbox/lib.mjs anchors --where page_type=<页型>` 选 2 到 3 个高分锚点（`group: high`）：至少 1 个同页型，至少 1 个和候选用了同一种冲击手法（`--where impact_methods=<手法>`）。`lib.mjs anchors <id>` 看一条全文。不整读 `anchors.json`。 同页型没有高分锚点时（例：`high` 里现在没有团队页，团队页只在 `low`），取最近的页型（`studio-home`、`brand`）并在评审记录里写明。
2. 用 `agent-browser` 现场打开，截首屏和中段各一张，放在项目临时目录（例 `_tmp/anchors/<id>-hero.png`）。不存进仓库。WebGL 站可能先显示加载页，等一次再截。**同一个任务里每个锚点只打开一次**：方向循环和整页循环的每一轮评审都复用这两张截图，不重开。原因：Grok 实测（2026-10-20）78 分钟里约 40 分钟花在评审，大头是每轮重开锚点站。
   - 机器没有 GPU 或 CPU 很少时，重 WebGL 站会把渲染进程拖死。这时改看条目里 `awwwards` 字段的作品页：页面上的主图和分段截图就是评审看到的获奖版本，页面轻，不跑 WebGL。图片只下载到临时目录看，看完删除。
   - 一次只开一个浏览器会话。并行开多个无头浏览器跑 WebGL，2 核机器会卡到无法工作（2026-10-20 实测，负载 22，swap 用满）。
   - 两种都看不到时，用条目里的文字记录代替，并写"未现场看"。
3. 先看锚点，再看候选。原因：先看候选，眼睛会按候选的水准校准。

## 4. 盲比怎么做

评审必须是独立会话。它只拿到截图和锚点，不读设计说明、不读方向理由、不知道哪一版是新的。

1. **对锚点**：把候选首屏和每个锚点首屏左右并排，问："这两张放在 Awwwards 首页上，哪张会被点开？差多少档？差在第 2 节哪个维度？"指着画面回答：哪个位置、什么东西。
2. **对冠军**：把挑战者和冠军并排，左右顺序随机，不标新旧。问："哪一张更让人想停下来看？"然后左右互换再问一次。两次结论不一样，算平局，平局按冠军赢处理。
3. **写结果**：每个维度一个档位，每个档位一句画面证据。最后写一句"最该改的一处"。

评审只回答"好不好、差在哪"，不负责设计新方案。

## 5. 深化还是换方向

这是 r5 最大的失误：A 的第一眼是成立的，问题都出在执行上，却被当成方向问题换掉了。

| 情况 | 做法 |
|---|---|
| 第一眼停留力 3 档及以上，问题在执行：蒙版太重、字形普通、裁切、颜色脏、手机丢了关系 | **深化**。保留这个世界，只改执行 |
| 第一眼停留力 3 档及以上，但"换成相邻身份也成立" | **深化**。在同一个世界里加身份元素：现场物件、行话、真实的工作痕迹。不换方向 |
| 第一眼停留力 2 档及以下 | **换方向** |
| 两个候选同档 | 选第一眼停留力高的。仍同档，选氛围高的 |

r5 首批 A 按这张表是"深化"：满屏现场照撑住了第一眼。要改的是：减轻深蓝蒙版，让现场露出来；显示字换成有声音的字形；手机重新裁切保住四人关系；再加一处只属于 FDE 的东西。实际做法是换方向，后来的每一版都没有再达到 A 的第一眼。

## 6. 常见误判

| 误判 | 实际 |
|---|---|
| 大、新奇、有交互，所以有冲击力 | 猎奇也能让人停住。冲击力要建立在美上：配色和谐、主物经得起放大、只有一个焦点（第 2 节规则 3） |
| 物件做得精致，所以有冲击力 | 物件要放进世界里才有冲击力。空底上的精致物件是产品图，不是氛围（第 2 节规则 1） |
| 贴题、可读、流程齐全，所以好 | 这些是地板，不是吸引力。r5 整页全都做到了，仍是 2 档 |
| 和上一版不一样，所以更好 | "不同"不等于"更好"。只有盲比能说明更好 |
| 加了交互和功能，所以更好 | 功能变多不会提高第一眼。r5 中段加了试验台和文件阅读器，整页反而更像产品后台 |
| 通用，所以要换方向 | 通用是深化任务（第 5 节），不是淘汰理由 |
| 标注越多越诚实 | "虚构、示意、mock"集中写一处（页脚或首屏角落一行小字）。每张卡都标，画面就碎了 |
| 技术检查全过，所以可以交付 | 技术检查只说明能用。好坏只由并排看图决定 |
| 创作者自己看过，觉得可以 | 自己评自己会偏高。评审由独立会话做 |

## 7. 锚点库怎么扩充

1. 新锚点必须亲自打开看过，写首屏、中段、页尾、让人停住的原因、平庸版本、能学走的做法。只存网址和文字，不存截图。
2. 来源优先级：Awwwards 年度（SOTY）与月度（SOTM）、FWA、CSS Design Awards 年度、用户点名的站。只有当日奖（SOTD）的，先标 `tier: 4`。
3. 用户评价过的我们自己的版本，作为低分或中分锚点加入，写用户原话。
4. 每次实测后，检查评审的档位和用户的评价是否一致。不一致时，先修这份文件的档位描述，再改别的。
