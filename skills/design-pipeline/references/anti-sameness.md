# 反同质化八条机制

同质化的根源：模型对模糊需求取训练数据的统计中间值。这是结构性默认，一次聪明提示解决不了（归档内 `research/R2-expression.md` 第 4 节，作者的私有归档（不在本仓库））。本文件把八条机制写成"何时做、怎么查、不成立怎么办"。

## 1. 八条机制

| 编号 | 机制 | 何时做 | 怎么查 | 不成立怎么办 |
|---|---|---|---|---|
| M1 | 点子先于库 | 阶段 2，发牌前 | `direction.md` 的主题盘点 8 到 12 件、点子 1 条在发牌记录之前。把题材换成另一行业读点子，点子不成立 | 重做点子。仍换题成立，回主题盘点补材料、印刷物、工具三类 |
| M2 | 发牌不检索 | 阶段 2 | `direction.md` 有 `deal.mjs` 的发牌记录（3 张 id）与所选 id。所选 id 在 3 张之内 | 重新发牌，最多两次。仍不贴题时可自拟第 4 张，条件：`direction.md` 写明与三张各差在哪、过 `defaults-check.py`、标"库外自拟"，并在项目收口后把它补进库 |
| M3 | 使用史跨项目 | 阶段 2 发牌前、`--commit` 后 | `direction.md` 写出"最近 5 次用了什么"。`history/history.json` 有本次记录。使用史为空或只有示例记录时，写“首次使用，不适用跨项目比较” | 补写。发现撞车时重新发牌 |
| M4 | 禁用清单每项目重写 | 阶段 2 | 5 条。有使用史时至少 2 条引用上一项目的具体决定（字体名、版式家族、hero 构图）。首次使用时 5 条由当前主题推导 | 有使用史时，读 `history/history.json` 与上一项目方向单，补 2 条 |
| M5 | 库里存决定不存形容词 | 写库与方向单时 | 每个决定有选项名、数值或色值、参照 URL 或代码路径 | 把形容词换成数值。"大气的标题"改为"96px、行距 0.95、左对齐" |
| M6 | 默认值检查 | 阶段 2 写完查决定，实现后查页面（可选工具 `toolbox/defaults-check.py`） | 第 2 节清单逐项查 | 命中 2 项回阶段 2 重做。命中 1 项写理由，或改掉 |
| M7 | 可区分性盲评（建议） | 实现后 | 有上一项目时，与其截图并排，另一个会话说出 3 处不同的决定。首次使用不适用 | 说不出 3 处，回阶段 2 换方向轴（纸带、显示字、强调色相、版式家族至少换 2 个） |
| M8 | 机制示例不带皮肤 | 实现接入表现形式时 | 接入后页面的颜色、字体全部来自方向单变量。grep 示例文件里的色值，页面中无残留 | 把残留色值改为方向单变量 |

## 2. 默认值检查清单

逐项查方案与页面。用户原话点名的项除外，写"用户指定"。

| 编号 | 默认值 | 查法 |
|---|---|---|
| X1 | Inter / Roboto / 系统默认字体作为显示字 | grep `font-family` |
| X2 | 紫到靛蓝渐变，尤其加白底或浅灰底 | grep `linear-gradient`，看色相 250 到 290 |
| X3 | 三卡片行：一行三张同尺寸卡 | 看截图与 DOM |
| X4 | 居中英雄区加单 CTA | 看首屏截图 |
| X5 | 奶油底（约 `#F4F1EA`）加衬线显示字加陶土强调（约 `#D97757`） | grep 色值，看截图 |
| X6 | 近黑底（`#0B0B0B`、`#111`）加单一酸绿或朱红强调 | grep 色值 |
| X7 | 同款圆角卡：所有块同一圆角、同一灰影 | grep `border-radius`、`box-shadow` 的取值种类数 |
| X8 | 全大写 eyebrow 标签 | grep `text-transform: uppercase`、`letter-spacing` |
| X9 | 点号连接的元信息（"A · B · C"） | grep `·` |
| X10 | 装饰编号（内容不是序列却标 01 / 02 / 03） | 看截图，对照蓝图是否为步骤 |
| X11 | 等宽字体做小标签 | grep `monospace` |
| X12 | 链接与按钮文字后加 "→" | grep `→` |
| X13 | 只给一个词换颜色或斜体的标题 | 看截图 |
| X14 | 每章同一种淡入上移入场 | 看动效代码，入场类型种类数 |
| X15 | 渐变洗色作装饰背景 | grep `gradient`，看是否承载含义 |
| X16 | 大数字加小标签加渐变强调的 hero | 看首屏截图 |
| X17 | 案例同源：同一页面 3 条以上案例来自同一参照站点 | 看 `design.md` 第 2 节的"案例"列，对照 `library/cases.json` |
| X18 | 细线零圆角的报纸栏版式 | 看截图，数 `border-radius: 0` 加 1 px 分隔线的块 |
| X19 | 标题上方的药丸徽章 | 看首屏截图 |
| X20 | 组件库模板件：网格光束首屏、倾斜到站直的产品屏、悬停播放拼块 | 看首屏与卡片区截图 |

X4 与 X6 同时命中且用户未指定时，回阶段 2 前先查 why-good 第 8 节的使用条件。M6 的阈值不变。

案例字段 `avoids` 只写该案例在本页替代掉的默认值。替代不了任何一项时写空数组。

grep 类各项由 `toolbox/defaults-check.py <index.html>` 查，`--compare <另一页>` 算与既有成品的命中率。看图类各项人工查。

## 3. 记录

每个项目在 `design.md` 末尾写一张表：机制编号、结果（过 / 不过 / 用户指定）、证据（文件与行，或截图名）。

案例也记使用史：`history/history.json` 每条加 `components: [{slot, id}]`。两个项目的 `components` 集合重合超过 50% 视为撞车，重新发牌。首次使用（使用史为空或只有示例记录）不适用。
