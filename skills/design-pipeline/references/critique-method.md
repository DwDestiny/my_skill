# 怎么看图：像设计师一样看截图

> 何时读：做完试样、做完每一轮实现、交付之前。
> 本文件教看图的方法。看图的目的是找到最该改的地方，不是确认"没问题"。
> 来源：2026-10-19 到 10-20 的实测。两边的执行者每轮都写了"截图看过"，白环、歪按钮、焦点框、中间空白和整体方向的问题，最后都由用户指出。原因是看图时只找溢出、遮挡、报错，没有用下面这些看法。团队页第三次看图用了这些看法，也看到了主方向的风险，但修改时把风险排到了后面，用户最终否定的是主方向（第 2.1 节）。

## 1. 七种看法

每种看法看出一类问题。一轮看图至少用前三种。看方向小样和首屏时，加上第六种和第七种。

| 看法 | 怎么做 | 看出什么 |
|---|---|---|
| 眯眼看 | 把截图缩到 25%，或模糊 8 px 再看 | 主次。缩小后还能认出的块，就是读者第一眼看到的。全是一样的灰块，说明没有主次 |
| 和锚点并排 | 把截图和锚点（用户认可过的页面，或设计源页面）左右并排，同宽同比例 | 水准差距和风格偏离。颜色冷暖、字重、留白、图片质感的差别，单看看不出，并排一眼就看出 |
| 放大看细节 | 放到 200%，看控件、图标按钮、标签、表单 | 对齐歪 1 px、两层底色形成的环、焦点框叠两道、文字基线跳动 |
| 走一遍状态 | 用键盘 Tab 走一遍；悬停每类可点元素；打开每个弹窗、下拉、tab；看空状态和加载 | 漏做的状态、默认样式残留、改版没覆盖到的 tab 和弹窗 |
| 找最平的一屏 | 按顺序看全部截图，指出最平淡的一屏 | 氛围在哪里掉了。最平的一屏通常在中段或最安静的一章 |
| 遮住说明看 | 不读设计说明和页面文案，只看截图，写下画面里实际发生的动作或关系 | 主物是不是只靠说明成立。写出来的只是"几个字母连在一起""一个物体在转"，说明画面还没有讲出身份（`direction-and-appeal.md` 第 3.2 节） |
| 盖住主物看 | 盖住首屏的 3D 或主图，再看首屏和中段截图 | 页面本身有没有氛围。盖住以后说不出"这页像什么"、底是一块平涂，说明氛围全压在一个物件上（`atmosphere-and-impact.md` 第 5 节） |

## 2. 写下最差的三处

看完以后，按"对用户目标影响最大"排序，写出最差的三处。每处写四件事：

1. **在哪里**：页面、区块、元素。
2. **看到什么**：具体现象，例如"搜索框外圈有一道 10 px 宽的白环"。
3. **为什么**：原因，例如"检索台暖白底和搜索框暖纸底之间有内边距"。
4. **怎么改**：具体做法，引用 `product-ui.md` 或 `direction-and-appeal.md` 的哪一节。

为什么要排序：小问题修得再多，最大的问题还在，页面就不会变好。团队页的复盘里，检查者看到了"中下段偏讲解、炫酷偏克制"，交回去修的却是白块和图标，方向问题留到了最后。

三处里有一处是方向问题（方向不吸引人、整页像说明书、盖住主物就没有氛围、和锚点差一个档次、颜色和字形的组合气质不对、主物靠说明成立）时，先处理它：回阶段 2 重选方向或回阶段 3 重做这一屏。方向不对时修细节，只会把一个弱方向做得更完整。

### 2.1 四种状态分开写

报告和评审里，下面四件事分开写，各有各的结论：

| 状态 | 回答什么 | 谁能关闭它 |
|---|---|---|
| 方向 | 这个方向本身让不让人停住，有没有身份 | 换方向或改画面后重新看图；最终由用户看成品 |
| 贯穿 | 首屏、安静章、手机像不像同一页 | 试样与全页截图 |
| 局部实现 | 某一屏、某个控件、某个状态做没做对 | 修复后的截图、测试 |
| 用户评价 | 用户看成品后的原话 | 只有用户 |

为什么：局部修得再好，也关不掉方向问题；贯穿做得再好，也可能只是把一个弱方向铺满了全页。团队页第三次修好了无脚本死按钮、打印漏行、视角复位、手机协作关系，贯穿也改善了，但这些都不改变方向的状态。"尚未经用户认可"这类话能防止虚报，但不能代替对方向本身的判断。

### 2.2 方向问题留在第一位

一个方向问题被指出后（自己看出的，或独立评审写的），它留在最差三处的第一位，直到画面上解决或者换了方向。不把它挪成"由中段补身份""由收尾补气质"之后继续铺页。

"比上一版好"写成比较观察，不写成方向够好的证据。

## 3. 改完再看一次

改完重拍同一组截图，用同样的看法再看。写一句"这一轮最差的三处变成了什么"。连续两轮最差的一处没变，说明修法不对，换一种修法；它是方向问题时，修法应换到方向这一层（回阶段 2），不在细节层再试一轮。

## 4. 测试通过说明什么

lint、类型检查、单元测试、构建通过，只说明功能没坏。`floor-check`、`defaults-check` 通过，只说明没有命中脚本能查的默认值。它们都不说明页面好看。报告里把这两类结果和看图结果分开写。
