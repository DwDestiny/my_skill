## 2. 怎么用

1. 讲解页里有两类"没有内容"的地方：信息缺口节（"本次未找到公开案例"），以及 404 页本身。
2. 先问：这个空状态要让读者做什么？本项目的答案：知道缺什么，知道下一步去哪。
3. 筛选：行业选"非营利与政务"和"媒体出版"，风格选"极简""字体型""编辑感"。避开"3D""故障感""游戏"（这些是 预设 `show`的玩法）。
4. 每个条目看三件事：说清发生了什么吗？给出回主线的路径吗？有没有炫技压过信息？

## 3. 示例

| 项 | 内容 |
|---|---|
| 任务 | 蓝图的"信息缺口"节：16 条缺口，每条要说清"缺什么、为什么缺、谁能补" |
| 查询 | 行业"媒体出版"加风格"字体型" |
| 取 | 一个明确的标题句，一个回主线的入口，缺口类型的分组 |
| 舍 | 游戏化、自定义光标、故障特效 |
| 落地 | 缺口用虚线方框标记（`components.md` 第 4 节）。每条缺口带断言编号 |
| 记录示例 | `404s.design / 字体型+编辑感 / 取：标题句+回主线入口 / 舍：特效 / 理由：缺口是内容，不是玩具` |

预设 `show`的展示页可以玩 404 彩蛋：`/sites/nothin` 标签为 3D、粗体、故障感、俏皮、自定义光标、可交互，适合做"概念演示"的参考。讲解页不用。

## 4. 不适用

1. 游戏类 404：占用读者时间。
2. 自定义光标：违反底线"原生光标可见"（`SKILL.md` 第 6 节）。
