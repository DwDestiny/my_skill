# 评审：截图自检、修正轮次、Fable 视觉评审

用户规则原文：

> After you build: look at real screenshots. Do not judge a design from gate results. Check each screenshot against the checklist below. Fix every miss before you report.
> Ask the Fable reviewer for a visual review. Give it the checklist and the screenshots.

> **注意**：门禁通过不证明设计好。门禁抓回归，只有截图评审能抓坏版式。

## 0. 参考值检查（先于自检表）

自检表和 Fable 评审问"有没有违规"。本节问"氛围是否成立，有没有做出该有的样子"。参考值是起点，不是品质分级，偏离时写理由。先过本节，再过自检表。顺序不能反。

1. 运行 `python3 <skill>/assets/floor-check.py <index.html>`。它检查 F1、F2、F3、F5 的可机械判断部分。FAIL 项先看：修，或在设计计划写偏离理由。
2. 对每张必拍截图，回答设计计划第 2.1 节的六项：过或不过，写截图编号。
3. 问一句："用户看到这张图，会不会说它做过设计？"答案是"不会"，说明太素。太素是缺陷，与违规同级。
4. 灰度测试：把截图想成黑白。如果层级只靠字号，没有色块、图形或版式变化，F1 到 F3 没过。
5. 参照对照：把首屏截图与设计计划第 2.2 节的 3 个参照并排。写出本页缺了什么。
6. 任何一项不过，先修，再进自检表。不为通过自检表删参考项。

## 2. 自检表（每张截图每一项）

| 区域 | 检查 | 本 skill 补充 |
|---|---|---|
| Hierarchy | 一件最重要的事，2 秒内找到 | 阅读屏的主角是结论句 |
| Quantity | 无重复信息，无无角色元素，交付前删一件 | 标题、图注、正文不重复同一结论 |
| Type | 同屏 ≤4 字号；数字 tabular 右对齐；无截断或折行 | 中文 ≥12px；正文行高 ≥1.7；每行 ≤40 字；标题 ≤2 行 |
| Spacing | 一套网格；等物等距；无拥挤或漂浮 | 节间距 > 节内间距；文本左边线 2 到 3 条 |
| Color | 颜色只表状态；普通项安静；深浅都过对比 | 强调色 <5%；状态色配文字或形状 |
| Components | 同组件同外观；命中区 ≥24pt；四态齐全 | 折叠标题写清内容；目录当前项可辨 |
| Copy | 白话；按钮说结果；无模糊标签 | 术语首次出现有解释；无话术（项目叠加层） |
| Motion | 回应动作或状态；尊重 Reduce Motion | 预算预设内；r-* 截图内容完整；无空白带 |
| Platform | 遵循平台惯例 | `lang="zh-CN"`；原生光标；可搜索；print 可读 |
| Defaults | 无奶油衬线、无酸色深底、无同款圆角卡、无模板外壳 | 无全大写 eyebrow、无点号串、无装饰编号、无等宽小标签 |
| 参考值 | F1 到 F6 对照参考值（本节第 0 节） | 先于本表检查 |
| 可信度 | 来源与标记可见、未被遮蔽、≥12px | 图例出现一次；芯片密度在预算内（`components.md` 第 4.3 节） |
| 速读通道 | 只读摘要与每节首句能得到主线 | |

## 3. 看图的顺序（取自 taste-skill critique.md，按讲解页改写）

1. 一秒：看一眼移开。看到了什么？只能有一个答案。
2. 眯眼：页面缩成 2 到 3 个大块，有明显大小差。
3. 遮住标题：这页能属于别的主题吗？能 → 点子失败。
4. 边线：数文本左边线，2 到 3 条。
5. 空白：相关的近、无关的远；有无意外的洞。
6. 字：正文到标题的跳变是否决定性；字号是否超过 4 个。
7. 色：哪个色占最多，强调色出现在几处。
8. 图：每张图是否有一句结论标题、表格孪生、12px 以上文字。
9. 同质：给每节版式写一个词，连续相同即模板。版式家族数低于参考值，也算不过。
10. 手机：是独立构图还是压缩版。
11. 实质：每节是否把蓝图要求的信息完整给出。
12. 遮挡：任何滚动位置有无东西盖住标题、按钮、来源。
13. 复述：合上页面，能否说出 3 条要点和它们的可信度。

## 4. 修正轮次

```
ROUND n · 预算预设 <clear|mixed|show>
一秒看到：…
主题点子（一句）：…
能复述的要点数：_/3
各节版式词：hero=… / 1=… / 2=…
分数（按预算预设权重）：可理解 _ · 可用 _ · 设计 _ · 创意 _ → 总分 _._
封顶原因：…
前三问题（最可见的先），各附截图编号与修法：
1. …
2. …
3. …
```

权重的含义：总分是四项分数按预算预设权重相加。权重大的项对总分影响大，例如 `mixed` 预设设计占 35%，可用占 15%。

封顶：任一底线（gears.md 第 4 节）未过，总分 ≤6.0；任一 Defaults 禁令可见，≤6.5；可信度标记被遮蔽或缺失，可理解 ≤5；入场未触发留下空白带，可用 ≤5。

修的顺序：点子 → 层级 → 构图 → 字 → 图 → 色 → 细节 → 动效。至多 3 轮。第 3 轮仍 <7.5 时如实报告。

## 5. Fable 视觉评审请求模板

```
你是视觉评审。只看截图与检查表，不看代码。

用户原话（逐字）：
> <用户原话 1>
> <用户原话 2>

页面：<路径>
预算预设：<clear|mixed|show>，理由：<一句>
设计计划：<02-设计/design-plan.md 路径>（可读，但先看截图再读）
截图目录：<05-评审/shots/>，编号含义见 review.md 第 1 节
检查表：visual-motion-design/references/review.md 第 2 节；底线见 gears.md 第 4 节
建造者自评（含疑点）：<ROUND n 的全文>

请给四件事：
1. 氛围判断：附上用户关于风格和效果的原话。对照设计计划第 2.1 节的 F1 到 F6 参考值，说这个页面氛围是否成立。如果太素，说哪里太素，给出该加什么。太素与违规同级。
2. 意见：每张截图逐项过检查表，列出未过项，附截图编号与具体位置。
3. 指导：前三个最该修的问题，每个给修法。修法既可以是"去掉"，也可以是"加上"。
4. 方向错误或预期错误清单：设计计划与用户原话不一致的地方；预算预设选错的迹象；为通过检查表而删掉的动效或参考项。

规则：从 6 分起评，每加一分要引用一张截图；不提新概念，只评屏幕上的。
```

## 6. 盲评（可选，预设 show 建议）

另起一个新代理，只给它截图目录与评分表，不给设计计划和代码。让它先用一句话说出页面的点子，再评分。它的一句话与设计计划第 3 节不符时，修页面，不修评审。

## 7. 报告格式

1. 最终文件路径与提交。
2. 预算预设与签名时刻。
3. 检查结果：截图数、自检未过项与修复、ROUND 记录、Fable 意见与处置。
4. 契约变更：退回 `content-blueprint` 的条目编号。
5. 未验证项：没拍的截图、没跑的脚本、没在真机看的项。

不要声称没跑过的检查。
