# 偏差记录：执行偏离用户要求时，原因和修正

追加写入，不改旧条目。每条：现象、证据、根因、修正位置。

## L1 · 2026-10-15 · "中档"被做成了"素档"

> 2026-10-17 注：本条是历史记录。"下限""品质下限""每档"等分级说法已被取代：现在没有分级，预设只是起点，氛围决定收放，判断用三句话原则（`gears.md` 第 2.1 节）。本条保留的教训是：不要把用户的风格词读成"少做"，页面不能做成灰色文档。

- 现象：用户说"本项目视觉要求中档"。页面按 `mixed` 预算预设（旧称档位）交付，但看起来是一份灰色文档。用户原话："我要的是中档，你这个中档也太差劲了吧"。
- 证据：截图只有一个深灰色相、没有任何图像、首屏只有文字标题、146 个小标记散在正文里、图表是灰色斜线块、每章版式相同。设计计划第 14 节写着"这个计划对中档预算偏重，按此顺序削减"。
- 根因：

| 编号 | 根因 | 位置 |
|---|---|---|
| R1 | 把"中档"读成成本上限，没有读成品质下限。计划的重点是"在预算内少做"，而不是"做到中档应有的样子" | 设计计划第 14 节 |
| R2 | 预算预设（旧称档位）机制只有上限。预算表每一格都是"≤"。没有一项下限，所以做得最少也算合格 | `gears.md` 第 2 节 |
| R3 | 用户检查表的"颜色只表状态""普通项安静""交付前删一件"被当成禁令。没有写"安静不等于无色"，也没有保护下限项不被删 | `gears.md` 第 3 节 |
| R4 | 评审只有负向清单。自检表和 Fable 评审都问"有没有违规"，没有问"有没有达到用户要的预算预设（旧称档位）"。第 1 轮评审只让页面更克制 | `review.md` 第 2、3 节 |
| R5 | 组件规范要求每条断言后有"形状加量表加文字加编号"四件套，直接产生 146 个标记，压过正文 | `components.md` 第 4 节 |
| R6 | 场合表把"行业讲解页"放在 `clear` 的典型场合，与用户的"中档"冲突，没有写冲突时怎么选 | `gears.md` 第 1 节 |
| R7 | 没有参照步骤。设计前没有看同类好页面，设计后没有对照 | `SKILL.md` 流程 |
| R8 | 与 skill 开头的"效果优先：预算与效果冲突时先保效果"矛盾。执行时反过来先保预算 | 设计计划第 14 节 |

- 修正：
  1. `gears.md` 新增第 2.1 节"每档的下限"。中档下限 5 条，用户原话"中档"等于 `mixed` 的下限加上限。
  2. `gears.md` 第 1 节改选档规则，第 3 节写明"安静不等于无色"和"删一件不得删下限项"。
  3. `review.md` 新增第 0 节"下限检查"，先于自检表。Fable 评审模板加"是否达到用户要的预算预设（旧称档位）"和"哪里太素"。
  4. `components.md` 第 4 节改为芯片加弹层，并设标记密度预算。
  5. `design-plan-template.md` 新增"预算预设（旧称档位）验收"和"参照对照"，并禁止用成本顺序削减下限项。
  6. 新增 `assets/floor-check.py`，机械检查下限。
  7. `SKILL.md` 流程插入预算预设（旧称档位）验收、参照步骤和下限检查。

## L2 · 2026-10-15 · 新资料到达后只汇报，没有更新蓝图和页面

- 现象：用户让我更新仓库。仓库带来了成都院的新材料。我汇报后问"要我改吗"，用户没有回复。我转去做别的事。用户之后问："我给你新资料之后你没有按照最新的资料更新蓝图和html页面吗"。
- 证据：子项目 README 的下一步写着"结合新材料确定后续讲解调整范围"。新材料 README 写着"后续内容调整应优先对齐成都院"。两处都是明确的下一步，我仍然去问。
- 根因：

| 编号 | 根因 | 位置 |
|---|---|---|
| R9 | `content-blueprint` 没有"再入"流程。新材料、目标变化、用户反馈"内容过时"都不触发重做 | `content-blueprint/SKILL.md` |
| R10 | 把"范围较大"当成"必须先问"。用户的原话和项目文件已经给出方向，应当按推荐项做并说明 | 协调者行为 |
| R11 | 问题没得到回复就转去别的任务，主线被丢下 | 协调者行为 |
| R12 | 蓝图假设 A1 写着"具体是哪一家院未知，不针对某一家院"，新材料到达后没有人负责重新检验假设 | `audience-outcomes.md` |

- 修正：
  1. `content-blueprint/SKILL.md` 新增步骤 0"再入"：触发条件、重定主线（不是追加）、升版本、交接记录。
  2. 同文件写明：用户原话或项目文件已给出下一步时，直接做，做完报告。只在两种读法会改变页面用途时才问，且先按推荐读法做。
  3. 用户没回复，不等于暂停主线。按推荐项继续，并在报告里写明。
  4. 记忆：新资料到达时直接更新，不只汇报。

## L3 · 2026-10-15 · 重建时的三个新坑

- 合并标记用 `rowspan`：桌面表看着干净，手机端表格变卡片后，只有组内第一张卡有标记，其余卡看起来没有来源。修正：表格一行一个标记，不用 `rowspan` 合并。`components.md` 第 4 节已写。
- 密度检查把表格行标记和正文标记一起算，逼着作者合并标记。修正：`floor-check.py` 把表格单元格里的标记单独计数，不计入正文密度。
- 截图脚本滚到元素上沿减 24px，手机粘性顶栏会遮住标题。这是脚本问题，不是页面缺陷。先查 `scroll-margin-top`，再判断。首屏截图用 `scrollTo(0,0)`。
- 计数动画放在首屏底部 15% 以内的元素上时，大视口下不触发，显示 0。总数类数字不做计数动画。

## L4 · 2026-10-26 · 把情绪做成了造出来的场景

- 现象：FDE 公开课的氛围讨论中，连出两轮"造场景"的方案：6 个故事候选（财务室 23:40 亮灯、棋局、天平、会议室模型、分屏群聊），以及 ASCII 方案里"用'月底对账，从三天缩到半天'拼出深夜工位"。用户原话："我实在不喜欢这种造场景的感觉……给人一种很尴尬的感觉；在网页设计上，我们要的是把这种感觉、情绪抽象出来，而不是就硬生生把造出来的场景摆上去，就显得很low"。同时说明动效偏好："我更喜欢平缓、持续的动态效果，给人一种舒缓、踏实、可靠的感觉"。
- 根因：

| 编号 | 根因 | 位置 |
|---|---|---|
| R13 | 把"讲清逻辑"理解成"演一个具体情节"，用虚构的人、时间、台词和道具去证明情绪。观众一眼认出是编的，情绪反而出戏 | 协调者行为；`design-pipeline/references/direction-and-appeal.md` 第 1 节 |
| R14 | 先定了故事，后问"这页要让人感觉到什么"。感觉没定，故事只能靠具体情节撑 | 阶段 2 顺序 |

- 修正：
  1. `design-pipeline/references/direction-and-appeal.md` 新增第 1.1 节"先定感觉，再把感觉抽象成画面"，附"造场景 / 抽象"对照例子。
  2. 动效气质按用户原话取"平缓、持续"：低频、长周期、不停也不闪，见同节。

## L5 · 2026-10-26 · 抽象成了没有主体的字符场

- 现象：L4 之后改成纯抽象的字符波纹场（干涉、同步）。用户认可方向（"是这种意思"），但说"不够好看"，并给出参照：收藏的 ASCII KOI 页（浅色方格纸底，每个字符坐在一块彩色小方块上，锦鲤慢慢游）。用户原话："字符动画还带颜色的你懂吗……他应该是一个有内容的东西，例如，卖观赏鱼的，他就是热带鱼在游动，那我们做fde的，我们应该弄个什么呢？"
- 根因：

| 编号 | 根因 | 位置 |
|---|---|---|
| R15 | 把"抽象"做成了"没有主体"。只有波纹和节奏，观众没有一个能认出、能跟着看的东西，画面耐看度低 | `design-pipeline/references/direction-and-appeal.md` 第 1.1 节 |
| R16 | 字符只用单色明暗。参照页的好看来自主体自身的颜色（锦鲤的红、白、黑、金）铺在字符底块上 | 阶段 2 配色 |

- 修正：
  1. 第 1.1 节补"抽象之后要有一个主体"：选一个自带生命、会慢慢变化的主体，它的结构对应业务逻辑。FDE 选了根系：地上一株苗是客户看得见的部分，地下的根是 FDE 的功夫，四层土对应四种认知，水沿根往上走，苗跟着长。
  2. 字符配色从主体本身取（土的褐、根的浅、水的青、叶的绿），每个字符带底块。

## 检查办法

每次交付前，协调者对照本文件回答：

1. 截图能通过 `floor-check.py` 吗？
2. 我是否把用户的风格词当成了预算？
3. 有没有新材料或新反馈还没进蓝图？
