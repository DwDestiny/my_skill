# 档位：预算、冲突处理、底线

用户原话（2026-10-15）：

> 补充一下，动效引擎和视觉炫技不应该降级，我经常会需要这样

这条原话决定本文的立场：动效引擎与视觉炫技是一级能力。档位机制不是"开或关"，而是"按场合分配预算"。

## 1. 三个档位

| 档位 | 代号 | 页面任务 | 读者状态 | 典型场合 |
|---|---|---|---|---|
| 清晰讲解 | `clear` | 让读者读懂、查到、记住 | 会前速读、会上翻看、学习 | 行业讲解页、备忘页、术语页、教程 |
| 混合 | `mixed` | 讲懂，同时在关键处留下印象 | 先被吸引，再读 | 方案页、汇报页、带舞台区的长文 |
| 展示冲击 | `show` | 让人记住、分享、感到"这是做过的" | 浏览、体验 | 发布页、作品页、概念演示、品牌页 |

选档方法：

1. 读 `blueprint.md` 的 `gear_suggestion` 与 `audience.use_mode`。
2. 如果用户原话指明风格（"炫一点""要能看懂""给人演示"），用户原话优先。
3. 读者主要在读文字，选 `clear`。读者主要在看和体验，选 `show`。两者都有，选 `mixed`。
4. 把档位和理由写进设计计划第 2 节。

## 2. 预算表

"阅读区"指正文、表格、来源、术语、折叠内容、图注、目录。"舞台区"指 hero、章节开场、签名时刻、页脚收尾、独立的图或 3D 场景。

| 预算项 | clear | mixed | show |
|---|---|---|---|
| 同屏字号数 | ≤4 | ≤4 | ≤4（display 字号计入） |
| 全页角色字号 | ≤5 | ≤6 | ≤6 |
| display 字号上限 | 2.5 倍正文 | 4 倍正文 | 不限，但 390px 下不得断词、不得超 2 行 |
| 中文显示字行高 | ≥1.2 | ≥1.15 | ≥1.1 |
| 中文字距 | 0 | 0 | 0（负字距只给拉丁显示字） |
| 阅读屏同屏动效元素 | 0 | ≤2 | ≤2 |
| 舞台屏同屏动效元素 | ≤3（仅 hero 开场） | ≤6 | ≤12 |
| 入场时长 | 400 到 700ms | 500 到 900ms | 700 到 1300ms |
| 入场错开 | 60ms | 70ms | 20 到 80ms |
| 反馈时长（hover/press） | 100 到 200ms | 100 到 200ms | 100 到 500ms |
| 签名时刻 | 0 到 1（静态也可） | 1 | 1，外加 1 个转场系统 |
| 加载器 | 无 | 可选，≤1.2 秒 | 1.1 到 2.6 秒，跟随真实进度 |
| 平滑滚动库（Lenis，固定版本 CDN） | 无 | 可选，默认关 | 默认开；减少动效时原生滚动 |
| 动效引擎 | `motion-engine.js`（零依赖，不用 GSAP） | `motion-engine-gsap.js`（GSAP + ScrollTrigger） | `motion-engine-gsap.js`（GSAP + ScrollTrigger + Lenis） |
| 滚动驱动 / 固定舞台 | 无 | ≤1 个 sticky 舞台，位移 ≤8% | 多个；scrub 允许 |
| 空闲动效 | 无 | 仅签名物，幅度几像素 | 允许；概念驱动；显眼循环配暂停按钮 |
| WebGL / 着色器 | 无 | ≤1 张图内 | 全屏层加平面 |
| 3D / 等轴测（anatomy） | ≤1 张，Figure 档（40 到 80 部件） | ≤1 张 | ≤2 张 |
| 允许炫技的区域 | 无（hero 开场除外） | hero、章节开场、1 张核心图、页脚 | 全部舞台区 |
| 必须安静的区域 | 全部阅读区 | 全部阅读区 | 全部阅读区 |
| 强调色占屏 | <5% | 阅读区 <5%；舞台区色场可大 | 同 mixed |
| 真实照片数量 | 不强制 | 不强制 | 不强制（取图须用户批准） |
| 自定义光标跟随 | 无 | 无 | 可加标签跟随，原生光标始终可见 |
| 评分权重 | 可理解 40 · 可用 30 · 设计 20 · 创意 10 | 设计 35 · 创意 25 · 可理解 25 · 可用 15 | 设计 40 · 可用 30 · 创意 20 · 内容 10 |

数值来源与取舍：入场时长、错开与反馈时长来自 taste-skill motion.md 与 juliobsz motion.md 的交集；两者矛盾时取较短的下限和较长的上限，由档位分配。字号数取用户规则的 4（比 taste-skill 的 5 更严）。加载器上下限取 juliobsz 的 1.1/2.6 秒。中文行高、字距为本 skill 的判断，依据是汉字无字母式紧排。

## 3. 用户检查表的逐项处理

用户检查表原文为英文产品 UI 规则。下表写出每个档位怎样解释它，以及什么是任何档位都不退的底线。

| 检查项 | clear | mixed | show | 任何档位不退 |
|---|---|---|---|---|
| Hierarchy：2 秒找到最重要的 | 最重要的是结论句 | 阅读屏是结论，舞台屏是签名时刻 | 舞台屏是签名时刻 | 每屏只有一个主角 |
| Quantity：无重复、无纯装饰、删一件 | 原文执行 | "装饰"改读为"没有登记角色的元素"。每个炫技元素在设计计划的角色表里登记职责（签名时刻、章节转场、概念驱动物、反馈、氛围系统） | 同 mixed，氛围系统最多 1 个 | 交付前删一件；无角色的元素删除 |
| Type：≤4 字号、数字 tabular 右对齐、无截断折行 | 原文执行 | 原文执行，display 计入 4 个 | 原文执行 | 同屏 ≤4；中文 ≥12px；390px 下无断词 |
| Spacing：一套网格、等距 | 原文执行 | 节奏可在刻度内取 3 档（紧 / 常 / 松） | 同 mixed | 全部取值来自一套刻度 |
| Color：颜色只表状态、普通项安静、深浅都过对比 | 原文执行 | 舞台区允许色场作为概念材料；阅读区颜色只表状态 | 同 mixed | 状态色与可信度标记不被挪作装饰；深浅两套都过 4.5:1 |
| Components：同组件同外观、命中区 ≥24pt、四态齐全 | 原文执行 | 原文执行 | 原文执行 | 四态齐全；触控主操作 ≥44px |
| Copy：白话、按钮说结果、无模糊标签 | 原文执行 | 原文执行 | 原文执行；标题可做视觉元素但仍是真句 | 文字始终是真文本，可选中、可搜索 |
| Motion：回应动作或状态变化、尊重 Reduce Motion | 回应动作或状态变化，外加 1 次 hero 开场编排 | 外加章节开场入场、1 个签名时刻、≤8% 漂移 | 外加加载器、驱动模块、GL、动态字体、空闲动效 | 减少动效时内容完整可见、无循环、无平滑滚动；入场不得把内容留在 `opacity:0` |
| Platform：遵循平台惯例 | Web 惯例：`lang="zh-CN"`、原生滚动、可搜索、可打印 | 同左；固定舞台不挡搜索结果 | 同左；Lenis 可用，减少动效时原生滚动 | 原生光标可见；键盘可用；焦点可见 |
| Defaults：无奶油衬线、无酸色深底、无同款圆角卡、无模板外壳 | 原文执行 | 原文执行 | 原文执行 | 全档位禁止 |

处理原则：不为通过检查表而悄悄删动效。某项过不了时，先调整动效的角色、位置或幅度，再考虑删除，并把删除写进报告。

## 4. 任何档位都不退的底线

1. 尊重 `prefers-reduced-motion`：内容全部可见，无位移、无循环、无平滑滚动、无加载表演。
2. 浅色和深色两套都过对比度：正文 4.5:1，大字与图形 3:1。
3. 可读性：中文正文 16 到 18px，行高 1.7 到 1.9，每行 32 到 40 字；图内中文 ≥12px。
4. 可信度标记与来源不被遮蔽：不被动效覆盖、不随入场延迟出现、不缩到 12px 以下、不只靠颜色区分。
5. 原生光标始终可见；不劫持滚动（Lenis 只给惯性，不锁滚动、不改方向）；滚轮、键盘、Ctrl+F 都正常。
6. 所有文字是真文本。Canvas 与 GL 只承载画面，不承载唯一信息。
7. 每个交互元素有 hover、pressed、focus-visible、disabled 四态；命中区 ≥24px，主操作 ≥44px。
8. 静态帧完整：动效关闭时页面仍是一张完成的页面。
