# 项目叠加层：如何为一个项目补充规则

本文是通用说明。项目叠加层是一个可选文件，放项目自己的视觉与交付边界。它不改本 skill 的流程，只增加限制。

## 1. 何时建叠加层

1. 页面必须体现项目的内容边界（例如每条结论带来源与可信度）。
2. 用户已为项目指定默认预算预设。
3. 项目有固定的目录结构与收尾动作。

没有这些要求时，不建叠加层。

## 2. 怎么建

1. 在项目里新建 `project-overlay.md`，放在本 skill 的 `references/` 下，或放在项目文档目录。
2. 在 `SKILL.md` 路由表的"本项目"行写明路径。
3. 只写项目独有的规则。本 skill 已有的规则不重复。
4. 用户原话与叠加层冲突时，按用户原话做。

## 3. 建议结构与示例

示例使用中性占位符。换成你的项目内容。

```markdown
# 项目叠加层：<项目名>

适用范围：<project-root>。换项目时删除或改写。

## 1. 视觉上必须体现的边界
1. 事实、判断、缺口分开写，也分开标。每条断言末尾有标记，见 components.md 第 4 节。
2. 每条结论带来源编号与可信度（高 / 中 / 低 / 未验证）。
3. 信息缺口单独成节。
4. 页面不出现 <禁用词清单>。出现即退回 B（term_conflict 或 incomplete）。
5. 页面不出现联系方式、名单、未脱敏数据。

## 2. 视觉预算预设
1. 用户在 <日期> 定：默认预算预设 mixed（起点，氛围决定收放）。
2. 舞台区只有两处：hero 与一张核心图。
3. 引擎用 assets/engine/motion-engine-gsap.js。

## 3. 目录
| 目录 | 放什么 |
|---|---|
| <project-root>/content-plan/ | 内容蓝图与证据索引 |
| <project-root>/design/ | design-plan.md、线框、令牌草稿 |
| <project-root>/page/ | index.html 与引擎副本 |
| <project-root>/review/ | 截图、ROUND 记录、评审意见 |

## 4. 收尾
截图目录只保留最后一轮。中间产物删除或归档。
```
