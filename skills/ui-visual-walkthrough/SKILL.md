# UI 视觉走查（无基线探索式审计）

对**真实运行的界面**逐屏逐页做视觉问题狩猎，产出带截图证据的分级 issue 清单。不是修复任务——只取证、分级、落账。

## 与 ui-visual-qa 的边界

- `ui-visual-qa`：**有冻结设计基线**的实现验收，逐元素对基线核对，判定通过/不通过。
- 本 skill：**无基线探索式走查**。没有设计稿也能跑，靠的是通用承载语义与可读性标准；发现的是"问题"而非"与基线的偏差"。同一站点两者可先后使用。

## 硬性纪律

1. **一切结论必须有证据**：截图（内嵌进报告，相对路径）或 DOM/CSS 实测值。口述印象不算数。
2. **截图存证目录与报告同级**，报告内每条 issue 下方用 `![描述](截图目录/xx.png)` 直接嵌图，不许只写文件名。
3. **探针优先于肉眼**：hover 覆盖、字号分布、容器边界、横滑溢出都用 computed style / CSSRules / console 实测，不靠截图猜。
4. **审美判据先行**：逐屏前先定该项目的视觉立场（见 checklist.md「审美定调」）——弱边界不等于无边界，两端都要判：裸排缺承载判丑，厚边框强投影越界也判丑。判据写进报告头再开查。
5. **覆盖必须完整**：先枚举全部路由（以代码路由表为准，不抄文档），逐条走完；参数路由先用种子数据确认有效 ID。
6. **交互必须实测**：筛选/排序/搜索/tab/分页/按钮/表单/hover 逐项真点真输真悬停，确认有反馈且结果正确——点击无响应、状态不变、结果不更新都算 issue。
7. **双视口**：桌面（1440×900 或约定值）+ 移动（390×844）至少各覆盖主要页面。
8. **状态覆盖**：默认态之外至少抽验 登录/游客、空态、404、loading。
9. **分级口径**：P0 明确缺陷（截断、报错、内容缺失、交互无响应）/ P1 体验硬伤（无容器或越界重卡、无 hover、超小字、密度过载）/ P2 建议项。
10. **收尾必有系统性根因分析**：不满足于逐条现象，追到令牌/覆盖层/骨架层面的共同成因。

## 工作流入口

按 [references/workflow.md](references/workflow.md) 执行七步：同步与启动 → 已有文档与路由盘点 → **审美定调** → 逐屏取证 → 实证探针 → 交互实测 → 分级台账与交付。

检查清单全集（四类主诉 + 扩展项）与可复用探针代码见 [references/checklist.md](references/checklist.md)。
