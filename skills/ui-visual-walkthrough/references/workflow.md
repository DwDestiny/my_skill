# 视觉走查 · 工作流

七步：同步与启动 → 已有文档与路由盘点 → **审美定调** → 逐屏取证 → 实证探针 → **交互实测** → 分级台账与交付。

## 0. 前置输入

- 可运行的目标（本机 dev server 或预览地址）+ 分支/commit 号
- 约定视口：默认桌面 1440×900、移动 390×844
- 账号态：若页面需要登录，确认可用的演示账号/登录方式
- 输出位置：报告 markdown + 同级截图目录

## 1. 同步与启动

1. 同步到约定的最新版本（记录 commit SHA，报告头部必须写）。
2. 安装依赖、启动 dev server，确认 HTTP 200。
3. 记录运行环境：端口、视口、登录身份、浏览器/工具。

## 2. 已有文档与路由盘点

1. **先读已有审计/设计文档**：仓库里若已有视觉审查报告或设计基线，全部读完再动手——承接上轮未修项，不重复报已修项；报告里注明与前轮的关系。
2. **路由枚举以代码为准**：从路由表/router 文件枚举全部路由；文档（README 等）声称的入口要实测，不一致本身是 issue。
3. **参数路由先取有效 ID**：查种子/mock 数据拿真实存在的 `:id`；无效 ID 落的空态不计入缺陷。
4. 登记覆盖表：路由 × 视口 × 状态 三轴，逐项勾选。

## 3. 审美定调

开查前先定项目立场并写进报告头（checklist.md S0）：

- 读设计令牌/基线文档（tokens、design-system、master-reference 类）校准数值；
- 定**边界立场**（弱边界≠无边界；裸排与重卡两端都判）、**色彩立场**（强调色枚数与语义色分工）、**密度立场**（内容型/营销型）；
- 定**反馈调性**（与边界立场同调的 hover 语法）。

没有设计文档时按通用弱边界基线判，并在报告中注明立场是推断的。

## 4. 逐屏取证

每页：导航 → 等首屏稳定 → 视口截图 → 分段滚动截图（见「滚动坑」）→ 必要时整页截图 → 对照检查清单 V1–V7 逐条过目。

命名约定：`NN-页面-区块.png`（如 `03-market-全部应用.png`），编号与报告目录一致。

### 滚动坑（实测教训）

- **平滑滚动**：`scrollTo` 可能是动画，读 scrollY/截图前先 `setTimeout` 等 ~1s，确认落点到位再截。
- **reveal 动画伪影**：IntersectionObserver 驱动的入场动画会让 fullPage 截图出现大段空白——那不是 bug。滚动到位重截取证；但「reveal 对无滚动场景不友好」本身可记观察项。
- **内部滚动容器**：window 滚不动时查哪个元素 `scrollHeight > clientHeight`，可能是 div 滚动。

## 5. 实证探针

截图之外必跑探针（playwright `browser_evaluate` 或 DevTools console），探针代码见 checklist.md 各维度：

| 探针 | 查什么 |
|---|---|
| 容器四要素 | computed `border/background/radius/shadow` 定 S0 档位——"像卡"不等于"是卡" |
| hover 覆盖层 | 枚举非框架 `:hover` 规则；**重点找显式禁用规则**；规则存在 ≠ 生效 |
| 真 hover | JS `dispatchEvent` **不触发** `:hover`——必须真实 hover 工具 + hover 中截图对比 |
| 字号分布 | 全页文本节点 fontSize 量化 ≤12px / <13px |
| 截断检测 | `scrollWidth > clientWidth` 横向 ellipsis；`scrollHeight` 纵向裁切；查 aria/展开兜底 |
| 横滑溢出 | 可横滑容器无 mask/箭头/滚动条提示 → 桌面端同样算缺陷 |
| 页面横溢 | `documentElement.scrollWidth > clientWidth` + 定位肇事元素 |
| console 报错 | 每页切 error 档收集；非法嵌套（`<p>` 内 `<div>`）→ hydration 报错 |
| 骨架一致性 | 页脚/导航路由白名单查代码（如 FOOTER_ROUTES） |

## 6. 交互实测

checklist.md I3 操作闭环表逐项真点真输真悬停，记录「操作 → 可见反馈 → 结果是否正确」：

- 筛选：点前后数卡片计数与名称对比；选中态可见性
- 排序：记录首项前后对比
- 搜索：结果集变化 + 无结果空态
- tab/select/分页/弹窗：内容与状态实变
- 按钮：有去向；死按钮 = P0
- 表单：校验与提交反馈
- 键盘：主流程 tab 序 + focus 环

## 7. 分级台账与交付

- P0/P1/P2 口径见 checklist.md 尾部；每条 issue 标注维度编号（V2-3、I3 等）：现象（实测值）→ 影响 → 修复方向 → 内嵌截图
- 「已验证正常项」单列一节并附对照图——证明覆盖到而不是没看到
- 报告尾部必写**系统性根因**：令牌双轨、覆盖层禁用、骨架白名单、缺单一设计源等共同成因 + 收敛顺序建议
- 与既有审计/规范文档建立引用关系，不制造平行台账
