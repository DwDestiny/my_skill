# 走查报告模板

报告与截图目录放同一父级；截图目录名 `视觉走查-YYYYMMDD/`（或 `screenshots/`）。图片一律相对路径内嵌，每条 issue 的图紧跟其描述下方。

```markdown
# <产品名> 全站视觉走查 · Issue 清单（YYYY-MM-DD）

> 走查环境：本机 http://127.0.0.1:<port>（<branch> `<sha>`，<dev 命令>），桌面 1440×900 + 移动 390×844，<登录态说明>。
> 截图目录：`./视觉走查-YYYYMMDD/`，共 N 张，每条 issue 下附对应证据图。
> 性质：<本轮定位：独立走查/复查/……>；与前序文档的关系一句话。

## 走查覆盖

| 页面 | 路由 | 结论 |
|---|---|---|
| … | `…` | ✅ / ⚠️ / ❌（一句结论） |

## P0 · 明确缺陷

### ISSUE-01 <页面>·<位置>：<一句话现象>

<现象+实测值>。<影响>。

**方向**：<修复方向>。

![<截图说明>](视觉走查-YYYYMMDD/NN-xxx.png)

## P1 · <维度分组标题>

（同上结构；一个问题多张图时全部内嵌）

## P2 · 建议项

（同上）

## 已验证正常项（不打 issue）

- <项>：<为什么正常>

  ![对照图](视觉走查-YYYYMMDD/NN-xxx.png)

## 汇总

- **P0 ×N / P1 ×N / P2 ×N**
- **系统性根因**：<令牌/覆盖层/骨架/单一来源层面的共同成因>，<收敛顺序建议>
```

## 写作要求

- 每条 issue：现象（含实测值，如"10.5px""scrollWidth>clientWidth"）→ 影响 → 方向 → 图。
- 截图说明文字要让不点开图的人也看懂拍了什么。
- 正常项也必须配图——正常是靠证据成立的，不是靠没截到。
- 发现即写，别攒到最后凭记忆补——走查过程里截图命名就与 issue 编号对齐。
