# Issue 草稿：新增 UI 交付 Skill 套件

## 背景

需要把从产品需求到可运行界面、再到视觉验收的 UI 交付方法沉淀成可独立使用、也可由总调度 Skill 串联的 Skill 套件。当前仓库已有 `visual-ppt-deck-builder` 等视觉产物流程，但缺少覆盖产品规划、交互与架构、视觉方向、设计系统、高保真稿、动效、前端实现和最终视觉 QA 的 UI 专用流程。

## 价值

- **适用场景**：从新产品想法或既有需求开始设计、实现或检查 Web UI；既支持只执行一个阶段，也支持串联完成整套交付。
- **解决问题**：降低阶段顺序混乱、交互逻辑晚于视觉、设计决策缺证据、实现与设计脱节，以及用文字描述冒充视觉候选等风险。
- **预期收益**：让每个阶段有清楚的最小输入、可审查输出、失败回退和验收条件；总调度可以按项目现状选择完整串联或跳过已有授权阶段。

## 现象与根因链

- **现象**：仓库没有一套可独立复用的 UI 交付 Skill；现有产品、视觉、前端和验收能力分散在不同流程，无法稳定交接。
- **直接机制**：缺少阶段边界、交接输入输出、阶段失败处置及 UI 交付专属验收约定。
- **系统设计缺口**：仓库没有把 UI 设计与前端实施当成有顺序、有证据、有回退路径的端到端交付过程，也没有强制区分真实图片候选与文字说明。

## 方案边界

新增 9 个独立 Skill：

1. `ui-delivery`：总调度与阶段选择、交接、完成状态管理。
2. `ui-product-planning`：目标用户、场景、范围与产品行为。
3. `ui-ux-architecture`：信息架构、交互状态和行为契约。
4. `ui-visual-direction`：视觉方向探索与方向确认。
5. `ui-design-system`：视觉令牌、组件语义和使用规则。
6. `ui-high-fidelity`：高保真页面与状态稿。
7. `ui-motion-design`：动效意图、时序和降级行为。
8. `ui-frontend-implementation`：按确认的设计与交互实现前端。
9. `ui-visual-qa`：在实际运行界面上执行视觉与布局验收。

每个 Skill 包含精炼的 `SKILL.md`、Codex 展示元数据 `agents/openai.yaml`，且可独立使用或按总调度流程串联。8 个阶段 Skill 各自提供 `references/workflow.md`；总调度链接交接契约与来源选型说明。

流程顺序以交互逻辑早于视觉、微动画后置为约束。用户要求多版本图片风格探索时，交付物必须包含实际图片候选；生图或图片展示能力不可用时应标记 BLOCKED，不能用文字描述冒充图片。默认可建议 2–3 个有差异的候选方向，但不强制；用户已有授权风格时可以复用。

示例只使用虚构、中性的项目与数据，不包含公司、客户或个人私密材料。本批次包含主题索引、中英文 README 目录、插件打包配方、结构校验和本地包验收；版本为 v0.1.0。

## 验收标准

- 9 个 Skill 均有有效 frontmatter，`name` 与目录名一致，`description` 能说明触发场景。
- 每个 Skill 均说明可独立使用还是如何接入完整串联；正文只保留触发规则和核心工作流，阶段细节放入 references。
- 8 个阶段各有 `references/workflow.md`，且写明最小输入、输出、失败回退和验收标准。
- 每阶段流程明确阶段边界与先后依赖：交互逻辑先于视觉，微动画后置；跳过阶段须基于用户已有授权或已确认产物。
- 用户要求多版本图片风格探索时，实际图片是验收产物；能力不可用时结论为 BLOCKED，不得以文字方案替代。2–3 个差异候选只是默认建议，已有授权风格可复用。
- 总调度能区分完整串联、单阶段调用、沿用已有设计、阶段失败和阻塞状态，并交接可复核的阶段产物。
- 示例均为虚构中性内容，无公司私密信息。
- 完整串联按 `delivery.json` 注册 project/pages/screen IDs；各阶段以 `stage.json` 记录状态、原因和产物，以 `snapshot.json` 冻结上游与产物哈希。独立调用阶段 Skill 不强制创建规范工作区或快照。
- 视觉方向选择按 `selection.by`、`selection.evidence`、`selection.authorization` 记录，并区分用户选择与获得明确授权的代理代选；高保真资产类型标清原型、设计图、渲染或 mock。
- 中英文 README、主题索引、插件构建配方与包内相对链接已补；完成套件结构、元数据、构建和便携包检查。
- 全局安装验收：9 个 hub 本体均位于 `self/<skill>`，原仓库 canonical 文件仍在；每个已授权 agent Skills 入口仅出现一个同名软链接，目标为对应 hub 本体，且解析有效、可读到 `SKILL.md`。目录软链别名不重复建链，平台托管目录不纳入本批次。
- Manifest 验收：9 个 self 资产行逐一记录实际创建的软链接位置，不登记计划中但未实施的入口；保留既有行和历史记录。
- GitHub 同步验收：只包含本轮授权的 9 个 Skill 与必要的 README/主题索引/配方文档变更；提交已推送到预期远端分支，并用远端 ref 核对推送结果。未创建 GitHub issue。
