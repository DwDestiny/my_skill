# UI Delivery 保真问题复核

## 范围与证据边界

本页记录一次限量、脱敏的近期 UI / 页面协作复核，以及本轮 UI Delivery 规则调整的依据。公开仓库不保存客户或项目名称、内部地址、原会话全文、会话标题或 ID。原始来源仅留内部知识记录。

证据分为三类：**用户报告**表示用户明确描述过的现象，不代表本轮已复现；**工具结果**表示当次工具确实返回的状态或内容；**代码核验**表示对旧版本地校验器的静态检查，不代表生产页面出现过同一故障。助手自述单独标注，不能替代工具证据。

## 已观察的问题

| 现象 | 证据等级 | 复核结果与限制 |
|---|---|---|
| 整套页面漏项、跨页导航不一致，以及设计图转实现时关键内容或间距偏离、复查不足 | 用户报告 | 作为需要防止的用户报告问题记录；本轮没有在现有 UI Delivery 套件上复现这些完整结果。 |
| 验收报告的问题与截图不相邻 | 用户报告 | 用户明确指出截图应放在对应问题旁；同一会话后续工具输出确认问题条目已补入内嵌截图，故记录为当轮修复。 |
| HTTP 200 和打开浏览器标签被当作页面已显示的依据 | 工具结果 + 助手自述 | 工具结果只证明地址返回成功和标签创建；当次没有页面截图、快照或 DOM 检查。助手的“页面已显示”说法超出这些证据。 |
| 项目文档中的预览端口与运行进程的工作树不一致 | 工具结果 | 现场检查发现已有预览进程来自另一工作目录；随后从目标代码工作树启动新端口并获得 HTTP 200。该记录不能证明旧预览页面的具体视觉内容。 |
| 旧版校验器接受了过弱的设计系统字段 | 代码核验 | 旧实现对颜色 token 只要求至少一个值，对组件清单主要检查 ID 和使用页面；它没有建立设计基线、必需元素、实现映射与运行证据之间的完整对应关系。这是契约缺口，不等于真实页面已发生某个具体设计偏差。 |

## 根因判断

本轮将主要风险归为**追溯链不完整**，而不是“图片数量不足”或“测试次数不够”：页面范围、用户旅程、屏幕状态、关键元素、共享组件、实现位置和运行证据需要相互引用并绑定到同一版本。若其中任一段只靠自然语言自述，漏页、跨页漂移、图到代码遗漏和验收误报就难以被发现。

另一个独立风险是运行目标未绑定到当前代码工作树。只记录一个端口或首页 HTTP 成功，无法说明实际打开的是哪个版本，也无法证明浏览器渲染、点击路径和页面状态正确。

## 本轮 v0.2.0 文档范围

- 在规划与 UX 阶段建立用户旅程到页面、screen、state 和关键元素的追溯；每个纳入范围的页面必须有旅程覆盖。
- 将获选视觉基线、设计令牌、公共组件版本、逐屏规格、实现清单与 QA 证据连接起来；完整字段以交接契约 v2 为准。
- 默认以每个适用页面/视口的完整静态视觉基线说明版式；其它状态可描述相对默认状态的变化。可点击原型是单独产物，可选提供，不冒充运行态验收。
- 最终 QA 必须在真实运行界面逐步点击用户旅程，并用截图或 DOM 证据确认目标页面和状态；视觉比对要对照冻结基线，问题截图紧邻问题记录。
- 预览复用前核对进程工作目录、目标版本与实际路由。HTTP 状态和 tab 创建只作连通性证据，不作渲染通过证据。
- 保留工具选择自由；任何单一白板或设计服务都不是公共 Skill 的强依赖。

## 完成边界

这些约束用于提高范围完整性、设计到实现的可追溯性和 QA 证据质量。schema 校验通过仍不等于设计质量合格、浏览器旅程通过、截图来源真实或用户已经签收；这些判断仍由实际审查和运行验收完成。
