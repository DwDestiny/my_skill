# Issue 草稿：补强 UI 逐屏完整性与视觉一致性

## 背景与证据边界

用户报告旧交付流程中出现整套 UI 图片漏页、跨页导航不一致，以及图片转代码后元素缺失、间距偏差和复验不足。这是用户报告的现象，不等于已在本仓库的新 UI Delivery 套件上复现。当前契约已有页面、状态、视口注册与阶段文件；已核对旧校验对 `tokens.json` 只要求至少一个颜色，对 `component-inventory.json` 只检查组件 ID 和 `used_by`，QA 证据尚无设计基线对应的机器约束。结构校验通过不能证明内容和视觉质量。

## 三层根因假设

1. **覆盖层**：若整套页面、状态与必需元素没有批次清单和逐项审查，单张 Hero 或部分图片容易被误当完整交付。
2. **设计层**：生成图片可提出方向，但不能稳定重现公共导航或提供精确尺寸；缺少从获选方向图确认的设计令牌、公共组件母版及版本，跨页会漂移。
3. **实现与验收层**：若代码按各图分别临摹，且运行截图不与冻结的设计基线逐页对照，遗漏、间距偏差及修复后回归会漏掉。

## 预期与可证伪验收

- 保留真实生图供方向选择；逐屏图明确区分生成式整页图、结构化设计预览和真实运行截图，不互相冒充。
- 在实现前确认完整可执行设计规范、公共组件及资产复用规则；每个适用页面/状态/视口的必需元素有可追踪审查结果，未完成项显示 pending。
- 运行 QA 固定版本与环境，把冻结基线和运行截图并排或叠加核对；任意删页、删关键元素、改一页公共导航或制造明显间距偏差，都应被发现并形成修复后重拍记录。
- 公共组件变更时，所有使用页重新检查；不能用当前实现截图覆盖原设计基线来消除差异。

## 执行边界

本草稿仅作为本地问题台账，不创建 GitHub issue。v0.2.0 先补 Skill 指引和可审查交付规则；字段级脚本契约及测试由另行任务对齐。Figma 是有多人设计协作需求时的可选路径，不成为所有项目的强制依赖；已有代码或设计组件应优先复用。
